# 现金流量表编写 — AI 操作手册

> **你是 AI 助手，这份手册是给你的。用户通常是会计/审计人员，不懂代码。**
> 你要替 TA 把每一步做到位并验证通过；TA 只需要回答几个问题、看一眼结果。

## 这个 skill 在做什么

```
序时账 ──► 业务分类（模型，来自 summary_cleaner）──► 现金流量项目（程序查表）──► 一个 Excel
```

- 输入：序时账 Excel/CSV，至少要有 **凭证号、一级科目、借方金额、贷方金额** 四列
- 输出：**一个** Excel（3 张 sheet），由程序落盘
- **本 skill 不判业务桶**——业务分类来自 `summary_cleaner`（序时账清洗）。这里只做
  「桶 + 货币资金借贷方向 → 现金流量项目」这一段。

## ⚠️ 分工铁律（先读这条）

| 谁做 | 做什么 | 为什么 |
|---|---|---|
| **程序** | 读文件、认列名、调上游判桶、查表定项目、写回、**导出 Excel** | 确定、可复现；落盘是"确定的活"，**你不写产出文件** |
| **你（AI）** | 看**待复核**清单、给结论、把结果**讲成人话** | 要读自然语言、处理模糊情况，程序写不完 |

**你只做最后一公里。** 不要自己算数、不要自己拼 Excel、**不要自己写脚本改产出文件**。
有结论就用 `run --cf "行号=项目"` 交回程序，程序重出文件。

> **两种跑法**：本文件的 `cli.py` 是**单跑**（一条命令跑到底，结论靠对话传递）；
> 需要"程序 → AI 复核 → 再算下游"的穿插流程，用仓库根的 `journal`（编排层，
> 见 `docs/design/architecture_v5.md`）。两者算法相同，编排模式多两处复核停靠点。

## 操作流程

```
第 0 步 环境自检 ── status：依赖齐不齐、上游模型在不在、映射表自洽不自洽
第 1 步 字段确认 ── check：认不出列名时用 --set 手工指定（极少用）
第 2 步 跑账     ── run：业务分类 + 编现金流 + 导出，一次完成
第 3 步 看待复核 ── run 出参里的 cashflow_review（不落 Excel）
第 4 步 交结论   ── run --cf "行号=项目" 或 --cf-patch 补丁.json，重跑
第 5 步 讲人话   ── 把现金流量表读数讲给用户；指出仍需人工确认的条目
```

### 第 0 步 环境自检

```cmd
%PY% -X utf8 cli.py status
```

看三块，任何一块不对就别往下走：

| 字段 | 期望 | 不对怎么办 |
|---|---|---|
| `missing_modules` | `[]` | 按 `reference/SETUP.md` 装依赖（torch 单独装） |
| `upstream.model_ready` | `true` | 上游模型缺件 → 让用户按 summary_cleaner 的 `reference/SETUP.md` 下载 |
| `cf_maps.validate_problems` | `0` | 映射表被改坏了，看 `validate` 的 `problems` |

`upstream.buckets` = 上游业务桶数（当前 33）。**桶表变了要重看 `bucket_to_cf.json` 覆盖没覆盖**，
没覆盖的桶会全部落到「待复核 · 桶不在映射表里」。

### 第 1 步 字段确认

```cmd
%PY% -X utf8 cli.py check "序时账.xlsx"
```

出参里看 `mapping`（程序认到的列）和 `cashflow.money_vouchers`（多少张凭证涉及货币资金）。
认错了列才用 `--set`：

```cmd
%PY% -X utf8 cli.py check "序时账.xlsx" --set 一级科目="科目" --set 借方金额="借方发生额"
```

字段名就是 `mapping` 里的键：`voucher_no / subject / debit / credit / summary / date / subject_name`。

### 第 2 步 跑账

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录"
```

- 不加 `--out` 时输出到序时账同级的 `现金流量表编写结果/`
- 产物：`<文件名>_现金流量表.xlsx`，3 张 sheet
  1. **原始序时账**——用户给什么就是什么，列名也不改
  2. **业务分类结果**——原始列 + 业务分类/置信度/判定来源 + 现金流量项目/方向/判定/复核
  3. **货币资金凭证**——含货币资金的**整张**凭证（编现金流要看对方科目在干什么）

> 超过 50 万行的账不再写 xlsx（Excel 单表上限 104 万行，硬写等于挖坑），
> 改成每张 sheet 一个 csv，`output_files` 里能看到实际路径。

### 第 3 步 看待复核

`run` 的 stdout 是单行 JSON（前缀 `RESULT `）。要完整结论就加 `--out-json 结果.json`：

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出" --quiet --out-json "结果.json"
```

`cashflow_review` 是待复核条目（每条一行），`cashflow_review_by_voucher` 是按凭证归并后的版本
（**先看这个**，一屏能看完）。每条带：

| 字段 | 用途 |
|---|---|
| `行号` | 1-based，等于 Excel 工作表行号；补丁的键就用它 |
| `凭证号` / `摘要` / `对方科目` | 判断这条业务到底是什么 |
| `业务分类` + `业务分类置信度` | 上游判的桶。置信度"高"还判错 → 多半是桶的边界问题 |
| `现金流方向` | 收 / 付 |
| `候选项目` | 程序筛完还剩哪些可能（空 = 这个方向本来就没候选） |
| `原因` | 为什么判不下来 |

四类待复核（见 `reference/CASHFLOW_GUIDE.md` 第四节）：

| 原因 | 怎么办 |
|---|---|
| **方向与桶不符**（费用桶却是收现=费用退回） | 先想：这笔业务真的是"费用"吗？多半要改桶 |
| 歧义桶，科目没登记 | 看摘要 → `--cf` 直接指定项目；同类反复出现就往 `account_ruling.json` 补科目 |
| 科目同时命中多个候选（赎回带收益） | 按金额主体拆判，或保留待复核问人 |
| 桶不在映射表里 | 上游桶名变了 → 补 `bucket_to_cf.json` |

### 第 4 步 交结论

```cmd
:: ① 直接给（首选：不写文件、可重复、一次交完）
%PY% -X utf8 cli.py run "序时账.xlsx" --cf "502=吸收投资收到的现金"

:: ② 补丁文件（人工长期维护）
%PY% -X utf8 cli.py run "序时账.xlsx" --cf-patch "补丁.json"
```

补丁格式（行号 = `cashflow_review` 里的 `行号`，1-based）：

```json
{"rows": {"502": {"item": "吸收投资收到的现金", "note": "股东实缴"}}}
```

被采纳的条目标为「补丁补充」，可追溯。**合法项目名的权威清单是 `assets/cf/cf_items.json`**
（24 项）——候选为空或看着不对时查它，`--cf` 可以指定清单里任意一项，不必从候选里挑。

如果结论其实是"业务桶判错了"，用应急把手改桶（**优先去修上游模型/别名表**）：

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --bucket "2025年1月-记-1245号=单位往来"
```

### 第 5 步 讲人话

给用户的结论至少包含：

1. **经营/投资/筹资三类的净额**，以及"现金及现金等价物净增加额"（`cashflow_statement` 最后一行）
2. **判断质量**：多少条由桶直接定（`by_source` 里的「桶唯一」「桶+方向」）、多少条走了科目裁判/兜底
3. **还需人工确认的条目**：多少条、为什么、涉及多少钱
4. 提醒：现金流量表的正确性上限 = 业务分类的正确性。桶判错，现金流必错且报表是平的

## 命令参考

| 命令 | 作用 | 会不会写文件 |
|---|---|---|
| `status` | 环境 + 上游模型 + 映射表自检 | 不写 |
| `check FILE` | 读表、认列名、数货币资金凭证 | 不写 |
| `run FILE [--out DIR]` | 判桶 → 编现金流 → 导出 | 写结果 Excel |
| `validate` | 映射表自检（桶覆盖、项目合法性、歧义桶） | 不写 |

通用开关：

| 开关 | 说明 |
|---|---|
| `--set 字段=列名` | 手工指定列名映射（可重复） |
| `--out DIR` | 输出目录 |
| `--out-json PATH` | 把完整出参写一份 JSON（stdout 仍然只有一行） |
| `--quiet` | 不输出进度（进度本来走 stderr） |
| `--cf 行号=项目` | 给待复核条目下结论（可重复） |
| `--cf-patch PATH` | 现金流补丁文件 |
| `--bucket 凭证号=桶` | 应急：覆盖业务桶（可重复） |
| `--bucket-patch PATH` | 业务桶覆盖文件 |

## 出参（`RESULT` 那一行 JSON）关键字段

| 字段 | 含义 |
|---|---|
| `rows` / `vouchers` | 行数与凭证数 |
| `bucket_counts` | 业务桶分布（上游判的） |
| `confidence_dist` | 高/中/低 |
| `upstream.model_calls` | 上游真正送进模型的条数（去重后） |
| `cashflow.money_vouchers` / `money_rows` | 涉及货币资金的凭证数 / 分录数 |
| `cashflow.by_source` | 每条分录的项目是**怎么定出来的**分布 |
| `cashflow.needs_review_rows` | 待复核分录数 |
| `cashflow.rows_without_item_detail` | 空项目行的拆分（正常/待复核/未分类） |
| `cashflow.amount_by_item` / `amount_by_section` | 按项目 / 按活动大类聚合 |
| `cashflow_statement` | 现金流量表（含净增加额合计行） |
| `cashflow_review` | 待复核明细 |
| `elapsed` | 读表 / 上游分类 / 现金流 / 导出 / 总耗时 |

## 边界（别越界）

| 事项 | 边界 |
|---|---|
| 判业务桶 | **不是本 skill 的事**。桶错了改上游（模型 / 别名表 / 桶定义），不要在这里造第二套口径 |
| 改产出 Excel | **禁止**。AI 只交结论，文件永远由程序落盘 |
| 一级科目当主映射 | **禁止**。它只在歧义桶里当裁判，否则就是两套口径并行 |
| 正式现金流量表（含期初余额、表间勾稽） | **未做**。当前只出"按项目聚合 + 净增加额" |
| 待复核硬选一个 | **禁止**。没有可靠依据时标出来，比硬选安全 |

# 复核指引（SKILL.md 第 3–4 步展开）

AI 在本 skill 里只做**两件事**：复核判断、把结论交回程序。本文只管复核与出错处理。

---

## 一、你要复核什么

| 复核对象 | 从哪拿 | 判据 |
|---|---|---|
| **单元的业务分类**（主体） | `units` 命令出的**单元清单** | `assets/bucket_definitions.md` + `AI_REVIEW_GUIDE.md` 的 A 表 |
| **现金流结论** | `run` 出参的 `cashflow_review.items` | `reference/CASHFLOW_GUIDE.md` |

**注意复核的单位是「单元」，不是凭证。** 序时账是按「科目组合 + 摘要」
去重成单元再给模型打分的，所以：

- 凭证可能几千张，单元通常只有几百个 —— 后者才是能过一遍的量；
- 一个单元可能覆盖多张凭证（实测样例 800 张凭证 124 张落在这种单元里，
  最多的一个覆盖 17 张）。改这个单元会把它名下所有凭证一起写回，
  **这是对的**：模型区分不了同单元的凭证，只改一张会留下没改到的兄弟。

---

## 二、怎么拿到复核面：用 `units`，别自己拼数据

> 命令里的 `%PY%` 指 python 解释器（设法见 `SKILL.md` 第 0 步）。

```cmd
:: 全部单元，已按「最可疑在前」排好（概率升序）
%PY% -X utf8 cli.py units "序时账.xlsx"

:: 只看最可疑的 40 个 / 翻页 / 只看某个桶
%PY% -X utf8 cli.py units "序时账.xlsx" --limit 40
%PY% -X utf8 cli.py units "序时账.xlsx" --offset 40 --limit 40
%PY% -X utf8 cli.py units "序时账.xlsx" --bucket 销售收入
```

`units` **不写回、不算现金流、不产出任何文件** —— 它是判断的输入，不是交付物。

每个单元给的是：`单元号`（如 `U186`）、`单元键`（`科目组合 :: 摘要`）、
`模型桶`、`概率`、`次选`、`来源`、`覆盖凭证数`。

> ⚠️ **别用置信度三档做判断**。这个模型对熟悉口径会饱和到概率 1.0
> （实测中位数 1.0000、95%+ 都是"高"），三档没有区分度。
> 有判别力的是**概率的排序** —— 清单就是按它排的，从头往下看。

---

## 三、怎么判断（按优先级）

1. **`assets/AI_JUDGMENT_NOTES.md` 里已有的案例与规则**——最优先，那是积累下来的口径
2. **`reference/AI_REVIEW_GUIDE.md` 的 A 表**——模式 → 桶的硬规则
3. **`assets/bucket_definitions.md` 的桶定义与边界**——兜底依据

**只能选 20 个桶之一**，拿不准就标「待人工确认」，不要自己造桶名。

### 几个高频坑

| 单元长相 | 容易判错成 | 应判 |
|---|---|---|
| 系统维护费 | 长期资产 | **日常费用**（软件开发费才归长期资产） |
| 银行手续费 / 转账费 | 利息收支 | **日常费用**（利息收支只含利息/罚息/结息） |
| 其他应收款 + 一笔钱 | 单位往来 | 先看摘要有没有「押金/保证金」（→押金保证金）、「借款/借支」（→员工借款），都没有才是单位往来 |
| 员工备用金垫付 | 员工借款 | **日常费用** |
| 短期借款[贷] + 银行存款[借] | 存货采购 | **借款筹资**（"福费廷"这类贸易融资也算借款，别被"费"字带偏） |

## 四、结论怎么交回程序（不要写文件）

**程序是「先改单元 → 再写回凭证 → 再算现金流」**，所以你的结论是**输入**，
不是事后修正。交结论用可重复的命令行参数，一次交完：

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出" ^
  --unit "U186=借款筹资" ^
  --unit "U052=单位往来"
```

- 键可以写**单元号**（`U186`），也可以写**单元键原文**
  （`其他应收款[借] + 银行存款[贷] :: 预付款张三退回`）
- `--unit` 可以重复很多次 —— **别发现一个改一个、改一个跑一次**
- 桶名必须是 20 个之一；非法桶名进 `rejected`，单元找不到进 `unknown_units`

**为什么不能自己写脚本/JSON**：手写 shell 脚本改文件要处理转义、编码（Windows
记事本写出来的 JSON 默认带 BOM）、路径，处处是坑，而且改错了没人拦。
程序收命令行参数，会校验、会回报、会把生效的口径修正落盘留档。

**为什么不能手改 Excel 的分类列**：现金流是拿业务桶算的，你改了分类列，
「现金流量项目」那一列**不会重算**，交付物立刻自相矛盾（分类写着 A、现金流按 B 算）。
实测样例 460 条现金流分录里 **431 条（93.7%）由「桶+方向」直接判定**，
桶一错项目就跟着错，而且候选唯一时程序看起来"很确定"，**根本不会报警**。

### 落档：口径修正表

程序会把你**采纳的**改判写成 `<输出目录>/口径修正.json`：

```json
{
  "units": {
    "短期借款[贷] + 银行存款[借] :: 2025/8/15-入福费廷贷款2000万": "借款筹资"
  }
}
```

键用的是**单元键**（不是单元号），所以**可以跨月复用**——下个月序时账出现
同样的「科目组合 + 摘要」，这张表直接命中。单元号只在同一份文件里有意义。

需要长期维护这个表时，也可以反过来用它跑：

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出" --unit-patch "口径修正.json"
```

| 情况 | 怎么处理 |
|---|---|
| 零星几个单元判错 | 用 `--unit` 改判（**不要逐个纠**），汇报里说明改了什么、依据是什么 |
| **同一类单元成批判错** | **不要逐个改**。告诉用户：这家公司数据与模型训练数据偏差较大，需**补充训练数据后重训模型** |
| 用户明确纠正的个别案例 | 记进 `assets/AI_JUDGMENT_NOTES.md` |

> 📌 **手改 Excel 分类列只有一个合法用途**：给**训练数据**用
> （`cli.py train export` 读的就是复核后的 Excel）。那是攒训练样本，
> 不是修这次交付——两件事别混。修交付走 `--unit`。

## 五、积累（"越用越准"的关键）

每次清洗后更新 `assets/AI_JUDGMENT_NOTES.md`：

| 记什么 | 记到哪一节 |
|---|---|
| 遇到的新财务词汇 → 应属哪个桶 | 一、词表补充 |
| 复核确认的「摘要 → 桶」案例 | 二、摘要 → 桶 的确认案例 |
| 新提炼的判断规则 | 三、判断规则备忘 |
| 本次运行的概况与待办 | 四、本次积累记录 |

**纪律**：只追加、不覆盖；写依据；用户纠正的优先级最高；
推断的必须标「低置信度，待验证」，别把猜测写成事实。

> 这个文件**只记判断经验**。程序/skill 的缺陷属于另一个范畴，
> 记到 `review/` 下（那是开发侧记录，不随包发布）——写在积累库里会随包
> 发给用户，而且缺陷修好后就变成假信息了。

## 六、错误处理（按性质分流）

出问题时先判断是**哪一类**，再决定动作——不要一上来就改数据：

| 症状 | 性质 | 动作 |
|---|---|---|
| `coverage < 1.0` | 数据/字段问题 | 看桶分布，排查科目列是否缺失或映射错误 |
| 某个桶占了一半以上 | 口径问题 | 抽查这个桶的单元，判断是模型不适用还是数据本身如此 |
| 同类单元成批判错 | **模型/桶定义问题** | 走重训路线，**不要逐个改** |
| 现金流待复核条数很多 | 桶定义粒度问题 | 见 `CASHFLOW_GUIDE.md` 第三节：该拆桶了 |
| `--unit` 报 `unknown_units` | 单元号/单元键抄错 | 重跑 `units` 核对；单元号只对同一份文件有效 |
| `ok: false` | 运行失败 | 看 `error` 字段；`stage` 告诉你失败在哪一步 |

> **原则**：程序能确定的错（字段映射、文件格式）→ 修配置重跑；
> 模型层面的错（成批同类错误）→ 汇报并建议重训；
> **只有零星的、模型拿不准的**才值得你逐个给结论。

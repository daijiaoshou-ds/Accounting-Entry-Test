# 复核指引（SKILL.md 第 4 步展开）

AI 在本 skill 里只做**两件事**，本文只管第一件（复核判定）与出错处理。

---

## 一、你要复核什么

| 复核对象 | 从哪拿 | 判据 |
|---|---|---|
| **业务分类** | `sample` 命令抽的凭证 | `assets/bucket_definitions.md` + `reference/AI_REVIEW_GUIDE.md` |
| **现金流结论** | `run` 出参的 `cashflow_review.items` | `reference/CASHFLOW_GUIDE.md` |

**高置信度（≥80%）占绝大多数（实测 95%+），中/低才是重点。**

---

## 二、抽样：用现成命令，别现场写脚本

> 命令里的 `%PY%` 指 python 解释器（设法见 `SKILL.md` 第 0 步）。
> `sample` **每条返回整张凭证**：`分录` 是全部借贷行——判断业务桶要看
> 科目组合 + 摘要，**别只看一行**（只给一行会把"银行存款在贷方"这类
> 关键信息漏掉，正是误判的来源）。

```cmd
:: 抽 5 条高置信度的核对（固定随机种子，重跑拿到同一批，便于对照）
%PY% -X utf8 cli.py sample "输出\序时账_结果.xlsx" --confidence 高 --n 5

:: 抽中/低置信度的（这些逐条看）
%PY% -X utf8 cli.py sample "...\序时账_结果.xlsx" --confidence 中 --n 20

:: 按业务桶分层抽，避免全落在一个大桶
%PY% -X utf8 cli.py sample "...\序时账_结果.xlsx" --confidence 高 --n 12 --by-bucket
```

> `sample` 会自动读结果文件里的「业务分类结果」sheet，不用你指定 sheet。

---

## 三、怎么判断（按优先级）

1. **`assets/AI_JUDGMENT_NOTES.md` 里已有的案例与规则**——最优先，那是积累下来的口径
2. **`reference/AI_REVIEW_GUIDE.md` 的跨桶决策表**——大量硬规则
3. **`assets/bucket_definitions.md` 的桶定义与边界**——兜底依据

**只能选 20 个桶之一**，拿不准就标「待人工确认」，不要自己造桶名。

### 几个高频坑

| 凭证长相 | 容易判错成 | 应判 |
|---|---|---|
| 系统维护费 | 长期资产 | **日常费用**（软件开发费才归长期资产） |
| 银行手续费 / 转账费 | 利息收支 | **日常费用**（利息收支只含利息/罚息/结息） |
| 其他应收款 + 一笔钱 | 单位往来 | 先看摘要有没有「押金/保证金」（→押金保证金）、「借款/借支」（→员工借款），都没有才是单位往来 |
| 员工备用金垫付 | 员工借款 | **日常费用** |

## 四、改判怎么做（不做纠错累计）

**AI 可以给改判，但必须回给程序——不能改 Excel。**

- 纠错累计是 1.0 时代（纯程序）留下的机制，那时只能靠用户逐条纠正；
- 现在判断权在模型，**如果出现成规模的错误，根子在模型与训练数据，
  逐条纠错是杯水车薪**；
- 本 skill 已经用 `assets/AI_JUDGMENT_NOTES.md` 做经验积累，
  再叠一套纠错累计是**重复动作**。

### ⚠️ 改判只能走「业务分类补丁」

**为什么不能手改 Excel 的分类列**：现金流是拿业务桶算的，程序在你复核之前
就已经算完并落盘了。你把 Excel 里的「业务分类」改掉，**「现金流量项目」那一列
不会重算**——交付物立刻自相矛盾（分类写着 A，现金流却是按 B 算的）。

实测过这个坑：样例 460 条现金流分录里 **431 条（93.7%）由「桶 + 方向」直接判定**，
桶一错、项目就跟着错，而且因为候选唯一，程序看起来"很确定"，**根本不会报警**。

正确做法是把改判写成业务分类补丁：

```json
{ "vouchers": { "记-00543": { "bucket": "借款筹资", "note": "短期借款[贷]+银行存款[借]" } } }
```

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出" --bucket-patch "分类补丁.json"
```

程序会在算现金流**之前**套用它，于是现金流按改好的桶重算，交付物天然自洽，
并在 `分类判定` 列把这一行标成 `复核改判`。

| 情况 | 怎么处理 |
|---|---|
| 零星几条判错 | 写**业务分类补丁**（`--bucket-patch`），汇报里说明改判了什么 |
| **同一类业务成批判错** | **不要逐条纠**。告诉用户：这家公司数据与模型训练数据偏差较大，需**补充训练数据后重训模型** |
| 用户明确纠正的个别案例 | 记进 `assets/AI_JUDGMENT_NOTES.md` |

> 📌 **改 Excel 分类列只有一个合法用途**：给**训练数据**用
> （`cli.py train export` 读的就是你复核后的 Excel）。那是攒训练样本，
> 不是修这次交付——两件事别混。修交付走补丁。

## 五、积累（"越用越准"的关键）

每次清洗后更新 `assets/AI_JUDGMENT_NOTES.md`：

| 记什么 | 记到哪一节 |
|---|---|
| 遇到的新财务词汇 → 应属哪个桶 | 一、词表补充 |
| 复核确认的「摘要 → 桶」案例 | 二、摘要 → 桶 的确认案例 |
| 新提炼的判断规则 | 三、判断规则备忘 |
| 本次运行的概况与待办 | 四、本次积累记录 |

**纪律**：只追加、不覆盖；写依据；用户纠正的优先级最高；
推断的必须标「低置信度，待验证」，别把猜测写成事实。

## 六、错误处理（按性质分流）

出问题时先判断是**哪一类**，再决定动作——不要一上来就改数据：

| 症状 | 性质 | 动作 |
|---|---|---|
| `coverage < 1.0` | 数据/字段问题 | 看桶分布，排查科目列是否缺失或映射错误 |
| 某个桶占了一半以上 | 口径问题 | 抽样看这个桶，判断是模型不适用还是数据本身如此 |
| 中/低置信度占比很高（>30%） | **模型不适配这家公司** | 不要在结果上打补丁。汇报用户：需要补充训练数据后重训 |
| 同类凭证成批判错 | **模型/桶定义问题** | 同上，走重训路线，不要逐条纠 |
| 现金流待复核条数很多 | 桶定义粒度问题 | 见 `CASHFLOW_GUIDE.md` 第三节：该拆桶了 |
| `ok: false` | 运行失败 | 看 `error` 字段；`stage` 告诉你失败在哪一步 |

> **原则**：程序能确定的错（字段映射、文件格式）→ 修配置重跑；
> 模型层面的错（成批同类错误）→ 汇报并建议重训；
> **只有零星的、程序判不出来的**才值得你逐条给结论。

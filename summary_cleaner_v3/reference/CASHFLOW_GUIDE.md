# 现金流量表编制口径

> 这份文件说明**程序是怎么把业务分类变成现金流量项目的**。
> 权威设计文档是仓库根目录的 `docs/现金流量表编写理论.md`——
> 若本文件与它不一致，**以理论文档为准**，并把本文件改对。

---

## 一、三步，全在程序里

```
① 挑凭证   含「银行存款 / 库存现金 / 其他货币资金」的**整张**凭证
              （不是只留货币资金那一行 —— 编现金流要看对方在干什么）
② 定方向   货币资金在借方 = 收现；在贷方 = 付现
③ 定项目   业务桶 → 候选范围 → 按方向筛出唯一一个
              └─ 仍剩多个（歧义桶）→ 才拿一级科目当裁判 → 还不行就待复核
```

**项目范围只由业务分类决定**，不需要对方科目列。
一级科目**只在第 ③ 步出现歧义时**才参与，且只用来在已有候选里二选一
—— 它不是一套平行的映射表，详见第三节。

---

## 二、方向怎么定（最容易搞错的一步）

| 情形 | 方向 | 说明 |
|---|---|---|
| 货币资金行**只有借方**有数 | **收现** | 借方正数、**借方负数都算收现** |
| 货币资金行**只有贷方**有数 | **付现** | 贷方正数、贷方负数都算付现 |
| 同一行借方和贷方都有数 | 无净流量 | 冲销分录，不进现金流量表 |

### 为什么借方负数还是"收现"

理论文档原话：

> 不需要考虑正负号，如果是货币资金借方负数，等于冲收现，而冲收现≠付现。
> 就好比：销售收款 100 万，退货 20 万，在编现金流量时应该是销售收款 80 万，
> 而不能出现销售收款 100 万，采购付款 20 万。

所以方向**看科目在哪一方，不看金额正负**。金额取 `借方 - 贷方`，
红字自然把对应项目冲减：

| 分录 | 方向 | 项目 | 金额 |
|---|---|---|---|
| 借 银行存款 100 | 收现 | 销售商品、提供劳务收到的现金 | +100 |
| 借 银行存款 **-20**（退货红字） | 收现 | 销售商品、提供劳务收到的现金 | **-20** |
| 合计 | | | **+80** ✅ |

如果把红字判成付现，就会得到"收款 100 + 付款 20"两行——这正是文档要避免的。

## 三、业务桶 → 现金流量项目

| 业务桶 | 收现方向 | 付现方向 |
|---|---|---|
| 销售收入 | 销售商品、提供劳务收到的现金 | 支付其他与经营活动有关的现金 |
| 存货采购 | 收到其他与经营活动有关的现金 | 购买商品、接受劳务支付的现金 |
| 生产制造 | 收到其他与经营活动有关的现金 | 购买商品、接受劳务支付的现金 |
| 日常费用 | 收到其他与经营活动有关的现金 | 支付其他与经营活动有关的现金 |
| 研发 | 收到其他与经营活动有关的现金 | 支付其他与经营活动有关的现金 |
| 职工薪酬 | — | 支付给职工以及为职工支付的现金 |
| 税费 | 收到的税费返还 | 支付的各项税费 |
| 政府补助 | 收到其他与经营活动有关的现金 | — |
| 利息收支 | 收到其他与经营活动有关的现金 | 分配股利、利润或偿付利息支付的现金 |
| 分红股利 | — | 分配股利、利润或偿付利息支付的现金 |
| 借款筹资 | 取得借款收到的现金 | 偿还债务支付的现金 |
| 投资本金 ※ | 收回投资收到的现金 / 吸收投资收到的现金（**歧义，见下**） | 投资支付的现金 |
| 长期资产 | 处置固定资产、无形资产和其他长期资产收回的现金净额 | 购建固定资产、无形资产和其他长期资产支付的现金 |
| 员工借款 | 收到其他与经营活动有关的现金 | 支付其他与经营活动有关的现金 |
| 押金保证金 | 收到其他与经营活动有关的现金 | 支付其他与经营活动有关的现金 |
| 单位往来 | 收到其他与经营活动有关的现金 | 支付其他与经营活动有关的现金 |
| 其他业务 | 收到其他与经营活动有关的现金 | 支付其他与经营活动有关的现金 |
| **折旧摊销** | 不产生现金流量（非付现） | |
| **资金内部往来** | 不产生现金流量（货币资金互转，总额不变） | |
| **汇兑损益** | 不产生现金流量（在报表里单独列"汇率变动对现金的影响"） | |

> **设计原则**：一个桶在**同一个方向上尽量只有一个**项目。
> 能靠桶定义避免的二义性，就不该推给用户。
>
> **为什么同一个桶要列两个方向**：业务桶描述的是一类"业务事项"，
> 同一事项收付两个方向都可能发生。漏了反向项目，
> "退款 / 赎回 / 返还"这类凭证就永远判不出来。

### 投资本金：一个真正的歧义桶（靠一级科目当裁判）

`投资本金` 在**收现**方向上有两个候选，分属不同活动大类：

| 候选 | 活动 | 什么情况下是它 |
|---|---|---|
| 收回投资收到的现金 | **投资活动** | 赎回理财、处置股权、定期存款到期 |
| 吸收投资收到的现金 | **筹资活动** | 股东实缴出资、资本公积转入 |

桶层面**分不出来**——根因是桶没拆开（股东投资 / 金融产品投资）。
当前不重训模型，所以加一层**歧义裁判**：

```
业务桶定候选 → 方向筛 → 仍剩多个 → 才拿一级科目当裁判
```

| 一级科目 | 裁判结果 |
|---|---|
| 交易性金融资产、债权投资、其他债权投资、其他权益工具投资、持有至到期投资、可供出售金融资产、长期股权投资、投资性房地产、定期存款、大额存单、结构性存款、理财产品 | 收回投资收到的现金（投资活动） |
| 实收资本、资本公积、股本 | 吸收投资收到的现金（筹资活动） |

**裁判表在哪里**：`assets/cf/account_ruling.json`

### ⚠️ 一级科目只当裁判，绝不当前锋

依赖顺序是**严格**的：

```
① 业务桶定候选        ← 唯一的主依据
② 货币资金借贷定方向
③ 只有 ①② 还定不下来，才问一级科目
```

绝大多数凭证在第 ② 步就出结果了；只有"歧义桶 + 对应方向"那**一小撮**会走到第 ③ 步。
判定来源（结果文件「业务分类结果」sheet 的「现金流判定」列）会明确标出：

| 判定来源 | 含义 |
|---|---|
| 桶唯一 | 桶只有一个项目，直接定 |
| 桶+方向 | 桶有多个项目，按方向筛出唯一一个 |
| **科目裁判** | 桶 + 方向仍歧义，由一级科目定夺 |
| 待复核 | 裁判也定不下来（科目没登记 / 科目也重叠） |

**为什么不让一级科目当主映射表**：那等于两套口径并行。模型口径一变，
这套表就成了补丁摞补丁，越补越乱，而且没人说得清最终以谁为准。

### 歧义桶出现 = 该拆桶了

歧义桶是个**信号**，不是常态。它说明业务桶的粒度不够：

- 现在的 `投资本金` 把"股东投资"和"金融产品投资"混在一个桶里；
- 正确解法是**把桶拆开**（例如拆成 股东投入 / 金融产品投资），然后重训模型。

裁判表是**过渡补丁**。当某类歧义频繁出现时，说明该回去拆桶重训了，
而不是继续往裁判表里加科目。

## 四、判不下来时怎么办：标"待复核"，不硬选

程序在三种情况下会把条目放进 `run` 出参的 **`cashflow_review.items`**，
而不是硬选一个（**不落 Excel**——待复核是给 AI 的工作项，不是给用户的交付物）：

1. **歧义桶，但一级科目没登记在裁判表里**——例如 `投资本金` 收到钱，
   但对方科目既不是金融资产也不是实收资本/资本公积。
2. **一级科目同时命中多个候选**——科目本身也重叠，裁判失效。
3. **桶映射为空，但确实有货币资金收付**——提示映射表漏配，需要人工看。

**正常数据下这个列表应该是空的。** 它有内容就是信号：

- 如果是第 1、2 种 → 看摘要判断，**写补丁**（`run --cashflow-patch`）交回程序；
  同类反复出现时，考虑往 `account_ruling.json` 补科目；
- 如果是第 3 种 → 修映射表；若频繁出现同类，考虑拆桶重训。

**补丁是唯一的交回方式**——产出 Excel 永远由程序落盘，AI 不手改产出文件：

```cmd
venv\Scripts\python.exe -X utf8 cli.py run "序时账.xlsx" --cashflow-patch "补丁.json"
```

被采纳的条目在结果里标为「补丁补充」，可追溯、可复现。

理由与 3.0 删掉程序打分一致：**没有可靠依据时硬选一个，比标出来更危险**。

复核结论追加到 `assets/AI_JUDGMENT_NOTES.md`。

## 五、当前边界（还没做 / 已知限制）

| 项 | 状态 |
|---|---|
| 正式现金流量表（要货币资金期初余额） | **未做**——目前只出"按项目聚合 + 净增加额" |
| 汇率变动对现金的影响 | 未从凭证计算，需手工填 |
| 同一项目跨月/跨凭证的净额抵减 | 靠金额正负号天然完成（见第二节） |
| 非经营性往来的收付抵销（净额列示） | 未做 |
| **`投资本金` 桶的固有歧义** | 靠一级科目当裁判过渡；根治要拆桶重训 |
| **`借款筹资` 与 `投资本金` 的桶定义重叠** | 两边都写了"股东注资 / 实收资本"，建议拆桶时一并收拢 |

## 六、自检

`status` 命令会跑一次映射表自检（`cashflow` 字段）：

| 字段 | 期望 | 含义 |
|---|---|---|
| `problem_count` | `0` | 引用了不存在的项目 / 方向非法 |
| `ambiguous_buckets` | 看内容 | 哪些桶在哪个方向上有歧义，以及是否已被裁判表覆盖（`unruled` 应为空） |
| `ruling_items` | 与 `ambiguous_buckets` 对应 | 裁判表登记的项目 |
| `ruling_idle` | **空** | 登记了但实际用不到的裁判条目 → 应删除 |
| `ambiguous_without_ruling` | **空** | 有歧义却没有裁判的候选 → 会全部落到待复核 |
| `one_way_buckets` | 看内容 | 只有单一方向的桶（职工薪酬只付现、政府补助只收现），属正常 |

```cmd
venv\Scripts\python.exe -X utf8 cli.py status

:: 只看现金流部分
venv\Scripts\python.exe -X utf8 cli.py status 2>nul | findstr RESULT
```

生成器自带一致性校验，改完映射表跑一次就能发现矛盾：

```cmd
venv\Scripts\python.exe -X utf8 scripts\build_cf_maps.py
```

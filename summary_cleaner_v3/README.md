## 安装（三步）

```cmd
:: ① 建环境（在 skill 目录里；默认走阿里云源，国内快）
python -m venv venv
venv\Scripts\python.exe -m pip install torch --index-url https://mirrors.aliyun.com/pypi/simple/
venv\Scripts\python.exe -m pip install -r requirements.txt

:: ② 下模型（约 622MB，落到 assets/model/，仓库里不含模型）
venv\Scripts\python.exe -X utf8 -c "import sys; from modelscope import snapshot_download; print(snapshot_download('daijiaoshou/hajishou-V1.0', local_dir=sys.argv[1]))" "assets\model"

:: ③ 自检：model_ready 应为 true、bucket_count 应为 20
venv\Scripts\python.exe -X utf8 cli.py status
```

> - **Windows 上 PyPI / 阿里云的 torch 就是 CPU 版**（实测 105.8MB，与官方 `+cpu`
>   轮子只差 84KB），所以 ① 那条既快又不会误装成 2.4GB 的 CUDA 版。想走 GPU 才需要
>   `--index-url https://download.pytorch.org/whl/cu126`。
> - 装完约占 **1.5GB**（venv 0.92GB + 模型 0.62GB）。

## 复核这件事怎么做（3.0 的关键改动）

真账实测：**11456 张凭证 → 4931 个单元**，而概率已经饱和
（93.7% 是 `p=1.000`，**最终确认的错判里绝大多数也是 1.000**）。
"按概率从低到高读"这条路等于白读。所以 `units` 现在给三个视图：

| 视图 | 命令 | 给你什么 | 真账规模 |
|---|---|---|---|
| 全局画像 | `units x.xlsx --summary` | 桶分布、概率分布、族数、最可疑 20 个 | 1 屏 |
| **同族离群** | `units x.xlsx --families` | 按「科目组合」聚族，只列**桶分布不一致**的族 | 约 40 族 / 200+ 条 |
| 逐单元清单 | `units x.xlsx`（默认） | 全部单元，概率升序 | 4931 条 |

按「① 全局 → ② 同族离群 → ③ 尾部小桶整桶看」走，真账上 **约 500 个单元
（10% 的复核面）就命中 47 个改判 / 132 张凭证**。

> ⚠️ **少数派 ≠ 判错**：`应付账款[借] + 银行存款[贷]` 这一族 693 个单元里，
> 109 个"长期资产"（设备款/工程款/软件款）**全是对的** —— 那是银行付款族的正常支线。
> 判定要看摘要语义。

**改判不用重算全量推理**：`units --out-json 单元.json` 会把打分落盘，
`run --reuse-units 单元.json` 直接复用（键是单元键，跨月也命中），
全部命中时不加载模型（实测 800 张样例 7.5s → 1.3s）。

**出参太大就用 `--out-json`**：程序自己用 UTF-8 写**纯 JSON**，stdout 只留摘要。
（Windows PowerShell 的 `1>` 重定向拿到的是 UTF-16LE，按 UTF-8 读必崩——
这事不该由调用方兜。）

## 它做什么

**两件事，一次跑完：**

1. **业务分类**：把一份序时账（Excel/CSV）里的**每一张凭证**，自动归类到
   **20 个标准业务桶**之一（如 存货采购 / 销售收入 / 日常费用 / 职工薪酬 …），
   并给出**置信度**（高 / 中 / 低）。
2. **一键编现金流量表**：在业务分类之上，把涉及货币资金的凭证对应到
   **现金流量项目**（如 销售商品、提供劳务收到的现金），并汇总成现金流量表。

输入只要四列：**凭证号、科目、借方金额、贷方金额**（有摘要更准）。

> 编现金流**不需要**你准备对方科目列，也**不需要**一级科目映射表——
> 项目范围只由业务分类决定，方向由货币资金科目借贷方向决定。

## 谁在判断（3.0 架构）

判断权**完全在模型**，程序只做杂活：

| 角色 | 负责什么 |
|---|---|
| **模型**（微调 BGE-Large） | **18 个业务桶的判定**——读「科目组合 + 摘要」输出概率 |
| **程序** | ① ETL：读文件/认列名　② **切割**：按「科目组合 + 摘要」去重，再把同一科目组合内相似的摘要**归族**成**单元**　③ 加载模型、批量推理　④ 两条写死的机械规则　⑤ 写回凭证　⑥ **现金流映射（业务桶 → 现金流量项目）** |
| **AI 助手** | **复核单元**（不是凭证——凭证可能上万张），以及现金流里判不下来的少数条目 |

> ⚠️ **复核的单位是「单元」，顺序是「先复核、再写回、再算现金流」。**
> 程序把 AI 的复核结论当作**写回的输入**，不是事后修正——所以交付物里
> 业务分类与现金流量项目永远自洽。细节见 `SKILL.md` 的「三个层次与顺序」。
>
> **切割是两层的**：真账摘要里塞满单号/金额/日期，原样文本去重几乎无效
> （实测 11456 张凭证 → 11227 个单元）；所以第二层在**同一科目组合内**
> 把归一化（忽略数字）后相似度 ≥0.95 的摘要并成一族，只让模型判代表，
> 结论写回整族 —— 同一份真账切到 **4931** 个单元。`--sim` 调阈值。

**程序写死的两个桶**（模型没学过，因为这类凭证是机械性的，进训练会污染分布）：

| 桶 | 判定条件 |
|---|---|
| 资金内部往来 | 一张凭证的全部一级科目都是货币资金（纯资金划转） |
| 汇兑损益 | 含财务费用 + 无其他损益类科目 + 无黑名单科目 + 摘要含汇兑/结汇/收汇 |

> ⚠️ **3.0 的关键变化**：程序**不再给业务桶打分**。旧版是"程序规则 20% + 模型 80%"
> 融合打分，实测程序那 20% 在 2,000 张凭证里**一张都没改变过结果**，纯属负担，已整个删除。
> 附带好处：更快（800 张 8.9s → 7s）、架构干净、也没有旧版纠错记录带来的客户数据泄露面。

## 编现金流量表（清洗之后的第二步）

```
业务分类（模型判出的 20 个桶之一）
        │
        ├─ 这张凭证里有货币资金科目吗？ ── 没有 → 不进现金流量表
        │
        ├─ 方向：货币资金在借方 = 收现，在贷方 = 付现
        │        （看在哪一方，**不看正负号**；借方负数 = 冲收现 ≠ 付现）
        │
        └─ 项目：业务桶 → 候选范围，按方向筛出唯一一个
```

举例（口径详解见 `reference/CASHFLOW_GUIDE.md`）：

| 凭证号 | 摘要 | 一级科目 | 借方 | 贷方 | 业务分类 | 现金流量项目 |
|---|---|---|---|---|---|---|
| 101 | 支付1月税费 | 应交税费 | 100 | | 税费 | 支付的各项税费 |
| 101 | 支付1月税费 | 银行存款 | | 100 | 税费 | 支付的各项税费 |

**映射这一步是纯程序**（不调模型、不问 AI），但**它的输入是模型判出来的桶**——
这一点必须说清楚：

- 映射规则本身纯程序、可复现；
- 可桶一错，映射就跟着错。而且候选唯一时程序**看起来"很确定"，不会报警**：
  实测样例 460 条现金流分录里 **436 条（94.8%）由桶直接判定**。
- 所以**复核改判必须回给程序**（`run --unit`），让现金流按改好的桶重算；
  手改导出 Excel 的分类列不会重算现金流，只会让交付物自相矛盾。
- 与清洗**单向解耦**：编现金流不会影响业务分类结果；但业务分类补丁**必须在
  算现金流之前**套用。
- 不硬猜：候选筛不出唯一一个时**标记「待复核」**，而不是随便选一个。
- **单向桶不给反方向候选**：销售收入 / 存货采购 / 日常费用这类桶名自带方向，
  反方向凭证（如日常费用收到退款）会落「待复核 · 方向与桶不符」。
  不给它配一个"支付其他…"，是因为那会把"桶判错了"洗成一个看着合理的项目。
  实测样例里这样的有 7 条（1.5%）——以前它们被静默洗掉了。

### 歧义桶：一级科目只当裁判

`投资本金` 收现有两个候选，分属不同活动大类：

| 候选 | 活动 |
|---|---|
| 收回投资收到的现金 | 投资活动（赎回理财、处置股权） |
| 吸收投资收到的现金 | 筹资活动（股东实缴出资） |

桶层面分不出来。依赖顺序是**严格**的：

```
① 业务桶定候选 → ② 货币资金借贷定方向 → ③ 仍歧义才问一级科目 → ④ 还不行才用兜底表
```

绝大多数凭证在第 ② 步就出结果，只有"歧义桶 + 对应方向"那一小撮走到第 ③④ 步。
判定来源会在结果里明确标出（桶唯一 / 桶+方向 / **科目裁判** / **桶兜底** /
**中性项目** / 待复核 / 未分类）。

**为什么不让一级科目当主映射表**：那等于两套口径并行，模型口径一变就成了
补丁摞补丁。裁判表与兜底表都在 `assets/cf/account_ruling.json`。

> 歧义桶本身是个**信号**——说明桶粒度不够（`投资本金` 把"股东投资"和
> "金融产品投资"混在一起；`利息收支` 把"利息"和"手续费"混在一起）。
> 裁判表/兜底表只是过渡补丁，根治要**拆桶重训模型**。
> 详见 [reference/CASHFLOW_GUIDE.md](reference/CASHFLOW_GUIDE.md) 第三节。

## 3.0 的提速：一句话只问模型一次

一份序时账里同一句摘要会按月重复（"付杭州分公司货款"出现 12 次）。
旧版逐张问模型 12 遍；3.0 先按「科目组合 + 摘要」分组，**一组只算一次**。

实测（1 万张凭证，GPU fp16 / CPU int8 两条路径）：

| 版本 | 模型耗时 | 端到端 |
|---|---:|---:|
| CPU int8 · 改造前 | 258.9s | 307.5s |
| **CPU int8 · 改造后** | **94.8s** | **151.3s（约 2.5 分钟）** |
| GPU fp16 · 改造前 | 25.0s | 72.9s |
| **GPU fp16 · 改造后** | **8.2s** | **55.8s（约 1 分钟）** |

模型调用次数 9,992 → 3,324（**省 66.7%**），两个版本一致。

> 顺带修掉一个老问题：改造前"同一句话问多遍"会让同一输入拿到**略有差异**的概率，
> 导致同一份序时账重跑结果可能变化。现在一个输入只有一个答案，重跑稳定了。

## 版本管理：一个代码库 + 打包剔除

> **下文命令里的 `%PY%` 指 python 解释器**，先设一次：
> 自建 venv 就 `set PY=venv\Scripts\python.exe`；
> 也可以直接把 `%PY%` 换成解释器的绝对路径。
> ⚠️ **别写 `..\venv`**：skill 被装到 `<项目>\.dsh\skills\` 时父目录里没有 venv
> （那条只在开发者的仓库里成立）。详见 `SKILL.md` 第 0 步。

**开发版和用户版是同一份代码**，区别只在发布时剔除什么：

```cmd
:: 打包用户版（默认不带模型 → 约 0.2MB）
%PY% -X utf8 scripts\package_release.py

:: 连模型一起打包（约 622MB，适合压 zip 给单个用户）
%PY% -X utf8 scripts\package_release.py --with-model

:: 打包后自检
%PY% -X utf8 scripts\package_release.py --verify
```

打包脚本剔除的内容：

| 剔除 | 为什么 |
|---|---|
| `jc/training/` | 训练代码——用户只做清洗 |
| `_dev/` | 训练数据金标准、BGE 基座缓存、权重备份 |
| `assets/model/`（默认） | 622MB 模型，让用户按 SKILL.md 自己下；`--with-model` 可带上 |

脚本带**黑名单断言**：一旦发现客户数据或训练数据混进清单，直接报错退出。

## 命令速查（用户）

```cmd
:: 环境自检：模型 / torch / GPU / 桶数
%PY% -X utf8 cli.py status

:: 字段检查（不加载模型、不写数据）
%PY% -X utf8 cli.py check "序时账.xlsx"

:: 完整清洗（写回 + 编现金流 + 导出一个 Excel）
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录"

:: ★ 复核面：把序时账切成单元并打分（不写回、不算现金流、不产出文件）
%PY% -X utf8 cli.py units "序时账.xlsx"
%PY% -X utf8 cli.py units "序时账.xlsx" --summary      :: 全局画像
%PY% -X utf8 cli.py units "序时账.xlsx" --families     :: ★ 同族离群
%PY% -X utf8 cli.py units "序时账.xlsx" --out-json "单元.json"   :: 完整出参落盘

:: ★ 迭代：复用上次打分，跳过全量推理
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出" --reuse-units "单元.json" --unit "U186=借款筹资"
```

清洗导出**一个** Excel（用户不用在多个文件间找）：

| sheet | 给谁 | 内容 |
|---|---|---|
| `原始序时账` | 用户 | 用户给什么就是什么，一个字不改 |
| `业务分类结果` | 用户 | 原始序时账 + 业务分类 + **分类判定** + 置信度 + 现金流量项目 |
| `货币资金凭证` | 用户 | 含货币资金科目的**整张**凭证 + 现金流量项目 |

`分类判定` 标明**这个桶是谁定的**：`模型` / `硬规则` / `复核改判` / `兜底`。
AI 改判过的行会标 `复核改判`，用户一眼能看出哪些结论不是模型给的。

**落盘由程序负责，AI 不写产出文件、也不自己写脚本改数据。**
复核结论用可重复的命令行参数交回程序：

```cmd
:: 1) 出复核面：序时账 → 单元清单（已按最可疑在前排序）
%PY% -X utf8 cli.py units "序时账.xlsx"

:: 2) ★ 交复核结论并出交付物（--unit 可重复，一次交完）
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出" --unit "U186=借款筹资" --unit "U052=单位往来"

:: 3) 现金流还有待复核的，一并补上（务必带上 --unit）
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出" --unit "U186=借款筹资" --cashflow "502=吸收投资收到的现金"
```

**复核结论**（改的是**单元**，不是凭证）：

- 键可以写 `units` 出的**单元号**（`U186`），也可以写**单元键原文**
  （`其他应收款[借] + 银行存款[贷] :: 预付款张三退回`）
- 一个单元可能覆盖多张凭证（实测最多的一个覆盖 **17 张**），改它会一并写回
  ——模型按单元打分，同单元的凭证桶必然相同，只改一张会留下没改到的兄弟
- 被改判的行在结果里 `分类判定` 标 `复核改判`
- 程序把**采纳的**改判写成 `<输出目录>/口径修正.json`，键用**单元键**，
  所以**可以跨月复用**（下个月出现同样的「科目组合 + 摘要」直接命中）
- 需要长期维护这张表时也可以用 `--unit-patch "口径修正.json"`

> **为什么不能让 AI 自己写脚本/JSON**：shell 转义、编码（Windows 记事本写出的
> JSON 默认带 BOM）、路径，处处是坑，改错了还没人拦。程序收参数会校验、会回报。
> **为什么不能手改 Excel 的分类列**：现金流是拿桶算的，改了分类列，
> 现金流量项目列**不会重算**，交付物立刻自相矛盾。实测 94.8% 的现金流分录
> 由桶直接判定（`桶唯一` / `桶+方向`），桶错了程序多半也不会报警。

**现金流补丁**：

```json
{ "rows": { "12": { "item": "吸收投资收到的现金", "note": "对方科目为实收资本" } } }
```

> 键是 `cashflow_review.items` 里的 `行号`（**表体第几行数据**，1 开始；
> 不等于 Excel 工作表行号——表头占第 1 行，所以工作表行号 = 它 + 1）。
> 程序会校验：项目名必须合法、方向必须与收/付一致、**不覆盖已判定的条目**。

> ⚠️ 目前**不单独出「现金流量表」sheet**：那份汇总表需要货币资金期初余额
> 才能编成正式报表，而期初余额本 skill 拿不到。现金流量的明细
> （每条货币资金分录的项目与方向）都在 `货币资金凭证` sheet 里，
> 你可以直接透视汇总。正式现金流量表**待做**。

## 修改现金流映射表

`assets/cf/*.json` 是**业务配置**（不含客户数据），可以直接手改；
改完下次 `run` 即生效。三个文件分工：

| 文件 | 作用 |
|---|---|
| `cf_items.json` | 24 个现金流量项目、方向、报表分组 |
| `bucket_to_cf.json` | 业务桶 → 候选项目（主力映射；单向桶只列一个方向） |
| `account_ruling.json` | 歧义裁判表 + **兜底表**（都只在桶 + 方向定不下来时才参与） |

> 全包只有**这一份**映射表（`assets/cf/`）。`scripts/` 下曾经留过一份同名旧文件，
> 已经删掉 —— 两份同时存在时，没人说得清该信哪份。

也可以改生成器再重跑；生成器带一致性校验（含"兜底值必须是该桶该方向的候选"、
"裁判/兜底登记了却用不到"），改错会直接报错：

```cmd
:: 重新生成 assets/cf/
%PY% -X utf8 scripts\build_cf_maps.py

:: 自检映射表（status 里也会跑）
%PY% -X utf8 cli.py status
```

**3.0 的训练标签来源变了**：旧版用"程序原生桶"自动导出；3.0 删了程序打分，

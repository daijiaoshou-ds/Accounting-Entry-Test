# 序时账清洗 3.0

> **这是一个 AI skill。** 用法是让 AI 助手读 `SKILL.md`，由它带着你走完配置与清洗
> ——你不需要懂代码，也不需要点网页。
>
> 操作流程 → **[SKILL.md](SKILL.md)**
> 20 个业务桶怎么定的 → **[assets/bucket_definitions.md](assets/bucket_definitions.md)**
> 现金流量表怎么编 → **[reference/CASHFLOW_GUIDE.md](reference/CASHFLOW_GUIDE.md)**

---

## 它做什么

**两件事，一次跑完：**

1. **业务分类**：把一份序时账（Excel/CSV）里的**每一张凭证**，自动归类到
   **20 个标准业务桶**之一（如 存货采购 / 销售收入 / 日常费用 / 职工薪酬 …），
   并给出**置信度**（高 / 中 / 低）。
2. **一键编现金流量表**：在业务分类之上，把涉及货币资金的凭证对应到
   **现金流量项目**（如 销售商品、提供劳务收到的现金），并汇总成现金流量表。

输入只要四列：**凭证号、科目、借方金额、贷方金额**（有摘要更准）。

> 编现金流**不需要**你准备对方科目列，也**不需要**一级科目映射表——
> 项目范围只由业务分类决定，方向由货币资金科目借贷方向决定。

## 谁在判断（3.0 架构）

判断权**完全在模型**，程序只做杂活：

| 角色 | 负责什么 |
|---|---|
| **模型**（微调 BGE-Large） | **18 个业务桶的判定**——读「科目组合 + 摘要」输出概率 |
| **程序** | ① ETL：读文件/认列名/写回结果　② 加载模型、批量推理　③ 两条写死的机械规则　④ **现金流映射（业务桶 → 现金流量项目）** |
| **AI 助手** | 复核**中、低置信度**的判断，以及现金流里判不下来的少数条目 |

**程序写死的两个桶**（模型没学过，因为这类凭证是机械性的，进训练会污染分布）：

| 桶 | 判定条件 |
|---|---|
| 资金内部往来 | 一张凭证的全部一级科目都是货币资金（纯资金划转） |
| 汇兑损益 | 含财务费用 + 无其他损益类科目 + 无黑名单科目 + 摘要含汇兑/结汇/收汇 |

> ⚠️ **3.0 的关键变化**：程序**不再给业务桶打分**。旧版是"程序规则 20% + 模型 80%"
> 融合打分，实测程序那 20% 在 2,000 张凭证里**一张都没改变过结果**，纯属负担，已整个删除。
> 附带好处：更快（800 张 8.9s → 7s）、架构干净、也没有旧版纠错记录带来的客户数据泄露面。

## 编现金流量表（清洗之后的第二步）

```
业务分类（模型判出的 20 个桶之一）
        │
        ├─ 这张凭证里有货币资金科目吗？ ── 没有 → 不进现金流量表
        │
        ├─ 方向：货币资金在借方 = 收现，在贷方 = 付现
        │        （看在哪一方，**不看正负号**；借方负数 = 冲收现 ≠ 付现）
        │
        └─ 项目：业务桶 → 候选范围，按方向筛出唯一一个
```

举例（`docs/现金流量表编写理论.md` 的原例）：

| 凭证号 | 摘要 | 一级科目 | 借方 | 贷方 | 业务分类 | 现金流量项目 |
|---|---|---|---|---|---|---|
| 101 | 支付1月税费 | 应交税费 | 100 | | 税费 | 支付的各项税费 |
| 101 | 支付1月税费 | 银行存款 | | 100 | 税费 | 支付的各项税费 |

- 全程**纯程序**，不过模型、不过 AI。
- 与清洗**完全解耦**：编现金流不会影响业务分类结果。
- 不硬猜：候选筛不出唯一一个时**标记「待复核」**，而不是随便选一个。

### 借款筹资 vs 投资本金

这两个桶最容易混，靠**桶定义**分工，不靠映射表猜：

| 桶 | 含义 | 收现 → |
|---|---|---|
| **借款筹资** | 银行借款、融资、股东注资 | 取得借款收到的现金 |
| **投资本金** | 对外投资、收回投资、定期存款/理财 | 收回投资收到的现金 |

映射表**不做语义翻译**，只做"业务桶 → 项目"的机械对应；
否则模型口径一变，映射表就成了一层补丁，越补越乱。
股东出资若被归到 `投资本金`，那是**清洗阶段的归属问题**——
正确做法是修桶定义/补训练数据。详见
[reference/CASHFLOW_GUIDE.md](reference/CASHFLOW_GUIDE.md) 第三节。

## 3.0 的提速：一句话只问模型一次

一份序时账里同一句摘要会按月重复（"付杭州分公司货款"出现 12 次）。
旧版逐张问模型 12 遍；3.0 先按「科目组合 + 摘要」分组，**一组只算一次**。

实测（1 万张凭证，GPU fp16 / CPU int8 两条路径）：

| 版本 | 模型耗时 | 端到端 |
|---|---:|---:|
| CPU int8 · 改造前 | 258.9s | 307.5s |
| **CPU int8 · 改造后** | **94.8s** | **151.3s（约 2.5 分钟）** |
| GPU fp16 · 改造前 | 25.0s | 72.9s |
| **GPU fp16 · 改造后** | **8.2s** | **55.8s（约 1 分钟）** |

模型调用次数 9,992 → 3,324（**省 66.7%**），两个版本一致。

> 顺带修掉一个老问题：改造前"同一句话问多遍"会让同一输入拿到**略有差异**的概率，
> 导致同一份序时账重跑结果可能变化。现在一个输入只有一个答案，重跑稳定了。

## 环境要求

| 项 | 要求 |
|---|---|
| Python | 3.11 ~ 3.13（推荐 3.13） |
| 依赖 | `pip install -r requirements.txt`（**torch 必须单独用 CPU 源装**，见文件头） |
| 模型 | 4 件交付物约 622MB，放 `assets/model/`，见 SKILL.md 第 1 步 |
| 硬件 | 无门槛。有 N 卡（显存空闲 ≥2.5GB）会自动走 GPU，更快 |

> **3.0 没有"纯程序降级模式"**：18 个业务桶全部依赖模型，模型不齐就不能分类。

## 版本管理：一个代码库 + 打包剔除

**开发版和用户版是同一份代码**，区别只在发布时剔除什么：

```cmd
:: 打包用户版（默认不带模型 → 约 0.2MB）
venv\Scripts\python.exe -X utf8 scripts\package_release.py

:: 连模型一起打包（约 622MB，适合压 zip 给单个用户）
venv\Scripts\python.exe -X utf8 scripts\package_release.py --with-model

:: 打包后自检
venv\Scripts\python.exe -X utf8 scripts\package_release.py --verify
```

打包脚本剔除的内容：

| 剔除 | 为什么 |
|---|---|
| `jc/training/` | 训练代码——用户只做清洗 |
| `_dev/` | 训练数据金标准、BGE 基座缓存、权重备份 |
| `assets/model/`（默认） | 622MB 模型，让用户按 SKILL.md 自己下；`--with-model` 可带上 |
| `_storage/` | 运行期缓存 |

脚本带**黑名单断言**：一旦发现客户数据或训练数据混进清单，直接报错退出。

## 命令速查（用户）

```cmd
:: 环境自检：模型 / torch / GPU / 桶数
venv\Scripts\python.exe -X utf8 cli.py status

:: 字段检查（不加载模型、不写数据）
venv\Scripts\python.exe -X utf8 cli.py check "序时账.xlsx"

:: 完整清洗
venv\Scripts\python.exe -X utf8 cli.py run "序时账.xlsx" --out "输出目录"

:: 抽样复核
venv\Scripts\python.exe -X utf8 cli.py sample "输出\序时账_分类结果.xlsx" --confidence 高 --n 5
```

清洗会导出这些文件：

| 文件 | 给谁 |
|---|---|
| `<名>_分类结果.xlsx` | **用户**：原序时账 + 业务分类 + 置信度 + 现金流量项目（仅货币资金行） |
| `<名>_现金流相关凭证.xlsx` | **用户**：含货币资金科目的**整张**凭证，带现金流量项目 |
| `<名>_现金流量表.xlsx` | **用户**：按项目聚合（经营活动/投资活动/筹资活动） |
| `<名>_待复核条目.xlsx` | **AI**：去重后的中/低置信度条目（按条目复核，比逐凭证省得多） |
| `<名>_待复核.xlsx` | **AI**：中/低置信度的凭证清单（含模型 Top3） |
| `<名>_现金流待复核.xlsx` | **AI**：现金流判不下来的条目（**只在有**时才生成） |
| `<名>_凭证明细.xlsx` | 追溯：每张凭证的判定来源与模型概率 |

> `_现金流量表.xlsx` 的末行是"现金及现金等价物净增加额"。
> 完整的正式现金流量表还需要你提供**货币资金期初余额**——这一步暂未做。

## 修改现金流映射表

`assets/cf/*.json` 是**业务配置**（不含客户数据），可以直接手改；
改完下次 `run` 即生效。也可以改生成器再重跑：

```cmd
:: 重新生成 assets/cf/（生成器是纯 ASCII 源码，中文用 \u 转义）
venv\Scripts\python.exe -X utf8 scripts\build_cf_maps.py

:: 自检映射表（status 里也会跑）
venv\Scripts\python.exe -X utf8 -c "import sys;sys.path.insert(0,'.');from jc import cashflow;import json;print(json.dumps(cashflow.validate(),ensure_ascii=False,indent=2))"
```

## 命令速查（开发者：训练）

```cmd
:: 看金标准规模 / 分桶分布 / 未审文件
venv\Scripts\python.exe -X utf8 cli.py train status

:: 1) 把 AI 复核后的分类结果导出为「已审」训练数据
venv\Scripts\python.exe -X utf8 cli.py train export "复核后的分类结果.xlsx"

:: 2) 并入金标准（幂等，可反复执行）
venv\Scripts\python.exe -X utf8 cli.py train merge

:: 3) 微调（需 NVIDIA 显卡，显存 ≥8GB）
venv\Scripts\python.exe -X utf8 cli.py train run
```

**3.0 的训练标签来源变了**：旧版用"程序原生桶"自动导出；3.0 删了程序打分，
标签改成 **AI 复核（含改判）后的最终结果**——每一条都经过复核才进训练集，
比旧版"自动落盘、无人看过"更可靠。

训练直接把 best 权重落盘到 `assets/model/`（推理读取的位置），**训完不需要手动拷贝**。

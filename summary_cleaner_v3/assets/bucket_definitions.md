# 业务桶体系（20 个桶 · 判断依据）

> **这份文件是 AI 判断凭证归属哪个业务桶时的权威依据。**
> 模型只能输出这 20 个桶中的一个，**不存在第 21 个桶**——
> 你（AI）复核时给的建议桶也必须来自这里，不能自己造名字。
>
> 数据来源：`v2/assets/业务桶与keyword.json`（程序实际加载的文件）+ `v2/config.py` 的 `BUCKET_REGISTRY`。
> 若本文件与程序实际行为不一致，**以程序为准**，并把本文件改对。

## 一、桶清单（20 个）

### B. 程序写死的 2 个硬规则桶（模型不学习、不输出）

| 桶 | 判定条件（程序 if 语句） |
|---|---|
| **资金内部往来** | 一张凭证的**全部**一级科目都属于 {库存现金, 银行存款, 其他货币资金} |
| **汇兑损益** | 含财务费用 + 无其他损益类科目 + 无黑名单科目 + 摘要含{汇兑, 结汇, 收汇} |

> 这两个桶由程序在分类第一步直接判定，**置信度恒为「高」**，
> 不参与模型打分，也不会出现在模型概率里。
> 你复核时遇到这两类，直接采信程序结果即可。

## 二、兜底桶的优先级（容易搞错）

当一条凭证同时像多个桶时，程序按「桶清晰度 + 科目偏好 + 关键词」竞争。
**兜底桶排在后面**，优先级从低到高：

```
单位往来 (1.0)  <  税费 (1.0)  <  其他业务 (1.0)  <  押金保证金 (2.0)
   <  日常费用 (3.0) / 员工借款 (3.0)  <  投资本金 (5.0)
   <  生产制造/研发/分红股利 (6.0)  <  利息收支 (7.0)
   <  销售收入/借款筹资/政府补助/折旧摊销 (8.0)
   <  存货采购 (9.0)  <  职工薪酬/长期资产 (10.0)
```

**实务含义**：
- "其他应收款 + 一笔钱" → 优先怀疑 **押金保证金**、**员工借款**、**单位往来** 三者，
  看摘要里有没有"押金/保证金"（→押金保证金）、"借款/借支"（→员工借款），
  都没有才是单位往来。
- **日常费用是最常见的落点**，因为它清晰度低但科目（管理费用/销售费用）覆盖极广。
  费用类拿不准时，落日常费用通常比落其他桶更安全。

## 三、模型的已知短板（复核时重点关注）

来自技术报告 3.0 与历轮 review，这些是模型容易错的地方：

| 短板 | 表现 | 复核建议 |
|---|---|---|
| **类别不均衡** | 日常费用/销售收入/存货采购占摘要约 78%；尾部 8 桶（<100 条）模型近乎随机 | 尾部桶（分红股利/借款筹资/员工借款/政府补助/单位往来/投资本金/押金保证金/其他业务）的判断要多留一分怀疑 |
| **置信度只看模型单方概率** | 最终桶 = 0.2×程序 + 0.8×模型，但高/中/低只按模型概率分档 | 出现"模型概率低但程序力挺"时，不要因为标了「低」就否定它 |
| **长摘要截断** | 模型只看前 64 token（约 200 字符） | 摘要很长的凭证，尾部信息（供应商/日期）模型没看到，可能是判断依据 |
| **科目开关丢行数权重** | 模型只知道"有哪些科目"，不知道"某科目金额占比" | 金额悬殊的多借多贷凭证，模型可能误判，要看金额 |

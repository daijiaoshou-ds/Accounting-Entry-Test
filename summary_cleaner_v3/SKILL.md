# 序时账清洗 3.0 — AI 操作手册

> **你是 AI 助手，这份手册是给你的。用户通常是会计/审计人员，不懂代码。**
> 你要替 TA 把每一步做到位并验证通过；TA 只需要回答几个问题、看一眼结果。

## 这个 skill 在做什么

把一份序时账的**每张凭证**归类到 20 个标准业务桶之一，
并在此基础上一键编出**现金流量表**。两件事一次跑完。

- 输入：序时账 Excel/CSV，至少要有 **凭证号、一级科目、借方金额、贷方金额** 四列
- 输出：**一个** Excel（3 张 sheet），由程序落盘

## ⚠️ 分工铁律（先读这条，再看流程）

| 谁做 | 做什么 | 为什么 |
|---|---|---|
| **程序** | 读文件、认列名、跑模型、编现金流、**导出 Excel**、校验 | 确定、量大、要可复现；落盘是"确定的活"，**你不写产出文件** |
| **你（AI）** | **复核判断**、对程序判不出来的条目**给结论**、把结果**讲成人话** | 这些要读懂自然语言、处理模糊情况，程序写不完 |

**你只做最后一公里。** 不要自己算数、不要自己拼 Excel、不要自己挑样本——
需要数据就用 `sample` 命令，需要结论就写补丁让程序重跑。

```
第 0 步 环境自检 ──────────【程序】检查依赖 →【你】决定装什么
第 1 步 模型自检 ──────────【程序】status →【你】判断能否继续
第 2 步 字段配置 ──────────【程序】check 优先 →【你】只在配不上时兜底
第 3 步 出底稿 ────────────【程序】run → 分类 + 现金流 + 一个 Excel
第 4 步 复核 ─────────────【你】核心环节，按顺序做：
         4.1 找可疑的桶      ← lowest_confidence（含模型次选桶）
         4.2 改判业务分类    →【你】写分类补丁
         4.3 处理现金流待复核 →【你】写现金流补丁
         4.4 带补丁重跑      →【程序】按改好的桶**重算现金流**、重出 Excel
```

> 只要第 4 步有改判或补丁，就必须带补丁重跑，交付**重跑后**的那一份。
> 原因见下面「为什么改判必须回给程序」。

## ⚠️ 为什么改判必须回给程序（先读这条）

**现金流是拿业务桶算出来的**，不是独立判断的。所以：

```
模型判桶 ──→ 程序按桶算现金流 ──→ 写回 ──→ 导出 Excel
                    ↑
        你的改判必须从这里插进去（分类补丁），不能事后改 Excel
```

实测：样例 460 条现金流分录里 **431 条（93.7%）由「桶 + 方向」直接判定**——
桶一错，现金流项目就跟着错，而且因为候选唯一，程序看起来"很确定"，**不会报警**。

**所以你不能这样干**（这是上一轮测试踩过的坑）：

| ❌ 错误做法 | 后果 |
|---|---|
| 手改导出 Excel 的业务分类列 | 现金流列不会重算，交付物自相矛盾；且违反"产出文件由程序落盘" |
| 用现金流补丁去"修"桶判错导致的错误项目 | 程序判定的行**拒收**补丁，改不动 |
| 什么都不做，只在汇报里写"建议改判" | 交付出去的现金流量表仍然是错的 |

**正确做法**：把改判写成**业务分类补丁**，让程序在算现金流**之前**套用，
这样现金流是按改好的桶重算的，交付物天然自洽。

## 第 3 步：执行清洗 【程序】

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录"
```

**程序会做 6 件事，你一件都不用管**：

| 阶段 | 做什么 | 谁 |
|---|---|---|
| 1. ETL | 读文件、认列名、抽出一凭证一条的模型输入 | 程序 |
| 2. 硬规则 | 预分配「资金内部往来」「汇兑损益」 | 程序 |
| 3. 模型打分 | 按「科目组合 + 摘要」折叠，每组只问模型一次 | 程序 |
| **3b. 分类补丁** | **套用你的复核改判（必须在 4 之前，否则现金流会算错）** | 程序 |
| 4. 编现金流 | 业务桶 → 现金流量项目，方向看货币资金借贷 | 程序 |
| 5. 写回 | 结论写回每一张凭证 | 程序 |
| 6. **导出** | **一个** Excel，3 张 sheet | 程序 |

**输出的那一个 Excel，3 张 sheet**：

| sheet | 内容 |
|---|---|
| `原始序时账` | 用户给什么就是什么，一个字不改 |
| `业务分类结果` | 原始序时账 + 业务分类 + **分类判定** + 置信度 + 现金流量项目 |
| `货币资金凭证` | 含货币资金科目的**整张**凭证 + 现金流量项目 |

`分类判定` 这列告诉你**这个桶是谁定的**，用户也靠它审计：
`模型` / `硬规则` / `复核改判`（你改的）/ `兜底`。

> **不要**给用户多个 Excel。**不要**自己生成任何产出文件。

**跑完检查这几个字段**（`run` 出参 JSON）：

| 字段 | 期望 | 不正常说明什么 |
|---|---|---|
| `ok` | `true` | false → 看 `error` 和 `stage` |
| `coverage` | 接近 1.0 | 偏低 → 有凭证没分到桶 |
| `unclassified` | `0` | 不为 0 → 有凭证丢了标签，**别交付** |
| `lowest_confidence` | 10 条，最可疑的在前 | **这是判断"模型适不适配"的正经依据**，逐条看 |
| `confidence_dist` | — | ⚠️ **别拿它当诊断**：模型对熟悉口径会饱和到概率 1.0，这个分布恒为"高占绝大多数"，没有判别力 |
| `cashflow.needs_review_rows` | 越小越好 | 不为 0 → 走第 4 步的补丁流程 |
| `bucket_patch` | 只在带补丁重跑时出现 | 看 `applied` / `rejected` / `unknown_vouchers`，确认改判都被吃进去了 |
| `sheet_rows` | 3 个 sheet | 少一个说明现金流没跑出来 |
| `output_files` | **只有 1 个** | 多于 1 个说明程序有问题 |

## 第 4 步：复核 【你】 ← 本 skill 的核心价值

**按这个顺序做——先找可疑的，再改桶，最后管现金流。顺序不能反**
（理由见前面「为什么改判必须回给程序」）。

```
4.1 找可疑的桶  ← lowest_confidence（10 张，附完整分录 + 模型次选）
4.2 改判        ← 写业务分类补丁（唯一能让现金流跟着改的路）
4.3 管现金流    ← cashflow_review 待复核 → 写现金流补丁
4.4 重跑 + 抽查 ← 带补丁重跑，交付重跑后那份；再 sample 兜底
```

### 4.1 先看「最可疑」的几张（`lowest_confidence`）

`run` 出参里的 `lowest_confidence.items` 是**按模型概率升序**排的 10 张凭证，
每张都附了**完整分录**，还给了模型的**次选**桶：

```json
{
  "凭证号": "记-001", "业务分类": "存货采购", "概率": 0.58,
  "次选": [["借款筹资", 0.42], ["销售收入", 0.0]],
  "摘要": "（示例）某银行福费廷贷款到账",
  "分录": [
    {"一级科目": "短期借款", "借方金额": 0.0, "贷方金额": 950000},
    {"一级科目": "银行存款", "借方金额": 950000, "贷方金额": 0.0}
  ]
}
```

**这几条是本次最值得看的东西**：概率最低 = 模型最没把握；
`次选` 往往就是正确答案（上例 `短期借款[贷] + 银行存款[借]` 应为 `借款筹资`，
不是模型首选的那个）。

**怎么用**：
- 逐条核对 `业务分类`，看**整张凭证**（科目组合 + 摘要），别只看一行；
- 判错了 → 去 4.2 写业务分类补丁；
- 这 10 条里**成批同类判错** → 模型不适配这家公司，建议补训练数据重训，别逐条纠。

### 4.2 桶判错了就改判（业务分类补丁）

```json
{
  "vouchers": {
    "记-00543": { "bucket": "借款筹资", "note": "短期借款[贷]+银行存款[借]，福费廷贸易融资" },
    "记-00157": { "bucket": "单位往来", "note": "其他应收款[借]+银行存款[贷]，预付款退回" }
  }
}
```

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录" --bucket-patch "分类补丁.json"
```

**补丁规则**（程序会校验）：

- 键是**凭证号**（不是行号），值是 `{"bucket": "…", "note": "依据"}`
- `bucket` 必须是 **20 个业务桶之一**，非法桶名会被驳回
- 凭证号写错会被列进 `unknown_vouchers`
- **它作用于整张凭证**（一张凭证一个桶），不是单行
- 被改判的行在结果里 `分类判定` 列标为 **`复核改判`**

> ✅ **这是唯一正确的改判方式**：程序会拿改好的桶**重算现金流**，
> 所以交付物里业务分类与现金流量项目永远自洽。
> ⚠️ 改判后**必须再看一眼 `cashflow_review`**（下一步）——改成另一个桶
> 可能让这笔现金流产生新的歧义（比如改判到 `投资本金` 收现）。

### 4.3 再处理现金流待复核（如果有）

程序判不出来的条目会出现在 `run` 出参的 **`cashflow_review.items`** 里：

```json
{
  "行号": 1, "凭证号": "记-001", "科目": "银行存款",
  "对方科目": ["其他权益工具"], "摘要": "收到某公司投资款",
  "业务分类": "投资本金", "现金流方向": "收",
  "候选项目": ["收回投资收到的现金", "吸收投资收到的现金"],
  "原因": "业务桶「投资本金」在收现方向下有 2 个候选，…"
}
```

**你的任务**：看**摘要 + 对方科目**，从 `候选项目` 里选一个。

**然后写补丁让程序重跑**（不要自己改 Excel）：

```json
{
  "rows": {
    "1": { "item": "吸收投资收到的现金", "note": "对方科目为实收资本，属股东出资" }
  }
}
```

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录" --cashflow-patch "补丁.json"
```

**补丁规则**（程序会校验，不合规的条目会被驳回并告诉你原因）：

- 键是 `items` 里的 `行号`——**该行在序时账表体里是第几行数据**（1 开始）。
  ⚠️ 它**不等于 Excel 的工作表行号**：第 1 行是表头，所以工作表行号 = `行号` + 1。
  写补丁时**原样抄 `items` 里的 `行号` 就行**，别自己去数行。
- `item` 必须是合法现金流量项目，且**方向要与该笔收/付一致**
- 只作用于「待复核」的条目；程序已判定的**不会被覆盖**
- 被采纳的条目在结果里标为 **「补丁补充」**

**为什么必须写补丁而不是改 Excel**：产出文件由程序负责。
补丁是可复现、可审计、可版本管理的；手改 Excel 不是。

### 4.4 带补丁重跑，然后抽查兜底

两个补丁可以一起带（业务分类补丁务必带上，否则改判白做）：

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录" --bucket-patch "分类补丁.json" --cashflow-patch "现金流补丁.json"
```

**重跑后这份才是交付物**（第 3 步那份只是底稿）。看 `bucket_patch` 确认改判
都被吃进去了（`applied` / `rejected` / `unknown_vouchers`）。

再抽一轮高置信度兜底：

```cmd
%PY% -X utf8 cli.py sample "输出\序时账_结果.xlsx" --confidence 高 --n 5 --by-bucket
```

`sample` **每条都返回整张凭证**（`分录` 是全部借贷行），不用再去翻 Excel。
高置信度占 95%+，抽查是为了兜底；**中/低置信度要逐条看**。
发现判错就回 4.2 补进分类补丁，再重跑一次。

> ⚠️ 别被"高置信度"骗了：这个模型的置信度几乎恒为"高"，
> 真正有判别力的是 4.1 的概率排序。

📖 **判断优先级、高频误判对照表、改判怎么做、出错怎么分流
→ `reference/REVIEW_GUIDE.md`**
📖 **跨桶决策表 → `reference/AI_REVIEW_GUIDE.md` 的 A 表**
　（⚠️ 同文件的 B/C 表是**训练数据筛选**口径——写着"不属于任何桶 → 删除"，

　`员工借款` 这些桶，往来款、员工借款都有地方放）

## 出错了先想清楚是哪一类

不要一上来就改数据。**按性质分流**：

| 症状 | 性质 | 动作 |
|---|---|---|
| 字段映射错、文件格式不对 | 程序能确定的错 | 修配置重跑 |
| **同类凭证成批判错** | **模型/桶定义问题** | **不要逐条纠**，汇报并建议补充训练数据后重训 |
| 中/低置信度占比很高 | 模型不适配这家公司 | 同上 |
| 现金流待复核条数很多 | 桶定义粒度不够 | 见 `CASHFLOW_GUIDE.md` 第三节：该拆桶了 |
| 零星几条判错 | 正常误差 | **写业务分类补丁**（4.2）+ 记进积累库 |
| 桶补丁被驳回 | 桶名/凭证号写错 | 看 `bucket_patch.rejected` 与 `unknown_vouchers` |

📖 **完整故障对照表 → `reference/SETUP.md` 第六节**
📖 **错误分流详解 → `reference/REVIEW_GUIDE.md` 第六节**

## 边界（别越界）

- 本 skill 只做**业务分类**与**现金流映射**，不做实质性审计测试、不评价合规性。
- **不生成产出文件**——Excel 永远由程序落盘；你只写补丁。
- **不手改产出文件来"修"分类**——改分类走**业务分类补丁**，
  否则现金流列不会重算，交付物会自相矛盾（见前面「为什么改判必须回给程序」）。
- **不逐条纠错**——成规模的错误说明该重训模型，不是该打补丁。
- **不造桶名**——只能选 20 个桶之一，拿不准标「待人工确认」。
- **不改 `assets/cf/*.json` 来"修"个别案例**——那是业务配置，
  改它会影响所有同桶凭证。个别问题走补丁。

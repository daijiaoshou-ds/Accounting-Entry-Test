# 序时账清洗 3.0 — AI 操作手册

> **你是 AI 助手，这份手册是给你的。用户通常是会计/审计人员，不懂代码。**
> 你要替 TA 把每一步做到位并验证通过；TA 只需要回答几个问题、看一眼结果。

## 这个 skill 在做什么

把一份序时账**先切成单元、再判到 20 个标准业务桶**，并在此基础上一键编出**现金流量表**。

- 输入：序时账 Excel/CSV，至少要有 **凭证号、一级科目、借方金额、贷方金额** 四列
- 中间产物：**单元清单**（切割 + 打分的结果，交给 AI 复核）
- 输出：**一个** Excel（3 张 sheet），由程序落盘

## ⚠️ 分工铁律（先读这条，再看流程）

| 谁做 | 做什么 | 为什么 |
|---|---|---|
| **程序** | 读文件、认列名、**切成单元**、跑模型、写回凭证、编现金流、**导出 Excel**、校验 | 确定、量大、要可复现；落盘是"确定的活"，**你不写产出文件** |
| **你（AI）** | **复核单元**、把结论交回程序、把结果**讲成人话** | 要读懂自然语言、处理模糊情况，程序写不完 |

**你只做最后一公里。** 不要自己算数、不要自己拼 Excel、**不要自己写 JSON/脚本改东西**——
需要复核面就用 `units` 命令，有结论就用 `run --unit` / `run --cashflow` 交回程序。

## ⚠️ 三个层次与顺序（先读这条，别记反）

```
序时账（几千张凭证）
   │
   ① 切割 ── 按「科目组合 + 摘要」去重 ──→ 单元（几百个）
   │                                      ★ 这一层**没有凭证号**
   ② 打分 ── 模型给**每个单元**一个桶（一次推理 = 一个单元）
   ③ 复核 ── **你**看的就是这些单元
   │                                      ★ 你改的是单元，不是凭证
   ④ 写回 ── 单元 → 桶，铺到具体凭证      ★ 凭证号在这一步才出现
   ⑤ 现金流 ─ 程序拿具体凭证（货币资金行）→ 现金流量项目
```

**为什么是这个顺序**：你的复核结论是**写回的输入**，不是事后修正。
先改单元，再写回凭证，再算现金流 —— 所以交付物天然自洽
（业务分类与现金流量项目永远对得上）。

**为什么你复核的是单元而不是凭证**：凭证可能几千张，AI 必然复核不过来；
同一份序时账切出来的单元通常只有几百个，才是能过一遍的量。

实测样例：**800 张凭证 → 278 个单元**；其中 124 张凭证（15.5%）落在
"一个单元多张凭证"里（最多的一个单元覆盖 **17 张**）。
所以改一个单元会连带写回它名下所有凭证 —— 这是应该的：
模型是按单元打分的，同单元的凭证桶**必然相同**，只改一张会留下没改到的兄弟。

**所以你不能这样干**：

| ❌ 错误做法 | 后果 |
|---|---|
| 手改导出 Excel 的业务分类列 | 现金流列不会重算，交付物自相矛盾；且违反"产出文件由程序落盘" |
| 自己写 PowerShell / Python 脚本去改补丁文件 | shell 转义、BOM、编码、路径处处是坑，而且改错了没人拦 |
| 用 `run --cashflow` 去"修"单元判错导致的错误项目 | 程序判定的行**拒收**，改不动；而且根子在单元，不在现金流 |
| 什么都不做，只在汇报里写"建议改判" | 交付出去的现金流量表仍然是错的 |

**正确做法**：把结论用**可重复的命令行参数**交给程序（见第 4、5 步），
别写文件、别碰 Excel。

## 第 3 步：切成单元并打分 【程序】

```cmd
%PY% -X utf8 cli.py units "序时账.xlsx"
```

**这一步只做 ①②：切割 + 打分，不写回凭证、不算现金流、不产出任何文件。**
它的出参就是你的**复核面**。

程序会做 3 件事：

| 阶段 | 做什么 |
|---|---|
| 1. ETL | 读文件、认列名 |
| 2. 硬规则 | 预分配「资金内部往来」「汇兑损益」（这几类程序直接定） |
| 3. 切割 + 打分 | 按「科目组合 + 摘要」去重成单元，每个单元问模型一次 |

**出参关键字段**：

| 字段 | 含义 |
|---|---|
| `vouchers` / `unit_count` | 多少张凭证 / 切成多少个单元（复核面大小） |
| `units[].单元号` | 如 `U137`——交给程序时的简短把手 |
| `units[].单元键` | `科目组合 :: 摘要` 的规范文本，**可跨月复用** |
| `units[].模型桶` | 模型判的桶（要复核的就是它） |
| `units[].概率` | 模型对这个桶的概率（越低越可疑） |
| `units[].次选` | 模型拿不准时的第二/第三选择，**往往就是正确答案** |
| `units[].来源` | `模型` / `硬规则` / `兜底` |
| `units[].覆盖凭证数` | 这个单元铺到几张凭证（改它就会改这么多张） |

**清单已按概率升序排好**（最可疑的在最前），硬规则单元没概率、排最后。
清单通常只有几百条，**从头往下看**即可；`--limit` / `--offset` 可以翻页，
`--bucket 销售费用` 之类可以只看某个桶。

> ⚠️ **别用 `confidence_dist` 做判断**：这个模型对熟悉口径会饱和到概率 1.0
> （实测中位数 1.0000、95%+ 落进"高"），三档标签几乎没有区分度。
> 有判别力的是**概率的排序**，也就是上面这个清单的顺序。

📖 **桶的权威定义与边界 → `assets/bucket_definitions.md`**

## 第 4 步：复核单元 【你】 ← 本 skill 的核心价值

**逐个看单元，判断「模型桶」对不对。** 依据优先级：

1. **`assets/AI_JUDGMENT_NOTES.md` 里已有的案例与规则**——最优先，那是积累下来的口径
2. **`reference/AI_REVIEW_GUIDE.md` 的 A 表**——模式 → 桶的硬规则
3. **`assets/bucket_definitions.md` 的桶定义与边界**——兜底依据

**只能选 20 个桶之一**，拿不准就标「待人工确认」，不要自己造桶名。

### 4.1 怎么读一个单元

```
U186  模型桶=存货采购  p=0.5777  覆盖 1 张
单元键：短期借款[贷] + 银行存款[借] :: 2025/8/15-入福费廷贷款2000万
次选：  [["借款筹资", 0.4218], ["销售收入", 0.0003]]
```

- 看**科目组合 + 摘要**（这就是模型看到的全部输入，也是单元的身份）；
- 概率低 + `次选` 就看着像正确答案 → **大概率判错了**；
- 上例 `短期借款[贷] + 银行存款[借]` 是收借款，应为 `借款筹资`，
  不是 `存货采购`（模型被"费"字带偏了）。

### 4.2 把结论交回程序（**不要写文件**）

一条命令交完所有改判，`--unit` 可以重复：

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录" ^
  --unit "U186=借款筹资" ^
  --unit "U052=单位往来"
```

- 键可以是 **单元号**（`U186`，短、不易抄错），也可以是**单元键原文**：
  `--unit "短期借款[贷] + 银行存款[借] :: 2025/8/15-入福费廷贷款2000万=借款筹资"`
- `--unit` 可以写**很多次**——一次把结论交完，**别发现一个跑一次**
- 桶名必须是 **20 个业务桶之一**，非法桶名会被驳回；
  单元没找到会列进 `unknown_units`
- 程序会把生效的口径修正写成 `<输出目录>/口径修正.json` 留档。
  **它是程序写的，不是你写的**；键用的是**单元键**，所以下个月出现同样的
  「科目组合 + 摘要」时会直接命中——这就是可复用的口径修正表。

### 4.3 拿不准 / 成批出错怎么办

| 情况 | 怎么处理 |
|---|---|
| 零星几个单元判错 | 用 `--unit` 改判，汇报里说明改了什么、依据是什么 |
| **成批同类单元判错** | **不要逐个改**。说明模型不适配这家公司，汇报并建议**补训练数据后重训** |
| 某几个单元确实定不了 | 不要硬猜，标「待人工确认」并在汇报里列出来 |

📖 **判断优先级、高频误判对照表、出错怎么分流 → `reference/REVIEW_GUIDE.md`**
📖 **跨桶决策表 → `reference/AI_REVIEW_GUIDE.md` 的 A 表**
　（⚠️ 同文件的 B/C 表是**训练数据筛选**口径——写着"不属于任何桶 → 删除"，
　那是 1.0 时代挑训练样本的标准，**3.0 复核时不要执行**：3.0 有 `单位往来`／
　`员工借款` 这些桶，往来款、员工借款都有地方放）

## 第 5 步：写回 + 编现金流 + 导出 【程序】

复核结论作为**输入**传给 `run`：

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录" --unit "U186=借款筹资"
```

程序会做（顺序不可调换）：

| 阶段 | 做什么 |
|---|---|
| 1. 切割 + 打分 | 同第 3 步（`units` 与 `run` 用的是同一段逻辑，单元号也一致） |
| **2. 套用复核结论** | 按你交的单元改桶 —— 这是**写回的输入** |
| 3. 写回 | 单元 → 桶，铺到每一张具体凭证（`分类判定` 标 `复核改判`） |
| 4. 编现金流 | 业务桶 → 现金流量项目，方向看货币资金借贷 |
| 5. 导出 | **一个** Excel，3 张 sheet |

**输出的那一个 Excel，3 张 sheet**：

| sheet | 内容 |
|---|---|
| `原始序时账` | 用户给什么就是什么，一个字不改 |
| `业务分类结果` | 原始序时账 + 业务分类 + **分类判定** + 置信度 + 现金流量项目 |
| `货币资金凭证` | 含货币资金科目的**整张**凭证 + 现金流量项目 |

`分类判定` 这列告诉你**这个桶是谁定的**，用户也靠它审计：
`模型` / `硬规则` / `复核改判`（你改的）/ `兜底`。

> **不要**给用户多个 Excel。**不要**自己生成任何产出文件。

**跑完检查这几个字段**（`run` 出参 JSON）：

| 字段 | 期望 | 不正常说明什么 |
|---|---|---|
| `ok` | `true` | false → 看 `error` 和 `stage` |
| `coverage` | 接近 1.0 | 偏低 → 有凭证没分到桶 |
| `unclassified` | `0` | 不为 0 → 有凭证丢了标签，**别交付** |
| `unit_patch` | 你交的结论 | 看 `applied` / `changed_vouchers` / `rejected` / `unknown_units`，确认都吃进去了 |
| `patch_files` | 程序写的留档 | 口径修正表在 `<输出目录>/口径修正.json` |
| `cashflow.needs_review_rows` | 越小越好 | 不为 0 → 看下一节 |
| `sheet_rows` | 3 个 sheet | 少一个说明现金流没跑出来 |
| `output_files` | **只有 1 个** | 多于 1 个说明程序有问题 |

### 5.1 现金流"待复核"（如果有）

改完单元、算完现金流后，可能出现程序判不下来的条目，
在 `run` 出参的 **`cashflow_review.items`** 里：

```json
{
  "行号": 1, "凭证号": "记-001", "科目": "银行存款",
  "对方科目": ["其他权益工具"], "摘要": "收到某公司投资款",
  "业务分类": "投资本金", "现金流方向": "收",
  "候选项目": ["收回投资收到的现金", "吸收投资收到的现金"],
  "原因": "业务桶「投资本金」在收现方向下有 2 个候选，…"
}
```

**你的任务**：看**摘要 + 对方科目**，从 `候选项目` 里选一个，用 `--cashflow` 交回去
（同样可以重复，同样不用写文件）：

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录" ^
  --unit "U186=借款筹资" ^
  --cashflow "502=吸收投资收到的现金"
```

- 键是 `items` 里的 `行号`——**该行在序时账表体里是第几行数据**（1 开始）。
  ⚠️ 它**不等于 Excel 的工作表行号**：第 1 行是表头，所以工作表行号 = `行号` + 1。
  **原样抄 `items` 里的 `行号` 就行**，别自己去数行。
- `item` 必须是合法现金流量项目，且**方向要与该笔收/付一致**
- 只作用于「待复核」的条目；程序已判定的**不会被覆盖**
- 被采纳的条目在结果里标为 **「补丁补充」**

> ⚠️ **带上 `--unit` 一起跑**：`run` 每次都是从零重算的，
> 漏带 `--unit` 你的改判就白做了。

```cmd
:: ★ 切成单元并打分 —— 你的复核面（不写回、不算现金流、不产出文件）
%PY% -X utf8 cli.py units "序时账.xlsx"

:: 只看最可疑的 40 个单元 / 翻页 / 只看某个桶
%PY% -X utf8 cli.py units "序时账.xlsx" --limit 40
%PY% -X utf8 cli.py units "序时账.xlsx" --offset 40 --limit 40
%PY% -X utf8 cli.py units "序时账.xlsx" --bucket 销售收入

:: ★ 把复核结论交回程序并出交付物（--unit 可重复）
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录" --unit "U186=借款筹资" --unit "U052=单位往来"

:: 再补现金流待复核条目（务必带上 --unit）
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录" --unit "U186=借款筹资" --cashflow "502=吸收投资收到的现金"

:: 需要长期维护/跨月复用口径时，也可以用修正表文件
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录" --unit-patch "口径修正.json"
```

## 出错了先想清楚是哪一类

不要一上来就改数据。**按性质分流**：

| 症状 | 性质 | 动作 |
|---|---|---|
| 字段映射错、文件格式不对 | 程序能确定的错 | 修配置重跑 |
| **同类单元成批判错** | **模型/桶定义问题** | **不要逐个改**，汇报并建议补充训练数据后重训 |
| 现金流待复核条数很多 | 桶定义粒度不够 | 见 `CASHFLOW_GUIDE.md` 第三节：该拆桶了 |
| 零星几个单元判错 | 正常误差 | 用 `--unit` 改判 + 记进积累库 |
| `--unit` 报 `unknown_units` | 单元号/单元键抄错 | 重新跑 `units` 核对；单元号只对同一份文件有效 |
| `--unit` 被驳回 | 桶名不是 20 个之一 | 看 `rejected` 里的原因 |

📖 **完整故障对照表 → `reference/SETUP.md` 第六节**
📖 **错误分流详解 → `reference/REVIEW_GUIDE.md` 第六节**

## 边界（别越界）

- 本 skill 只做**业务分类**与**现金流映射**，不做实质性审计测试、不评价合规性。
- **不生成产出文件**——Excel 永远由程序落盘。
- **不自己写脚本/JSON 去改数据**——结论只用命令行参数交回程序。
  手写 shell 脚本改文件容易踩转义、编码、路径的坑，而且改错了没人拦。
- **不手改产出文件**——改业务分类要走 `--unit`，否则现金流列不会重算，
  交付物会自相矛盾。
- **不逐个纠错**——成规模的错误说明该重训模型，不是该逐个改单元。
- **不造桶名**——只能选 20 个桶之一，拿不准标「待人工确认」。
- **不改 `assets/cf/*.json` 来"修"个别案例**——那是业务配置，
  改它会影响所有同桶凭证。个别问题走 `--unit` / `--cashflow`。

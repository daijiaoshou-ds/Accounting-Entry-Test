# 序时账清洗 3.0 — AI 操作手册

> **你是 AI 助手，这份手册是给你的。用户通常是会计/审计人员，不懂代码。**
> 你要替 TA 把每一步做到位并验证通过；TA 只需要回答几个问题、看一眼结果。

## 这个 skill 在做什么

把一份序时账的**每张凭证**归类到 20 个标准业务桶之一，
并在此基础上一键编出**现金流量表**。两件事一次跑完。

- 输入：序时账 Excel/CSV，至少要有 **凭证号、一级科目、借方金额、贷方金额** 四列
- 输出：**一个** Excel（3 张 sheet），由程序落盘

## ⚠️ 分工铁律（先读这条，再看流程）

| 谁做 | 做什么 | 为什么 |
|---|---|---|
| **程序** | 读文件、认列名、跑模型、编现金流、**导出 Excel**、校验 | 确定、量大、要可复现；落盘是"确定的活"，**你不写产出文件** |
| **你（AI）** | **复核判断**、对程序判不出来的条目**给结论**、把结果**讲成人话** | 这些要读懂自然语言、处理模糊情况，程序写不完 |

**你只做最后一公里。** 不要自己算数、不要自己拼 Excel、不要自己挑样本——
需要数据就用 `sample` 命令，需要结论就写补丁让程序重跑。

## 你的操作流程

```
第 0 步 环境自检 ──────────【程序】检查依赖 →【你】决定装什么
第 1 步 模型自检 ──────────【程序】status →【你】判断能否继续
第 2 步 字段配置 ──────────【程序】check 优先 →【你】只在配不上时兜底
第 3 步 执行清洗 ──────────【程序】run（业务分类 + 现金流 + 导出一个 Excel）
第 4 步 复核 ─────────────【你】抽样看业务分类 + 处理现金流待复核
         └─ 有现金流待复核 →【你】写补丁 →【程序】带补丁重跑
第 5 步 交付与积累 ────────【你】汇报 + 更新积累库
```

每一步的"判断点"在下面各节。**具体的命令、踩坑、判断表放在 reference/ 里，
按需去读**——别一次性全读进来。

## 第 1 步：模型自检 【程序】+ 判断点

```cmd
venv\Scripts\python.exe -X utf8 cli.py status
```

**看 `model_ready` 一个字段就够：**

| 结果 | 动作 |
|---|---|
| `true` | 继续第 2 步 |
| `false` | **停下来**，告诉用户需要下载模型（约 622MB） |

> ❌ **3.0 没有"纯程序降级模式"**——18 个业务桶全部依赖模型。
> 模型不齐就**不能分类**，不要试图继续跑。

同时扫一眼 `cashflow.problem_count`（应为 `0`）、`bucket_count`（应为 `20`）。

📖 **模型下载方式、status 全字段解释 → `reference/SETUP.md` 第二、三节**

## 第 2 步：字段配置 【程序】优先，【你】兜底

```cmd
venv\Scripts\python.exe -X utf8 cli.py check "用户给的序时账.xlsx"
```

**判断点**：看 `ok` 和 `preview`。

| 结果 | 动作 |
|---|---|
| `ok: true`，且 `preview` 样例值对得上 | 直接进第 3 步 |
| `ok: false`（缺必需字段） | 你来生成映射 JSON，用 `--set` 传 |

**为什么这步需要你兜底**：程序能认「科目」「一级科目」这类标准表头，
但认不出「存货科目」这种写法。这时只有你能看懂它是什么。

📖 **角色化匹配的细节、映射 JSON 格式 → `reference/SETUP.md` 第四节**

## 第 3 步：执行清洗 【程序】

```cmd
venv\Scripts\python.exe -X utf8 cli.py run "序时账.xlsx" --out "输出目录"
```

**程序会做 6 件事，你一件都不用管**：

| 阶段 | 做什么 | 谁 |
|---|---|---|
| 1. ETL | 读文件、认列名、抽出一凭证一条的模型输入 | 程序 |
| 2. 硬规则 | 预分配「资金内部往来」「汇兑损益」 | 程序 |
| 3. 模型打分 | 按「科目组合 + 摘要」折叠，每组只问模型一次 | 程序 |
| 4. 编现金流 | 业务桶 → 现金流量项目，方向看货币资金借贷 | 程序 |
| 5. 写回 | 结论写回每一张凭证 | 程序 |
| 6. **导出** | **一个** Excel，3 张 sheet | 程序 |

**输出的那一个 Excel，3 张 sheet**：

| sheet | 内容 |
|---|---|
| `原始序时账` | 用户给什么就是什么，一个字不改 |
| `业务分类结果` | 原始序时账 + 业务分类 + 置信度 + 现金流量项目 |
| `货币资金凭证` | 含货币资金科目的**整张**凭证 + 现金流量项目 |

> **不要**给用户多个 Excel。**不要**自己生成任何产出文件。

**跑完检查这几个字段**（`run` 出参 JSON）：

| 字段 | 期望 | 不正常说明什么 |
|---|---|---|
| `ok` | `true` | false → 看 `error` 和 `stage` |
| `coverage` | 接近 1.0 | 偏低 → 有凭证没分到桶 |
| `unclassified` | `0` | 不为 0 → 有凭证丢了标签，**别交付** |
| `confidence_dist` | 高占多数 | 低占比过高 → 模型可能不适配这家公司 |
| `cashflow.needs_review_rows` | 越小越好 | 不为 0 → 走第 4 步的补丁流程 |
| `sheet_rows` | 3 个 sheet | 少一个说明现金流没跑出来 |
| `output_files` | **只有 1 个** | 多于 1 个说明程序有问题 |

## 第 4 步：复核 【你】 ← 本 skill 的核心价值

**你要复核两样东西**，按下面的顺序做：

### 4.1 先处理现金流待复核（如果有）

程序判不出来的条目会出现在 `run` 出参的 **`cashflow_review.items`** 里：

```json
{
  "行号": 1, "凭证号": "记-001", "科目": "银行存款",
  "对方科目": ["其他权益工具"], "摘要": "收到某公司投资款",
  "业务分类": "投资本金", "现金流方向": "收",
  "候选项目": ["收回投资收到的现金", "吸收投资收到的现金"],
  "原因": "业务桶「投资本金」在收现方向下有 2 个候选，…"
}
```

**你的任务**：看**摘要 + 对方科目**，从 `候选项目` 里选一个。

**然后写补丁让程序重跑**（不要自己改 Excel）：

```json
{
  "rows": {
    "1": { "item": "吸收投资收到的现金", "note": "对方科目为实收资本，属股东出资" }
  }
}
```

```cmd
venv\Scripts\python.exe -X utf8 cli.py run "序时账.xlsx" --out "输出目录" --cashflow-patch "补丁.json"
```

**补丁规则**（程序会校验，不合规的条目会被驳回并告诉你原因）：

- 键是 `items` 里的 `行号`（**1 开始，与 Excel 行号一致**）
- `item` 必须是合法现金流量项目，且**方向要与该笔收/付一致**
- 只作用于「待复核」的条目；程序已判定的**不会被覆盖**
- 被采纳的条目在结果里标为 **「补丁补充」**

**为什么必须写补丁而不是改 Excel**：产出文件由程序负责。
补丁是可复现、可审计、可版本管理的；手改 Excel 不是。

### 4.2 再抽查业务分类

```cmd
venv\Scripts\python.exe -X utf8 cli.py sample "输出\序时账_结果.xlsx" --confidence 高 --n 5
```

**高置信度占 95%+，也不能完全不看**（否则没有质量兜底）；
中/低置信度要逐条看。

📖 **判断优先级、高频误判对照表、改判怎么做、出错怎么分流
→ `reference/REVIEW_GUIDE.md`**
📖 **跨桶决策表（大量硬规则）→ `reference/AI_REVIEW_GUIDE.md`**
📖 **桶的权威定义与边界 → `assets/bucket_definitions.md`**
📖 **现金流口径与边界 → `reference/CASHFLOW_GUIDE.md`**

```cmd
:: 环境自检
venv\Scripts\python.exe -c "import torch; print(torch.__version__, torch.version.cuda)"

:: 就绪度（模型 / torch / GPU / 桶数 / 现金流映射表自检）

:: 字段检查（不跑模型、不写数据）
venv\Scripts\python.exe -X utf8 cli.py check "序时账.xlsx"

:: 字段检查 + 手工映射
venv\Scripts\python.exe -X utf8 cli.py check "序时账.xlsx" --set "字段映射.json"

:: 执行清洗（业务分类 + 现金流 + 导出一个 Excel）
venv\Scripts\python.exe -X utf8 cli.py run "序时账.xlsx" --out "输出目录"

:: 带补丁重跑（补上待复核的现金流条目）
venv\Scripts\python.exe -X utf8 cli.py run "序时账.xlsx" --out "输出目录" --cashflow-patch "补丁.json"

:: 抽样复核
venv\Scripts\python.exe -X utf8 cli.py sample "输出\序时账_结果.xlsx" --confidence 高 --n 5
venv\Scripts\python.exe -X utf8 cli.py sample "...\序时账_结果.xlsx" --confidence 中 --n 20
venv\Scripts\python.exe -X utf8 cli.py sample "...\序时账_结果.xlsx" --confidence 高 --n 12 --by-bucket
```

> 所有命令都是**单行 JSON 出参**（前缀 `RESULT `），进度信息走 stderr。
> 解析时只认 `RESULT ` 开头那一行。

## 出错了先想清楚是哪一类

不要一上来就改数据。**按性质分流**：

| 症状 | 性质 | 动作 |
|---|---|---|
| 字段映射错、文件格式不对 | 程序能确定的错 | 修配置重跑 |
| **同类凭证成批判错** | **模型/桶定义问题** | **不要逐条纠**，汇报并建议补充训练数据后重训 |
| 中/低置信度占比很高 | 模型不适配这家公司 | 同上 |
| 现金流待复核条数很多 | 桶定义粒度不够 | 见 `CASHFLOW_GUIDE.md` 第三节：该拆桶了 |
| 零星几条判错 | 正常误差 | 你给结论，记进积累库 |

📖 **完整故障对照表 → `reference/SETUP.md` 第六节**
📖 **错误分流详解 → `reference/REVIEW_GUIDE.md` 第六节**

## 边界（别越界）

- 本 skill 只做**业务分类**与**现金流映射**，不做实质性审计测试、不评价合规性。
- **不生成产出文件**——Excel 永远由程序落盘；你只写补丁。
- **不逐条纠错**——成规模的错误说明该重训模型，不是该打补丁。
- **不造桶名**——只能选 20 个桶之一，拿不准标「待人工确认」。
- **不改 `assets/cf/*.json` 来"修"个别案例**——那是业务配置，
  改它会影响所有同桶凭证。个别问题走补丁。

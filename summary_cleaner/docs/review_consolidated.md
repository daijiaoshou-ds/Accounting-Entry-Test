## 3. 架构层面的观察（非 bug，但重要的设计张力）

这些是历轮 review 反复提到、且当前实现「符合既定需求」但值得持续关注的点：

1. **融合置信度只反映模型单方概率**：最终桶 = 0.2×程序 + 0.8×NN，但置信度只按 P_nn(bucket*) 分档——模型 30% 但程序力挺时记「低」。若想更诚实，应保存融合概率向量后分档（技术报告 3.0 §十 第 5 条已列入下一步）。
2. **金标准 count 语义在「程序进化」后冻结**：count = 入库时的分类质量，程序/融合升级后旧数据的错误标签删不掉，需定期人工复审。
3. **硬规则桶与 NN 边界单向**：预分配桶不走 NN 且置信度恒「高」，其中员工借款规则 0d 最脆弱（字符串逻辑，边界案例可能漏判）。建议四个硬规则桶各建定期抽查清单。
4. **NN 科目开关丢失行数/金额权重**：set 去重后「3 行银行存款 + 1 行应付账款」与「1+1」同为两个开关，金额权重只存在于程序侧 v 向量。
5. **PMI 静态性**：通用 R 只增不减，不会遗忘过时共现；**L2 归一化稀释**：w' 值通常只有初始 w 的 1/5~1/10（融合后程序权重仅 20%，影响已大幅降低）。
6. **类别不均衡**：头部三桶（日常费用/存货采购/销售收入）占摘要 76%，尾部 7 桶（<100 条）模型近乎随机——专项补数据是最大杠杆。
7. **auto 数据噪声**：置信度 high 直接并入金标准的记录可能残留程序错误标签，需定期抽样复审。
8. **jieba 分词依赖词库**：「材料采购过渡」等财务术语需人工补充词库。

## 4. 做得好的方面（历轮一致认可）

1. **双轨 + 融合架构**：程序可解释、可纠错、冷启动可用；模型懂语义、泛化强；融合取长补短（20/80）。
2. **纠错回路闭环且幂等**：金额 EMA 按 (vid,金额) 历史精确回滚、改判覆盖撤销旧信号、批次内去重 + 批次间内容哈希防重。
3. **训练数据管线完整**：buckets_v2 按桶聚合审核、相似摘要数字归一化去重、跨文件 count 加权众数、幂等 merge、记录级 80/20 分层切分防泄漏。
4. **交付物加载校验严格**：缺失显式报错、分类头键集合校验、科目索引/桶映射逐项比对、weights_only=True 防 pickle 注入。
5. **显存工程细致**：chunk 批量推理、fp16 AMP + gradient checkpointing、显存自检表、训练结束 empty_cache()、残留进度清理。
6. **硬规则 0a~0d 边界处理到位**：红字凭证绝对值判方向、NaN truthy 陷阱、员工借款与单位借款的科目+摘要联合判定。

## 第一阶段：学习（分类完成后）

每次分类完成后，系统用刚分好类的数据来"学习"。

### Step 1: jieba 分词

对每张凭证的**摘要**和**科目名称**拼接后的文本做分词：

```
原文: "支付王总去北京出差的顺丰快递费"
jieba分词: ['支付', '王总', '去', '北京', '出差', '的', '顺丰', '快递费']
```

### Step 2: 五重过滤

分词后经过五道滤网：

| 序号 | 过滤器 | 排除内容 | 例子 |
|------|--------|---------|------|
| ① | 长度 | 单字 | `的` `去` |
| ② | 纯数字 | 金额、日期 | `2025` `13928.95` |
| ③ | 纯英文 | 英文缩写 | `WE` `SMT` |
| ④ | 发票号 | 字母+数字混合(数字占比>50%) | `NO.25442000000553011526` |
| ⑤ | 停用词 | 全桶高频无区分力 | `支付` `招行` `报销` `本月` `深圳` |

过滤后保留有意义的词：

```
保留: ['出差', '顺丰', '快递费', '王总', '北京']
```

### Step 3: 按桶累积词频

每张凭证内同词只计一次（去重），然后按该凭证的业务桶累加：

```
费用报销桶：出差:450, 顺丰:320, 快递费:280, 机票:400, 酒店:350, ...
存货采购桶：原材料:600, 采购:550, 一批:200, 货款:180, ...
税费桶:    增值税:200, 所得税:150, 印花税:80, ...
```

存储格式 (`word_counts`)：

```json
{
  "费用报销": {"出差": 450, "顺丰": 320, "快递费": 280, ...},
  "存货采购": {"原材料": 600, "采购": 550, ...},
  ...
}
```

## 第二阶段：PMI 计算（每次学习后重新计算）

### PMI 公式

对每个 `(桶, 词)` 组合计算 PMI（点间互信息）：

```
PMI(词, 桶) = ln( P(词出现在该桶) / (P(词出现在全局) × P(该桶占比)) )
```

**具体计算**：

```
P(词在桶内)  = 该词在桶内出现次数 / 该桶凭证总数
P(词在全局)  = 该词全局总出现次数 / 全局凭证总数
P(桶占比)    = 该桶凭证总数 / 全局凭证总数
```

**举例**："顺丰"在费用报销桶的 PMI

```
费用报销桶: 5000张凭证, "顺丰"出现320次
全局: 20000张凭证, "顺丰"总共出现400次

P(顺丰|费用报销) = 320 / 5000 = 0.064
P(顺丰|全局)     = 400 / 20000 = 0.020
P(费用报销)       = 5000 / 20000 = 0.25

PMI = ln(0.064 / (0.020 × 0.25)) = ln(12.8) ≈ 2.55
```

> PMI > 0 说明这个词在费用报销桶里出现得比随机期望更多，有绑定关系。  
> PMI 越高，绑定越强。

### 准入门槛

| 条件 | 阈值 | 说明 |
|------|------|------|
| 桶凭证数 | ≥ 10 张 | 桶太小，PMI 不可靠 |
| 词出现次数 | ≥ 5 次 | 偶发词不考虑 |
| PMI 下限 | > 0.5 | PMI ≤ 0.5 = 没有显著绑定 |

---

## 第三阶段：PMI → auto_score 映射

PMI 的原始值范围从 0.5 到可能 5、6 甚至更高。直接用会压倒结构分 `v·w'`。所以做分段线性压缩：

| PMI 范围 | auto_score | 含义 |
|----------|-----------|------|
| ≤ 0.5 | **0** | 不参与 |
| (0.5, 1.5] | 0 → 0.3 | 弱信号 |
| (1.5, 3.0] | 0.3 → 0.7 | 中强信号 |
| (3.0, 5.0] | 0.7 → 0.9 | 强信号 |
| > 5.0 | **1.0** | 极强信号 |

接上例："顺丰" PMI=2.55，映射后 auto_score = 0.3 + (2.55-1.5) × (0.4/1.5) ≈ **0.58**

---

## 第四阶段：跨桶排他过滤

如果同一个词在**多个桶**都通过了 PMI 门槛（PMI>0.5），说明它不专属于任何桶——**直接丢弃**。

```
"报关"在税费桶 PMI=2.1 ✓ (强特征)
"报关"在费用报销桶 PMI=1.8 ✓ (强特征)
→ 出现在2个桶 → 全部丢弃 ✗
```

```
"顺丰"在费用报销桶 PMI=4.2 ✓ (强特征)
"顺丰"在其他桶全部 PMI<0.5 ✗
→ 只出现在1个桶 → 保留 ✓
```

## 第五阶段：持久化存储

以上三步的结果写入 `_storage/global_counters.json` 的 `auto_scores` 字段：

```json
{
  "auto_scores": {
    "费用报销": {
      "顺丰": {
        "pmi": 4.21,
        "auto_score": 0.648,
        "count": 320
      },
      "出差": {
        "pmi": 3.85,
        "auto_score": 0.612,
        "count": 450
      }
    },
    "存货采购": {
      "原材料": {
        "pmi": 2.15,
        "auto_score": 0.473,
        "count": 600
      }
    }
  }
}
```

三个字段含义：

| 字段 | 含义 |
|------|------|
| `pmi` | 该词与桶的 PMI 绑定强度 |
| `auto_score` | 对 Score 公式的 `+c` 贡献值 (0~1) |
| `count` | 该词在该桶内出现的凭证数 |

---

## 第六阶段：分类时使用（下一次跑分类）

下次用户上传序时账跑分类时，系统会：

### 1. 加载记忆

从 `_storage/global_counters.json` 加载 `auto_scores`。

### 2. 对每张凭证匹配强特征词

对凭证的摘要+科目名称做 jieba 分词 → 五重过滤 → 去停用词 → 去掉已存在于手工关键词的词（避免重复加分）→ 查 auto_scores 表。

```
凭证摘要: "支付顺丰快递费NO.25442出差北京"
分词过滤: ['顺丰', '快递费', '出差']
去掉手工已覆盖: 顺丰(手工无), 快递费(手工无), 出差(手工已配) → ['顺丰', '快递费']
查表: 顺丰→费用报销+0.648, 快递费→费用报销+0.450
累加: c(费用报销) = 0.648 + 0.450 = 1.098
```

### 3. 最终得分

```
Score = v·w' + b + c + s_amount
       结构   手工  自动  金额
```

这是理论增强部分，目的就是越使用，让程序越聪明。

## 1. 金额特征

我们来记录每一次跑的序时账的金额特征。

### 1.1 金额对数化

对于每个业务桶，我们来统计其历史所有凭证的“合计金额”（借方总额）的自然对数，形成一个对数金额的列表。

然后计算：

- **对数均值** `μ_b`：这个桶的典型数量级。
- **对数标准差** `σ_b`：这个桶内金额的波动程度。

### 1.2 核心思想与案例

我们不直接比金额（5000 vs 100000），而是比“它是几位数”（数量级）。  
所以先把金额取对数（以 e 为底，`ln`），得到一个更平缓的数值。  
然后我们看这个对数值，在目标桶的历史对数分布里，属于“正常范围”还是“离群怪胎”。  
“正常”就加分，越离谱扣得越狠，用概率密度来打分。

>一个case：

#### 假设一个费用报销桶

我们从历史数据里把该桶所有凭证的合计金额都取了对数，算出来：
- **对数均值 μ** = 6.5（对应的典型金额 = e^6.5 ≈ 665 元）
- **对数标准差 σ** = 1.2

这意味着该桶大部分凭证的金额对数在 6.5±1.2 之间，也就是金额大致在  
e^(5.3)≈200 元 到 e^(7.7)≈2200 元 之间。

#### 来一张新凭证，金额 5000 元

1. 取自然对数：`ln(5000) ≈ 8.517`
2. 计算 z 值（离均值几个标准差）：  
   `z = (8.517 - 6.5) / 1.2 = 2.017 / 1.2 ≈ 1.68`
3. 这意味着 5000 元的对数比桶均值高了 1.68 个标准差。  
   虽然偏离了，但还没到离谱（通常 2 个标准差内还可以容忍）。

#### 把 z 值换成得分

假设正态分布，对数似然得分（忽略常数）可以只取平方项，我们做一个简化得分函数，便于比较：

```
s_amount = - (z^2) / 2
```

算出来：  
`z^2 = 1.68^2 ≈ 2.82`  
`s_amount = -2.82 / 2 = -1.41`

这个分数是负数，因为偏离了均值。如果是正好 665 元，z=0，得分就是 0（最高）。  
如果是极端离谱的金额（比如 100 万，对数 13.8，z ≈ 6），得分会接近 -18，严重拖后腿。

#### 对比长期资产桶

假设长期资产桶：μ=12.5（对应 e^12.5 ≈ 27 万元），σ=1.5。  
还是这张 5000 元的凭证：
- `ln(5000) = 8.517`
- `z = (8.517 - 12.5) / 1.5 = -3.983 / 1.5 ≈ -2.66`
- `s_amount = - (2.66^2)/2 ≈ -3.54`

费用桶得分 -1.41，资产桶得分 -3.54，费用桶得分更高，意味着 5000 元更像费用报销的金额量级。  
这正是我们想要的——金额特征把凭证往正确的桶推了一把。

### 1.3 z值的得分与量纲

注意：金额得分是纯惩罚项（Penalty Only）

我们设计的 Tanh 映射会将得分严格控制在 (-λ_a, 0] 之间。

即：金额极其符合历史均值时，不加分（得 0 分）；金额越偏离，扣分越多（最多扣减 λ_a 即 0.3 分）。

这样可以防止某些大众金额（如 1000 元）给所有的桶乱加分，金额特征只用于“排雷”。

同时，从案例看来，算出来的z值可能会偏高，直接以z值来计算得分，可能z值会直接主导最终结果。

这与我们最开始的想法是完全相悖的：**我们只是想要z值来辅助选择，而不是让z值变成了主导选择**

因此，在量纲上，应该要做出调整。

我们对 s_amount 做双曲正切（Tanh）截断，再乘以一个缩放系数 λ_a：

$$
s_{amount}(b) = \lambda_a \cdot \tanh\left(-\frac{z^2}{2}\right)
$$

- Tanh 将任意实数映射到 (-1, 1)，且原点附近近似线性，远离原点时快速饱和。
- z=0（金额完美匹配均值）：Tanh(0)=0，得分最高为 0。
- z=1.68（5000元在费用桶）：Tanh(-1.41) ≈ -0.89，乘以 λ_a=0.3 后 ≈ -0.27。
- z=6（极端离谱）：Tanh(-18) ≈ -1.0，乘以 0.3 后 = -0.30。
- z=±∞：得分趋近于 -0.30。

即使最极端的情况，金额特征也只扣 0.3 分，相当于一个弱关键词的加分。
正常偏离（z=1~2）扣分在 0.1~0.3，只是温柔地“推一把”。

**λ_a 初始建议值：0.3**。它精确控制了金额特征的最大影响力。
若后续觉得太弱或太强，调整这一个参数即可。

## 2. 词特征

**核心思想**：我们跑完序时账，每次就去记录，每个桶里面经常出现的keyword是什么，然后把它记录下来，作为词特征，这个词特征就是一个强keyword。

**关键问题**：**强keyword是必然来自于keyword的**

keyword是我预先确定好的，而假如有一些强keyword始终没有出现在我预先编码好的keyword里面，那程序肯定也是不会知道它的存在的，这个问题该怎么解决？

我们分为以下几步：

### 2.1 引入中文分词库Tokenization

要发现新词，程序首先得能“认字”。
摘要是一长串字符串（如：支付王总去北京出差的顺丰快递费），程序不能只拿死字典去套，必须引入中文分词库（比如 Python 里的 jieba）。
jieba 会把这句话切成：['支付', '王总', '去', '北京', '出差', '的', '顺丰', '快递费']。
只有切开了，机器才能发现硬编码字典之外的“野生词汇”。

### 2.2 让 TF-IDF 去当“侦察兵”（发现潜在的新强词）

TF（词频）： 某个词在这个业务桶（比如【费用报销桶】）里出现的次数。
例如：顺丰 在报销桶里出现了 500 次，的 出现了 10,000 次。
IDF（逆文档频率）： 这个词在所有业务桶里有多罕见。
例如：的、支付 在所有桶里都有，它是烂大街的废话，IDF 极低。
例如：顺丰 只在报销桶和个别桶出现，IDF 很高。
TF-IDF 侦察结果：
相乘之后，废话词（的、支付）被过滤掉，机器自动发现：出差、顺丰、快递费 这三个野生词汇，在【费用报销桶】里的 TF-IDF 分数爆表！

>预处理与 TF-IDF 计算粒度约定：
- 垃圾词过滤：jieba 分词后，强制过滤掉所有“纯数字（含金额/日期）”、“纯英文字母（乱码）”、以及“长度为 1 的单字”，只保留长度 ≥2的中文有意义词汇。
- Document 的定义：在计算 TF-IDF 时，将同一个业务桶内所有历史凭证的摘要拼接成一段超长文本。如果系统有 10 个业务桶，那么 TF-IDF 的语料库（Corpus）就只有 10 篇 Document。这样算出来的 IDF 才能真正代表“这个词在这个业务桶的独特性”。

### 2.3 让 PMI 去当“裁判”（计算动态偏置 +c）

TF-IDF 把“顺丰”选拔出来了，但我们该给它加多少分呢？
就像算科目相关性一样，我们算一下野生词与业务桶的绑定程度：

$$ \text{PMI}(顺丰, 费用报销桶) = \log \frac{P(顺丰 \text{ 在报销桶出现})}{P(顺丰 \text{ 在全局出现}) \cdot P(\text{报销桶在全局占比})} $$

### 2.4 计算强特征词得分

>为什么不直接用 PMI 原始值？
- PMI 的范围可能是 0.5 到 5，甚至更高，直接加上去，结构分可能只有 2，关键词分却有 5，瞬间让科目结构推理变成摆设。
- PMI 的分布还受数据量影响，不同桶的 PMI 值域可能不同，需要统一映射到可控区间。

采用**分段线性映射**，将 PMI 压缩到 [0, 1] 区间，与手工 keyword 得分同量纲：

| PMI 范围 | 自动得分 `auto_score` | 含义 |
|----------|---------------------|------|
| PMI ≤ 0.5 | 0 | 未通过认定，直接不参与 |
| 0.5 < PMI ≤ 1.5 | 线性从 0 → 0.3 | 弱信号，勉强加分 |
| 1.5 < PMI ≤ 3.0 | 线性从 0.3 → 0.7 | 中强信号，达到手工分常见区间 |
| 3.0 < PMI ≤ 5.0 | 线性从 0.7 → 0.9 | 强信号，接近满分 |
| PMI > 5.0 | 封顶 1.0 | 非常强，和“工资”同档 |

伪代码实现：
```python
def pmi_to_score(pmi):
    if pmi <= 0.5: return 0.0
    if pmi <= 1.5: return (pmi - 0.5) * 0.3
    if pmi <= 3.0: return 0.3 + (pmi - 1.5) * (0.4 / 1.5)
    if pmi <= 5.0: return 0.7 + (pmi - 3.0) * (0.1)
    return 1.0
```

另外，我们再来乘以桶级别系数 λ_auto

最终加进总分的自动词特征分 c 是该词得分的累加（不同词求和，同一词手工与自动取 max）。
可通过全局系数 λ_auto 整体控制自动词影响力，初始值 1.0，

让自动词与手工词在规则上权重相同。若后续发现自动词过于激进，降低此值即可。 


### 2.5 强特征词与keyword的关系

在现在的设置里，keyword被hit中，是+b。

我们假强特征词被hit中是+c，如果这个强特征词和keyword是重复的，那么我们这样取：

$$WorkScore = max(b,c)$$

## 3. 记忆系统总结

总结一下我们要弄的与“记忆”有关的东西：

- 通用R矩阵
- 金额特征
- 词特征

有一些要注意的点就是，不然重复去“记忆”完全一模一样的序时账，这一点可以在通用R矩阵那里进行拦截。

如果通用R矩阵都拦截了，那就顺带帮金额特征和词特征也拦截了。

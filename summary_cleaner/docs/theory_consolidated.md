# 理论设计

## 1. 构建相关性矩阵R

我们对用户传入的序时账，先获取所有的一级科目，将这些一级科目作为矩阵的行和列，构成一个方阵R。

比如这样：

|  | 生产成本 | 制造费用 | 管理费用 | 
|---|---|---|---|
| **生产成本** | 1.0 | 0.8 | 0.1 | 0.9 | 
| **制造费用** | 0.8 | 1.0 | 0.3 | 0.7 | 
| **管理费用** | 0.1 | 0.3 | 1.0 | 0.0 | 


### 1.1 相关性矩阵R的计算

这里面的数值应该怎么算？我们用PMI公式：

对于两个科目（或实体）A 和 B：

$$
\text{PMI}(A,B) = \log \frac{P(A,B)}{P(A) \cdot P(B)}
$$

其中：
- `P(A,B)` = A 和 B **在同一张凭证里共同出现**的概率（或频率）。  
- `P(A)` = A 出现的概率。  
- `P(B)` = B 出现的概率。

用频率来估计（假设总凭证数 N）：

```
P(A) = (包含A的凭证数) / N
P(B) = (包含B的凭证数) / N
P(A,B) = (同时包含A和B的凭证数) / N
```

代入：

$$
\text{PMI}(A,B) = \log \frac{N \times (同时包含A和B的凭证数)}{(包含A的凭证数) \times (包含B的凭证数)}
$$

- **PMI > 0**：正相关，两者同时出现的次数高于随机期望，会计上存在绑定关系。  
- **PMI ≈ 0**：独立，出现与否互不影响。  
- **PMI < 0**：负相关，互相排斥（比如某些互斥的费用科目）。

实际使用时，通常会 **截断负值至 0**，因为负相关在相关性传播里没有意义，只保留非负值。

举个实际数字的例子

假设有 10000 张凭证：
- 生产成本出现了 500 张 → P(生产成本)=0.05
- 制造费用出现了 400 张 → P(制造费用)=0.04
- 两者同时出现的有 300 张 → P(共生)=0.03

那么：

$$
\text{PMI} = \log \frac{0.03}{0.05 \times 0.04} = \log \frac{0.03}{0.002} = \log 15 \approx 2.71
$$

很高，说明它们强绑定。

再看制造费用和管理费用：
- 管理费用出现 2000 张 → P=0.2
- 制造费用和管理费用同时出现 100 张 → P=0.01

$$
\text{PMI} = \log \frac{0.01}{0.04 \times 0.2} = \log \frac{0.01}{0.008} = \log 1.25 \approx 0.22
$$

虽然同时出现了 100 次，但 PMI 接近 0，因为管理费用本来出现就极其频繁，这个共现基本是碰运气，并非绑定。  
这样 PMI 就成功抑制了常见科目的干扰。

还有：
PMI 计算的工程平滑处理（Laplace Smoothing）：
为了防止代码中出现分母为 0 或 Log(0) 的错误：
如果 (同时包含A和B的凭证数) == 0，则直接判定 PMI(A,B) = 0，不进行 Log 计算。

### 1.2 相关性矩阵R的继承与使用

我们的矩阵R设为两套。

#### 1.2.1 通用 $R$（底层基座：不可篡改的真理）
*   **怎么来？** 是我们经过训练计算后的，跑出上面说的“条件概率矩阵”。
*   **它的长相：** 它极其稳定。在通用 $R$ 里，`应付职工薪酬` 和 `社保/公积金` 的相关性极高；`固定资产` 和 `在建工程` 的相关性极高。
*   **作用：** 这是一个**“保底防线”**。就算是一家刚成立的新公司，序时账里一条数据都没有，只要套上这个通用 $R$，它马上就拥有了“一个拥有10年经验的初级会计”的分类能力。

#### 1.2.2. 专属 $R$（地方方言：千人千面）
*   **怎么来？** 每次实施到一家具体的分公司时，抽取这家公司最近半年或一年的历史凭证，单独跑出一个矩阵。
*   **它的长相：** 充满了个性化偏差。比如这家公司的研发部门很喜欢买设备，所以在专属 $R$ 里，`研发费用` 和 `固定资产` 的相关度会异常高。

#### 1.2.3. 融合算法：动态权重参数 $\alpha$ (Alpha)
有了两份矩阵，我们不能直接相加，我们需要一个融合公式：
$$ Final\_R = (1 - \alpha) \times 通用\_R + \alpha \times 专属\_R $$

这里，我们把 $\alpha$ 设置为20%

#### 1.2.4. 通用R怎么获得？基于大数定律！

因为我们这个项目现在是刚开始，训练数据全部都是0。

我们分为下面三步走：

>第一步：建立三个“全局计数器”**

在项目里，我们只维护三个永远在累加的数字账本（Hash Table）：

1.  **全局凭证总数 ($N_{global}$)**：天下所有流进来的凭证总行数。
2.  **全局单科目频次 ($Count_A$)**：比如 `制造费用` 在全宇宙出现了多少次，`应付职工薪酬` 出现了多少次。
3.  **全局共现频次 ($Count_{AB}$)**：比如 `制造费用` 和 `生产成本` 同时出现在同一张凭证里的总次数。

>第二步：数据的“倒水”过程（如何累积）

我们的项目刚上线，计数器全是 0。

*   **第 1 天，导入了公司 A 的序时账（10,000张凭证）：**
    程序不去算PMI，只做统计。
    *   凭证总数 + 10,000
    *   `制造费用` 出现次数 + 1,000
    *   `生产成本` 出现次数 + 800
    *   两者共现次数 + 600
*   **第 2 天，导入了公司 B 的序时账（50,000张凭证）：**
    *   凭证总数再 + 50,000（全局变 60,000）
    *   `制造费用` 次数再 + 4,000（全局变 5,000）
    *   两者共现次数再 + 3,000（全局变 3,600）
*   **以此类推，不断倒水...**

>第三步：随时“酿酒”（生成通用 $R$）**

只要你拥有了这三个全局计数器，你**随时随地**都能生成最新的“通用 $R$”。
怎么生成？就是把你这三大全局计数器里的数字，代入刚才那个 PMI 条件概率公式：

$$通用 R(制造费用, 生产成本) = \frac{全局共现次数 / 全局凭证总数}{(全局制造费用次数 / 全局总数) \times (全局生产成本次数 / 全局总数)}$$

**为什么这就是“通用的”？**
因为根据**“大数定律（Law of Large Numbers）”**，当你的水池里累计了 1,000 家公司、一亿条凭证之后：
1. 某家小公司财务把“买辣条”记入“研发费用”这种奇葩操作，在几千万次的正规研发核算面前，会被彻底稀释成 0.0001 的微小噪音。
2. 留下的那些高分值，全是全中国百万会计共同用手敲出来的、符合《企业会计准则》的**钢铁共识**。

这就是“通用”的本质：**它是海量财务行为统计学上的最大公约数。**


## 2. 构建偏好矩阵w

我们再给每个业务桶，去构建它们的对相关性矩阵R里的每个元素的偏好，比如生产制造桶，它对生产成本、制造费用、管理费用的编号值可能是[1.0,0.6,0.1]

业务桶的明细你可以详见`assets\业务桶与keyword.json`

这个偏好度，我们先硬编码。

## 3. 相关性传播w'

我们用向量w乘以矩阵R，得到 $w'$ ，这就是到经过相关性传播后的桶偏好，比如，因为制造费用和生产成本的相关性比较强，所以生产制造桶对制造费用的偏好度会上升。

我们可以以此算好每个向量w乘以矩阵R的结果，并暂存起来。

## 4. 凭证向量v

每一张凭证，我们都变成一个向量，同时，我们再来考虑**金额大小**和**清晰度**来作为权重。

核心原则：
>某个科目在这张凭证里涉及的资金越大，它在向量里的值就越大，对最终得分的拉扯就越强。
>某个会计科目本身的语义越明确，它得到的加分更多。比如，应付职工薪酬、在建工程就是语义明确的会计科目，管理费用就是语义模糊的会计科目。

### 4.1 金额权重

#### 4.1.1 确定每个科目在凭证里的“参与金额”

一张凭证，同一个科目可能有借方金额，也可能有贷方金额（比如应付职工薪酬一借一贷）。  
我们关心的不是方向，而是**这个科目总共卷入了多少资金流**。  
所以，对于科目 `i`，我们定义它的凭证内总发生额：

\[
\text{amt}_i = \text{abs}(\text{借方金额}_i) + \text{abs}(\text{贷方金额}_i)
\]

比如一张凭证里：
- 在建工程：只有借方 1,000,000 → amt = 1,000,000
- 管理费用：只有借方 10 → amt = 10

### 4.1.2 转换成向量值：避免绝对值过大，做归一化或缩放

直接放 1,000,000 和 10 进去，数值差距太大，会让矩阵运算不稳定，而且不同凭证总金额不同，无法比较。  
常见做法是**凭证内归一化**：用该科目的 amt 除以整张凭证所有科目的 amt 总和（即凭证总发生额的一半？注意复式记账总发生额是借方总额+贷方总额，我们关心的是比例）。

定义凭证的**总参与金额基数**：

\[
\text{total\_amt} = \sum_{\text{所有分录行}} \text{amt}_k
\]

（注意：这等于 借方总额 + 贷方总额，因为每行都取绝对值，合起来就等于凭证的总资金流动规模×2？不对。借方总额=贷方总额=凭证合计金额，设为 T。那么每行 amt 相加，因为借方的 amt 就是借方发生额，贷方 amt 就是贷方发生额，总和 = 借方总额 + 贷方总额 = 2T。所以 total_amt = 2T。）

然后该科目的向量值：

\[
x_i = \frac{\text{amt}_i}{\text{total\_amt}}
\]

在建工程：1,000,000 / (1,000,000 + 10) × 2? 等等，我们要精确算。

凭证合计金额 T = 1,000,010（假设借方合计=1,000,010，贷方合计=1,000,010）。  
那么：
- 在建工程 amt = 1,000,000
- 管理费用 amt = 10
- 贷方科目（假设是银行存款）amt = 1,000,010

total_amt = 1,000,000 + 10 + 1,000,010 = 2,000,020

x_在建 = 1,000,000 / 2,000,020 ≈ 0.49999  
x_管理费用 = 10 / 2,000,020 ≈ 0.000005  
x_银行存款 = 1,000,010 / 2,000,020 ≈ 0.500005

这样，在建工程和银行存款主导，管理费用几乎可以忽略。

### 4.2 清晰度权重

我们构建一个清晰度的表格，可以是这样的：

| 科目类型 | 包含的一级科目（举例） | 清晰度系数 $C_i$ | 逻辑释义 |
| :--- | :--- | :--- | :--- |
| **T0：绝对灵魂（极其清晰）** | `应付职工薪酬`, `固定资产`, `在建工程`, `无形资产` | **1.2 ~ 1.5** | 自带强业务属性，只要出现，就是主角。 |
| **T1：标准业务（比较清晰）** | `管理费用`, `销售费用`, `主营业务收入/成本`, `研发费用` | **1.0** | 正常的业务承载科目，不放大也不缩小。 |
| **T2：垃圾桶/过渡（模糊）** | `其他应收款`, `其他应付款`, `营业外收支` | **0.2 ~ 0.3** | 表达极不清晰，哪怕金额很大，也要压制它的权重。 |
| **T3：资金/管道（无业务含义）** | `银行存款`, `库存现金`, `应交税费` | **0.0** | 纯粹的结算手段或副产物，彻底屏蔽。 |

在算金额时，我们再来乘以一个$C_i$即可。

每一个一级科目最好都建立一个清晰度，我给你准备了一级科目明细表，可详见`assets\一级科目明细.md`


## 5. keyword的设计

到这里，我们还没有用到keyword，我们把keyword当做感知机里的“+b”，这个b可以直接硬编码，就是keyword对桶加多少分，同时对某些桶扣多少分。比如可以维护一张关键词偏置表，这里的得分我们直接硬编码，比如：

| 关键词 | 生产制造桶 | 费用报销桶 | 职工薪酬桶 |
|--------|----------------|----------------|----------------|
| 领料   | +0.5           | 0              | 0              |
| 退料   | +0.5           | 0              | 0              |
| 报销   | -0.3           | +0.6           | 0              |
| 顺风车 | 0              | +0.3           | 0              |
| 社保   | 0              | 0              | +1.0           |
| 支付货款 | 0            | 0              | 0 (归采购桶)   |

我也给你准备了keyword明细，可以详见`assets\业务桶与keyword.json`

在工程实现上，我们对这些keyword做成AC字典，首先去扫描序时账每一行的科目明细（二级科目），再去扫描序时账的摘要，看看是否包含我们要的keyword。

| 制单日期 | 凭证编号 | 凭证号 | 摘要 | 业务分类 | 科目编码 | 一级科目 | 科目名称 | 币种 | 原币金额 | 借方金额 | 贷方金额 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

就是这里的“科目名称”列和“摘要”列。

同时，keyword可以是累加的：

比如，摘要里可能写了“刘总报销滴滴顺风车及招待餐费”。这里面命中了 `报销`、`顺风车`、`餐费` 多个词。

> 1. 采用 AC 自动机（Aho-Corasick Automaton）对整张凭证的【摘要拼接 + 所有明细科目名称拼接】进行全文扫描。
> 2. 如果命中了多个 keyword，则各个业务桶的偏置 $+b$ 采取**累加机制**。
>    例如：命中“报销”和“顺风车”，那么【费用报销桶】的 $+b = 0.6 + 0.3 = 0.9$。
> 3. **去重机制：** 同一个 keyword 在同一张凭证里无论出现多少次，只加一次分（防止因为分录有 10 行，导致摘要里的同一个词被重复加 10 次分）。


## 6. 最终计算

计算公式如下：

$$ Score = (v \cdot w') + b $$

然后取得分最高的业务桶。

## 1.2 增强理论

*（以下内容来自原 `theory_boost.md`）*

这是理论增强部分，目的就是越使用，让程序越聪明。

## 1. 金额特征

我们来记录每一次跑的序时账的金额特征。

### 1.1 金额对数化

对于每个业务桶，我们来统计其历史所有凭证的“合计金额”（借方总额）的自然对数，形成一个对数金额的列表。

然后计算：

- **对数均值** `μ_b`：这个桶的典型数量级。
- **对数标准差** `σ_b`：这个桶内金额的波动程度。

### 1.2 核心思想与案例

我们不直接比金额（5000 vs 100000），而是比“它是几位数”（数量级）。  
所以先把金额取对数（以 e 为底，`ln`），得到一个更平缓的数值。  
然后我们看这个对数值，在目标桶的历史对数分布里，属于“正常范围”还是“离群怪胎”。  
“正常”就加分，越离谱扣得越狠，用概率密度来打分。

>一个case：

#### 假设一个费用报销桶

我们从历史数据里把该桶所有凭证的合计金额都取了对数，算出来：
- **对数均值 μ** = 6.5（对应的典型金额 = e^6.5 ≈ 665 元）
- **对数标准差 σ** = 1.2

这意味着该桶大部分凭证的金额对数在 6.5±1.2 之间，也就是金额大致在  
e^(5.3)≈200 元 到 e^(7.7)≈2200 元 之间。

#### 来一张新凭证，金额 5000 元

1. 取自然对数：`ln(5000) ≈ 8.517`
2. 计算 z 值（离均值几个标准差）：  
   `z = (8.517 - 6.5) / 1.2 = 2.017 / 1.2 ≈ 1.68`
3. 这意味着 5000 元的对数比桶均值高了 1.68 个标准差。  
   虽然偏离了，但还没到离谱（通常 2 个标准差内还可以容忍）。

#### 把 z 值换成得分

假设正态分布，对数似然得分（忽略常数）可以只取平方项，我们做一个简化得分函数，便于比较：

```
s_amount = - (z^2) / 2
```

算出来：  
`z^2 = 1.68^2 ≈ 2.82`  
`s_amount = -2.82 / 2 = -1.41`

这个分数是负数，因为偏离了均值。如果是正好 665 元，z=0，得分就是 0（最高）。  
如果是极端离谱的金额（比如 100 万，对数 13.8，z ≈ 6），得分会接近 -18，严重拖后腿。

#### 对比长期资产桶

假设长期资产桶：μ=12.5（对应 e^12.5 ≈ 27 万元），σ=1.5。  
还是这张 5000 元的凭证：
- `ln(5000) = 8.517`
- `z = (8.517 - 12.5) / 1.5 = -3.983 / 1.5 ≈ -2.66`
- `s_amount = - (2.66^2)/2 ≈ -3.54`

费用桶得分 -1.41，资产桶得分 -3.54，费用桶得分更高，意味着 5000 元更像费用报销的金额量级。  
这正是我们想要的——金额特征把凭证往正确的桶推了一把。

### 1.3 z值的得分与量纲

注意：金额得分是纯惩罚项（Penalty Only）

我们设计的 Tanh 映射会将得分严格控制在 (-λ_a, 0] 之间。

即：金额极其符合历史均值时，不加分（得 0 分）；金额越偏离，扣分越多（最多扣减 λ_a 即 0.3 分）。

这样可以防止某些大众金额（如 1000 元）给所有的桶乱加分，金额特征只用于“排雷”。

同时，从案例看来，算出来的z值可能会偏高，直接以z值来计算得分，可能z值会直接主导最终结果。

这与我们最开始的想法是完全相悖的：**我们只是想要z值来辅助选择，而不是让z值变成了主导选择**

因此，在量纲上，应该要做出调整。

我们对 s_amount 做双曲正切（Tanh）截断，再乘以一个缩放系数 λ_a：

$$
s_{amount}(b) = \lambda_a \cdot \tanh\left(-\frac{z^2}{2}\right)
$$

- Tanh 将任意实数映射到 (-1, 1)，且原点附近近似线性，远离原点时快速饱和。
- z=0（金额完美匹配均值）：Tanh(0)=0，得分最高为 0。
- z=1.68（5000元在费用桶）：Tanh(-1.41) ≈ -0.89，乘以 λ_a=0.3 后 ≈ -0.27。
- z=6（极端离谱）：Tanh(-18) ≈ -1.0，乘以 0.3 后 = -0.30。
- z=±∞：得分趋近于 -0.30。

即使最极端的情况，金额特征也只扣 0.3 分，相当于一个弱关键词的加分。
正常偏离（z=1~2）扣分在 0.1~0.3，只是温柔地“推一把”。

**λ_a 初始建议值：0.3**。它精确控制了金额特征的最大影响力。
若后续觉得太弱或太强，调整这一个参数即可。

## 2. 词特征

**核心思想**：我们跑完序时账，每次就去记录，每个桶里面经常出现的keyword是什么，然后把它记录下来，作为词特征，这个词特征就是一个强keyword。

**关键问题**：**强keyword是必然来自于keyword的**

keyword是我预先确定好的，而假如有一些强keyword始终没有出现在我预先编码好的keyword里面，那程序肯定也是不会知道它的存在的，这个问题该怎么解决？

我们分为以下几步：

### 2.1 引入中文分词库Tokenization

要发现新词，程序首先得能“认字”。
摘要是一长串字符串（如：支付王总去北京出差的顺丰快递费），程序不能只拿死字典去套，必须引入中文分词库（比如 Python 里的 jieba）。
jieba 会把这句话切成：['支付', '王总', '去', '北京', '出差', '的', '顺丰', '快递费']。
只有切开了，机器才能发现硬编码字典之外的“野生词汇”。

### 2.2 让 TF-IDF 去当“侦察兵”（发现潜在的新强词）

TF（词频）： 某个词在这个业务桶（比如【费用报销桶】）里出现的次数。
例如：顺丰 在报销桶里出现了 500 次，的 出现了 10,000 次。
IDF（逆文档频率）： 这个词在所有业务桶里有多罕见。
例如：的、支付 在所有桶里都有，它是烂大街的废话，IDF 极低。
例如：顺丰 只在报销桶和个别桶出现，IDF 很高。
TF-IDF 侦察结果：
相乘之后，废话词（的、支付）被过滤掉，机器自动发现：出差、顺丰、快递费 这三个野生词汇，在【费用报销桶】里的 TF-IDF 分数爆表！

>预处理与 TF-IDF 计算粒度约定：
- 垃圾词过滤：jieba 分词后，强制过滤掉所有“纯数字（含金额/日期）”、“纯英文字母（乱码）”、以及“长度为 1 的单字”，只保留长度 ≥2的中文有意义词汇。
- Document 的定义：在计算 TF-IDF 时，将同一个业务桶内所有历史凭证的摘要拼接成一段超长文本。如果系统有 10 个业务桶，那么 TF-IDF 的语料库（Corpus）就只有 10 篇 Document。这样算出来的 IDF 才能真正代表“这个词在这个业务桶的独特性”。

### 2.3 让 PMI 去当“裁判”（计算动态偏置 +c）

TF-IDF 把“顺丰”选拔出来了，但我们该给它加多少分呢？
就像算科目相关性一样，我们算一下野生词与业务桶的绑定程度：

$$ \text{PMI}(顺丰, 费用报销桶) = \log \frac{P(顺丰 \text{ 在报销桶出现})}{P(顺丰 \text{ 在全局出现}) \cdot P(\text{报销桶在全局占比})} $$

### 2.4 计算强特征词得分

>为什么不直接用 PMI 原始值？
- PMI 的范围可能是 0.5 到 5，甚至更高，直接加上去，结构分可能只有 2，关键词分却有 5，瞬间让科目结构推理变成摆设。
- PMI 的分布还受数据量影响，不同桶的 PMI 值域可能不同，需要统一映射到可控区间。

采用**分段线性映射**，将 PMI 压缩到 [0, 1] 区间，与手工 keyword 得分同量纲：

| PMI 范围 | 自动得分 `auto_score` | 含义 |
|----------|---------------------|------|
| PMI ≤ 0.5 | 0 | 未通过认定，直接不参与 |
| 0.5 < PMI ≤ 1.5 | 线性从 0 → 0.3 | 弱信号，勉强加分 |
| 1.5 < PMI ≤ 3.0 | 线性从 0.3 → 0.7 | 中强信号，达到手工分常见区间 |
| 3.0 < PMI ≤ 5.0 | 线性从 0.7 → 0.9 | 强信号，接近满分 |
| PMI > 5.0 | 封顶 1.0 | 非常强，和“工资”同档 |

伪代码实现：
```python
def pmi_to_score(pmi):
    if pmi <= 0.5: return 0.0
    if pmi <= 1.5: return (pmi - 0.5) * 0.3
    if pmi <= 3.0: return 0.3 + (pmi - 1.5) * (0.4 / 1.5)
    if pmi <= 5.0: return 0.7 + (pmi - 3.0) * (0.1)
    return 1.0
```

另外，我们再来乘以桶级别系数 λ_auto

最终加进总分的自动词特征分 c 是该词得分的累加（不同词求和，同一词手工与自动取 max）。
可通过全局系数 λ_auto 整体控制自动词影响力，初始值 1.0，

让自动词与手工词在规则上权重相同。若后续发现自动词过于激进，降低此值即可。 


### 2.5 强特征词与keyword的关系

在现在的设置里，keyword被hit中，是+b。

我们假强特征词被hit中是+c，如果这个强特征词和keyword是重复的，那么我们这样取：

$$WorkScore = max(b,c)$$

# 核心思路

引入神经网络，进行真正的训练。

目前的程序，在一通流程跑下来，可以跑出每个业务桶的的归类结果，并且可以跑出里面有哪些会计科目、keyword

我们就在这个程序后面，接一个神经网络，让神经网络去学习，训练出一个模型。

类似于：程序跑好的结果，就是做好的饭菜，神经网络直接开吃。

## 1. 神经网络（模型）做什么？

神经网络只做一件事：**cluster**

```imagine
一个序时账的几何想象
假如，有一个10万行的序时账，它只有4列，摘要，会计科目，借方金额，贷方金额
它的几何本质：一束光，穿过了一个四维棱镜，这个四维棱镜有四个面，经过这4个面，光束发生了不同程度地偏折，偏折成了10万束不同方向的光束。
为什么偏折的这么剧烈？
因为有的面实在是坑坑洼洼，凹凸不平的，比如摘要那一面。
这个“折射”是可逆的吗？是可逆的，比如我们对序时账进行透视操作，什么列都不选，它就只有一团数字，选了一些列，它就依次展开。
我们序时账分类是在做什么？我们给这个四维棱镜再加一层更柔和的镜片，让它有序地偏折，射向不同的业务桶。
```

神经网络所要做的cluster是什么？

就是把这些散射的光束进行合并。

我们先搞定cluster，在这个目的下，模型不需要去理解业务桶的存在，它只做一件事：把它认为像的凭证合并到一起，至于合并成什么，它完全可以暂时合并为cluster1，cluster2，什么业务桶都不用管

回到我们的四维棱镜比喻，模型就是让这些散射的光束，全部都合并成几个cluster。

只要模型搞定cluster，归到哪个业务桶那就是一件简单的事。

## 2. 怎么进行训练？

这要靠我们的程序，我们的程序本身可以去帮神经网络搞cluster，程序就是会喂给神经网络，这个桶里有哪些pattern和keyword，这样，神经网络似乎就可以意识到，哪些patterns和keyword是可以聚成一个cluster的

相当于，pattern是一种聚类，比如，有1万张借：应付账款，贷：银行存款，那就压缩为1类pattern，即它是对科目组合的一种概括。

## 3. 我设计的SOP

### 场景设定：令人头疼的“办公费”

我们以制造型企业最常见的“办公费”为例。这个词是个典型的“和稀泥”词，既有行政买的，也有车间买的。

**4 张凭证（已过 Step 0 硬规则，且 T3 科目“银行存款”已被屏蔽）：**

*   **凭证 A（生产制造桶）**：借: 制造费用，贷: 银行存款。摘要：“付车间办公费”。
    *   **程序提取**：`Pattern_ID: 101 (制造费用借方,银行存款贷方)`，`Keyword: [车间, 办公费]`
*   **凭证 B（生产制造桶）**：借: 制造费用，贷: 银行存款。摘要：“买A4纸”。
    *   **程序提取**：`Pattern_ID: 101`，`Keyword: [A4纸]`
*   **凭证 C（费用报销桶）**：借: 管理费用，贷: 银行存款。摘要：“付行政办公费”。
    *   **程序提取**：`Pattern_ID: 102 (管理费用借借方，银行存款贷方)`，`Keyword: [行政, 办公费]`
*   **凭证 D（费用报销桶）**：借: 管理费用，贷: 银行存款。摘要：“买签字笔”。
    *   **程序提取**：`Pattern_ID: 102`，`Keyword: [签字笔]`

---

### 第一步：向量设计（初始化）

为了让 Bro 你看得直观，我们把维度缩小到 **4 维**（实际可能是 64 维）。
模型刚启动，给每个 Pattern 和 Keyword 随机分配 4 个小数（范围 -0.5 到 0.5）：

**Pattern 向量表：**
*   $V(P_{101})$ = `[0.2, -0.1, 0.4, 0.3]`  (代表：制造费用借)
*   $V(P_{102})$ = `[-0.3, 0.5, 0.1, -0.2]` (代表：管理费用借)

**Keyword 向量表：**
*   $V(K_{车间})$ = `[0.4, 0.2, -0.3, 0.1]`
*   $V(K_{办公费})$ = `[0.1, -0.2, 0.5, -0.4]`
*   $V(K_{A4纸})$ = `[-0.1, 0.3, 0.2, 0.4]`
*   $V(K_{行政})$ = `[-0.4, 0.1, 0.3, -0.1]`
*   $V(K_{签字笔})$ = `[0.2, -0.4, 0.1, 0.3]`

>这里范围你看下怎么设计比较好，是否有扩大？不一定一定要-0.5 到 0.5

---

### 第二步：乘法洞察（计算上下文推力）

模型不把向量加起来，而是让一张凭证里的 Pattern 和 Keyword **两两做哈达玛积（对应位相乘）**，得到推力向量。

**凭证 A 的推力计算：** $Push_A = V(P_{101}) \otimes V(K_{车间}) + V(P_{101}) \otimes V(K_{办公费})$
1. $P_{101} \times K_{车间}$ = `[0.2×0.4, -0.1×0.2, 0.4×-0.3, 0.3×0.1]` = `[0.08, -0.02, -0.12, 0.03]`
2. $P_{101} \times K_{办公费}$ = `[0.2×0.1, -0.1×-0.2, 0.4×0.5, 0.3×-0.4]` = `[0.02, 0.02, 0.20, -0.12]`
3. $Push_A$ = `[0.10, 0.00, 0.08, -0.09]` （这就是凭证 A 在 4 维空间里的坐标）

同理，模型算出凭证 B、C、D 的推力坐标：
*   $Push_B$ = `[0.01, -0.01, 0.12, 0.28]`
*   $Push_C$ = `[0.11, -0.01, 0.08, -0.09]` （巧合的是，初始化时它和 A 很近）
*   $Push_D$ = `[-0.02, 0.20, -0.01, -0.09]`

---

### 第三步：引力与斥力计算（对比学习 Triplet Loss）

此时，V2.1 程序把它的“弱监督标签”告诉模型：
A 和 B 是同一类（生产制造），C 和 D 是同一类（费用报销）。

模型需要计算它们之间的**距离**。我们用余弦相似度（越接近 1 越近，越接近 -1 越远）。

**1. 引力计算（拉近同类）**
模型计算 $Push_A$ 和 $Push_B$ 的相似度，假设算出来是 `0.15`。
模型计算 $Push_C$ 和 $Push_D$ 的相似度，假设算出来是 `-0.05`。

**2. 斥力计算（推远异类）**
模型计算 $Push_A$ 和 $Push_C$ 的相似度，假设算出来是 `0.85`（哎呀，分得太近了！）
模型计算 $Push_A$ 和 $Push_D$ 的相似度，假设算出来是 `-0.10`。

**3. 损失函数设计**
模型发现自己错得有多离谱（Loss 计算）。我们设定一个边界值 `Margin = 0.5`。
*   对于 A：它和同类 B 的距离(0.15) - 它和异类 C 的距离(0.85) + Margin(0.5) = `0.15 - 0.85 + 0.5 = -0.20`。
   因为结果小于 0，说明 A 和 C 靠得太近了，**必须惩罚！产生 Loss 误差！**

>这里，损失函数的设计也只是举个例子，不一定非要这样设计。

---

### 第四步：反向传播（模型调整向量参数）

模型拿着这个 Loss 误差，开始反向微调最底层的那些向量数字（这就是 PyTorch 干的事）。

模型的调整逻辑（几何翻译）：
1.  “凭证 A 和 C 靠太近了，我得把它们推开！”
2.  凭证 A 里有 `K_{办公费}`，凭证 C 里也有 `K_{办公费}`。如果只调 `K_{办公费}`，两边会同向移动，拉不开距离。
3.  模型发现，区分 A 和 C 的关键，在于 $V(P_{101})$ 和 $V(P_{102})$ 的差异，以及 $V(K_{车间})$ 和 $V(K_{行政})$ 的差异。
4.  于是，模型微微修改 $V(P_{101})$ 里的第 1 维数字（从 0.2 变成 0.25），同时修改 $V(P_{102})$ 的第 1 维（从 -0.3 变成 -0.35）。

**经过成百上千次迭代后，星系形成：**

模型通过不断调参，硬生生在 4 维空间里扯开了两团星云：
*   **星云 1（生产制造）**：$Push_A$ 和 $Push_B$ 的相似度变成了 `0.92`（极近）。它们俩和 $Push_C$、$Push_D$ 的相似度变成了 `-0.75`（极远）。
*   **星云 2（费用报销）**：$Push_C$ 和 $Push_D$ 的相似度变成了 `0.88`（极近）。

在这个过程中，**“办公费”这个向量变得极其依赖于它和谁相乘**。
当 $V(K_{办公费})$ 乘上调整后的 $V(P_{101})$ 时，产生的推力直奔星云 1；
当它乘上 $V(P_{102})$ 时，产生的推力直奔星云 2。
**这就是乘法洞察的威力：词语失去了绝对的归属，获得了上下文的归属。**

### 第五步：实战预测

新凭证 E 进来：借: 管理费用，贷: 银行存款。摘要：“买文件夹”。
*   **程序提取**：`Pattern_ID: 102`，`Keyword: [文件夹]`

1. V2.1 程序先跑：提取出 Pattern_102 和 Keyword_文件夹。程序用现有的加法规则算出分，把它分到了“费用报销桶”。
2. 数据落库：系统把这条记录写进历史库，标记为 [Pattern_102, 文件夹, 费用报销]。
3. V3.0 模型重训/增量学习：到了半夜（或按批次），模型开始读取新的训练数据。它看到了这条记录，发现“文件夹”这个词在向量表里不存在。
4. 动态扩容：模型自动在向量表里新增一行 V(K_文件夹)，并赋予初始向量。然后拿这条数据参与训练，调整参数，让 V(K_文件夹) 和 V(P_102) 相乘的推力靠近“费用报销”星系。

### 其他：如何设计新pattern的初始向量

假如，模型已经训练好了“制造费用、银行存款”pattern向量。

然后，出现了一个“制造费用、应交税费、银行存款”这样的pattern，模型可能没见过，它也只能像没见过keyword一样，再给pattern建一个新向量。

但是，keyword的初始向量可以随意，pattern的初始向量有必要随机吗？

我认为没有必要，因为它自己就有一个已经训练好的“制造费用、银行存款”pattern，它可以参考或者照抄，就是当pattern很像时，在会计语义上它们就是近似的。

当遇到没见过的 Pattern 时，我们不随机生成，而是去查表。
1. 新 Pattern 包含：`[制造费用(借), 银行存款(贷), 应交税费(贷)]`。
2. 我们在库里找到了老 Pattern `[制造费用(借), 银行存款(贷)]` 的向量：`[0.25, -0.15, 0.4, ...]`。
3. 我们直接把这个老向量**复制**过来，作为新 Pattern 的初始向量。

**会不会导致同质性太严重，影响训练效果？**
**绝对不会，反而会极大地加速收敛并提升鲁棒性。** 

原因如下：

在神经网络里，**初始化只是起跑线，不是终点线。**
当我们把新 Pattern 初始化为老 Pattern 的向量时，等于告诉模型：“你先假设这个新分录和普通的制造费用分录是一路货色。”

*   **情况 A（它确实是近似的）**：新分录里加了个“应交税费”，但在很多业务场景下，这就是带税的制造费用报销。因为初始向量就在“生产制造”星系附近，后续训练只要微调一下，它就稳稳地留在这个星系里，**训练效率极高**。
*   **情况 B（它其实是个不同的业务）**：假设这个组合其实不是制造费用，而是某种特殊的税费计提。在后续训练中，模型发现这个新 Pattern 和“应交税费”的 Keyword 相乘后，总是被用户纠错到“税费桶”。此时，**损失函数产生的梯度会强行把这个向量从“生产制造”星系拉向“税费”星系。**

## 问题的发现

我发现，我们不能从0开始训练神经网络，这可能会导致严重的过拟合，即模型只会背答案。

比如，我们给模型了这个训练数据，“付杭州分公司货款”，桶是“存货采购”，模型知道了，那么当模型遇到了一个“付北京分公司货款”呢？

我们训练时，因为模型是从0开始的，它压根不认识任何中文，在它眼里，“付杭州分公司货款”，桶是“存货采购”，实际上是8个“奇怪字符”等于存货采购，当遇到“付北京分公司货款”的时候，模型就会完全不认识了，相当于，它只是在背答案。

我们应该引入一个中文模型，首先要让这个模型天生就看得懂中文，不然训练很可能是白搭。

所以，我们的训练策略，**就变成了微调这个中文模型。**

## 新的训练架构

### 1. 直接输入整句摘要+引入中文模型

我们不再使用jieba分词，实测下来jieba分词的效果并不好，keyword是有的，但是很离散，比如“付杭州分公司货款”，jieba给的keyword可能是：杭州，分公司，货款，但真正的keyword只是货款。

所以，我们不用jieba分词，而是直接把整句话给模型，这个模型也不是一个彻底的傻白甜，而是一个会中文的模型。

>关于模型选择：
>我的电脑配置是：华硕天选5pro，CPU是R9，GPU是RTX4060，8GB显存
>建议选择的中文模型是：BGE-Large-zh-v1.5
>这个模型的参数量：只有 3.26 亿。加载到显存里大概只需要 1.5 GB，微调（Fine-tuning）时显存占用大概在 4GB-6GB，我的 8GB 显存跑它应该刚刚好，还能把 Batch Size 开大一点，训练极快！
>不过，如果实在不行，我们可以用它的弟弟 BGE-Base-zh-v1.5（1亿参数，显存占 0.5G）

在初期节点，这个中文模型，把每一句摘要，都映射成一个向量，叫做摘要向量

### 2. 准备训练数据

我们依旧利用程序来准备训练数据，这次我们喂给模型的数据是：[整句摘要，科目组合，被选中的桶]

这些训练数据需要经过AI和我共同review。

由于我们不需要单张凭证，有相同摘要和科目组合的，我们可以去重。

### 3. 设计一个科目组合向量

我们设计一个向量，只由0和1构成，这个向量由全部会计科目构成，初始全部是0

比如：“应付账款、银行存款”这个科目组合，应付账款、银行存款就变成1，这个向量就变成[0,0,1,1,0,0,...0]

### 4. 训练过程

#### 4.1 正向传播

机器现在还是个半吊子，它开始做题：
1. **生成摘要向量**：把“付杭州分公司设备款”扔进此时的 Embedding 模型。模型根据自己现有的认知，把它翻译成了一个 384 维的数字向量（比如 `[0.2, -1.5, 0.8...]`）。
2. **提取科目向量**：把 300 个开关组成的数组，通过一个小权重矩阵，压缩成了 64 维的数字向量。
3. **混合交叉（乘法矩阵）**：把上面两个向量拼成 448 维，送进**核心权重矩阵**。
4. **得出结论**：机器做完复杂的乘法后，大声报告：
   *“老大！我算出概率了：【存货采购】80%，【长期资产】15%，【费用报销】5%。”*

>这里为维数只是举例，未必一定要这些维数，你可以根据实际设计维度数
>这个“小权重矩阵”从哪来？
>它是我们用代码创建神经网络时，系统随机生成的（一开始里面全是一堆乱七八糟的随机小数）。随着我们喂数据给答案，反向传播算法会慢慢修改这些小数，把它变成一个有意义的矩阵。

#### 4.2 计算误差（Loss / 算总账）

系统拿出你给的标准答案（长期资产是 100%，其他是 0%）。
系统一对照：*“你个蠢货！正确答案是长期资产，你才给了 15% 的概率。存货采购你居然给了 80%！误差（Loss）极大！”*

#### 4.3 反向传播与优化（机器挨打并长记性）

这是神经网络最伟大的一步：自动求导与梯度下降。
系统顺着刚才的计算路径，**反向**找是谁犯了错，并且调整它们的参数（动它们的权重）：

1. **调整核心权重矩阵（乘法器）**：
   *“你这个矩阵，刚才看到‘应付账款’这个开关亮着，就盲目放大了【存货采购】的分数。现在我强制把这个乘数调小！下次别这么冲动！”*
2. **调整 Embedding 模型（注意力与语义重塑）**：
   系统追溯到生成“摘要向量”的 Embedding 模型：
   *“你刚才生成向量时，是不是把注意力放在了‘付’和‘款’上？给我把这俩词的权重压低！把‘设备’这个词的权重拉满！并且，在你的高维空间里，把这句话的坐标给我往【长期资产】的区域生拉硬拽！”*

#### 4.4 循环往复（Epochs）

这条数据学完了，机器稍微变聪明了一点点。接着下一条数据进场……
当 10 万条数据全部跑完（这叫一个 Epoch），机器会从头再把这 10 万条重看一遍。
通常看上 5 到 10 遍（耗时可能就个把小时），误差（Loss）就会降到最低，机器再也不会把“设备”认成“存货”了。训练结束！

### 问题 2：压缩科目开关的“小权重矩阵”是啥？为什么要压缩？

**这个“小权重矩阵”从哪来？**
它是你用代码创建神经网络时，系统**随机生成**的（一开始里面全是一堆乱七八糟的随机小数）。随着你喂数据给答案，反向传播算法会慢慢修改这些小数，把它变成一个有意义的矩阵。在 PyTorch 代码里，这玩意只要一行代码：`nn.Linear(300, 64)`。

**为啥要压缩？为啥是 64 维？**
你的直觉非常准：“维度数不能是 128 维或者其他吗？”
**完全可以！** 32、64、128、256 都可以，这在机器学习里叫**超参数（Hyperparameter）**，是你这个架构师自己定的。

之所以要压缩（降维），基于两个现实原因：
1. **去水存干（特征浓缩）**：300 个开关里，一张凭证通常只亮起 2 到 4 个，剩下 290 多个全是 0（这叫稀疏矩阵）。带着几百个 0 去做运算太浪费算力了。把它压缩到 64 维，模型会把“应付账款”和“银行存款”的组合特征，提纯成 64 个实打实的连续数字（这叫稠密向量）。
2. **权重平衡（话语权对等）**：上面 BGE 模型吐出的摘要向量，通常是 768 维。如果你的科目也是 300 维这么长，模型最后做决策时可能会被搞晕。把它压缩到 64 或 128 维，相当于告诉模型：“摘要的细节（768维）占主导，科目的底色（64维）做辅助校验。”

---

### 问题 3：矩阵乘法到底是咋操作的？（硬核干货）
类似于Excel 函数SUMPRODUCT（乘积求和）！
举个极简的例子。
假设我们的神经网络已经训练好了，现在进行“考试”。
假设简化后，我们只有 **3 个输入特征**（1 个科目开关，2 个摘要向量值）：
*   特征 1（应付账款开关）：`1`
*   特征 2（摘要里的“设备”含量）：`0.8`
*   特征 3（摘要里的“报销”含量）：`0.1`

所以，**输入的凭证向量 $X$** = `[1, 0.8, 0.1]`

假设我们要分到 **2 个桶**（长期资产、费用报销）。
我们训练好的**核心权重矩阵 $W$**，其实就是一个 2行 × 3列 的 Excel 表格：

| 权重矩阵 W | 对应特征 1 (应付账款) | 对应特征 2 (设备含量) | 对应特征 3 (报销含量) |
| :--- | :--- | :--- | :--- |
| **打分器 A (长期资产)** | `2.0` | `5.0` | `-1.0` |
| **打分器 B (费用报销)** | `-0.5` | `-2.0` | `4.0` |

*你看，这个矩阵就是 AI 学出来的“经验”：长期资产打分器非常喜欢“设备”（给了5.0的权重），讨厌“报销”（给了-1.0的惩罚）。*

**矩阵乘法开始执行：**
神经网络怎么算长期资产的分数？就是拿 **输入向量** 和 **打分器 A 的权重** 做 `SUMPRODUCT`！
*   **长期资产得分** = (1 × 2.0) + (0.8 × 5.0) + (0.1 × -1.0) 
    = 2.0 + 4.0 - 0.1 
    = **5.9 分**

神经网络怎么算费用报销的分数？拿 **输入向量** 和 **打分器 B 的权重** 做 `SUMPRODUCT`！
*   **费用报销得分** = (1 × -0.5) + (0.8 × -2.0) + (0.1 × 4.0)
    = -0.5 - 1.6 + 0.4
    = **-1.7 分**

**这就是矩阵乘法！ $Output = W \times X$**
最终结果是 `[5.9, -1.7]`。模型一看，5.9 远大于 -1.7，果断把这张凭证分给【长期资产】！

**为什么它能体现“耦合关系（化学反应）”？**
假设特征 1（应付）和特征 2（设备）分开看都不足以定案。但在矩阵的某一行里，可能存在一个隐藏的打分器，专门给“特征 1 和 特征 2 同时很高”的情况赋予极大的权重，这就是通过乘法（加权求和）把多个维度的信息给**绑定**在一起了。

如果输入变成 300 维，输出变成 20 个桶，矩阵就是 20 行 × 300 列的表格（里面有 6000 个参数），计算逻辑跟上面这个 `SUMPRODUCT` 一模一样，只是电脑在一毫秒内就算完了。

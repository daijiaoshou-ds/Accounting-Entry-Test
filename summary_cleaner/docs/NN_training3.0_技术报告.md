## 一、系统总览

### 1.1 双轨架构

系统由两条独立判断链 + 一个融合层组成：

```
序时账凭证
  │
  ├──────────────────────────────┬──────────────────────────────┐
  │  轨道一：V2.1 程序（规则+统计） │  轨道二：NN 模型（语义）        │
  │                              │                              │
  │  S_prog(b) = λ·v·w'          │  P_nn = softmax( Head(       │
  │    + max(b,c) + s + d + e    │     CLS(BGE(summary))        │
  │                              │     ⊕ Linear_64(switch) ) )  │
  │  → 程序得分（无界）            │  → 模型概率（归一化）           │
  └──────────────────────────────┴──────────────────────────────┘
                      │  融合打分（左脚踩右脚）
                      ▼
        P_final(b) = 0.2 · softmax(S_prog/T) + 0.8 · P_nn(b)
                      │
                      ▼
              最终桶 + 置信度（高/中/低）
```

### 1.2 三条执行路径

| 路径 | 条件 | 最终判定 | 置信度 |
|------|------|---------|:---:|
| **硬规则预分配** | Step 0 四条硬规则命中 | 程序写死（不走评分、不走 NN） | 高 |
| **未知科目退避** | NN 科目开关含未知科目 | 程序 100% | 低 |
| **融合** | 其余凭证（两侧桶集取交集） | $0.2 \times$ 程序 softmax $+ 0.8 \times$ NN | 按 NN 概率分档 |

### 1.3 宏观数据流

```
序时账 Excel 上传
  │
  ├─ 自动检测列名（凭证号/科目/摘要/金额/制单人）
  │
  ├─ Step 0: 硬规则预分配（四条，逐凭证检查——不参与后续评分）
  │
  ├─ Step 1: 构建公司专属 PMI 矩阵 R_company（排除预分配凭证 + 结转类科目）
  ├─ Step 2: 加载通用 R_universal → fuse（20% 当前公司 + 80% 历史全局）
  ├─ Step 3-4: 偏好向量 w → 传播 w' = w × R → L2 归一化
  ├─ Step 4b: 加载历史（金额 profiler / 自动词 / 纠错信号）
  │
  ├─ Step 5: 逐凭证两轮评分（第一轮 d=0 得原生桶 → 第二轮带 d 得程序桶）
  │     └─ 5i: NN 融合候选收集 + 批量推理 + 加权融合 → 最终桶
  │
  ├─ Step 6: 映射「业务分类」+「置信度」列
  ├─ Step 7: 更新 PMI 全局计数器（指纹去重防重复学习）
  ├─ Step 8: 学习（金额特征 + 自动词按哈希分离存储）
  │
  └─ Step 9: 自动导出 NN 训练数据 → training/unreviewed/{hash}.json
              → 置信度拆分 → AI 审核 → merge → training_data.json（唯一金标准）
              → split_records 80/20 → 微调 BGE → 4 件交付物 → 融合推理
```

## 二、程序部分（V2.1 规则引擎）

### 2.1 程序得分公式

$$\text{Score}(bucket) = \lambda_{struct} \cdot (\mathbf{v} \cdot \mathbf{w}') + \max(b, c) + \text{clamp}(s, \pm 0.05) + d + e$$

| 分量 | 符号 | 含义 | 来源 | 详见 |
|------|------|------|------|------|
| 结构分 | $\lambda_{struct} \cdot (\mathbf{v} \cdot \mathbf{w}')$ | PMI 相关性 × 桶偏好传播 | 数学 | §2.2 |
| 关键词偏置 | $\max(b, c)$ | 手工词 + 自动词取最强（同词不重复加分） | 经验 + 统计 | §2.3 |
| 金额特征 | $\text{clamp}(s, \pm 0.05)$ | 对数正态分布偏离惩罚 | 统计 | §2.4 |
| 纠错增强 | $d$ | 人类反馈 → 桶顺位加分 | 人类 | §2.5 |
| 制单人偏置 | $e$ | 模块会计偏好 | 组织 | §2.6 |

**常数速查**：

| 常数 | 值 | 作用 |
|------|-----|------|
| `LAMBDA_STRUCT` | 1.67 | 结构分放大系数 |
| `MAX_KEYWORD_BIAS` | 2.0 | 手工关键词单桶上限 |
| `MAX_AUTO_WORD_BIAS` | 2.0 | 自动词单桶上限 |
| `MAX_AMOUNT_SCORE` | 0.05 | 金额特征绝对值上限 |
| `SUBJECT_DETAIL_KEYWORD_DECAY` | 0.6 | 二级科目关键词衰减 |
| `LAMBDA_RANK` | 1.0 | 纠错顺位增强系数 |
| `TAX_DECAY` | 0.5 | 税费桶关键词衰减（税费无强锚定科目，防关键词抢占） |
| `BOOKKEEPER_PREFERRED_BONUS` | +0.5 | 专职会计偏好桶加分 |
| `BOOKKEEPER_PENALTY` | -0.1 | 专职会计对其他模块桶排斥 |
| `JACCARD_THRESHOLD` | 0.6 | 纠错信号科目指纹相似度门槛 |

### 2.2 结构分：$\lambda_{struct} \cdot (\mathbf{v} \cdot \mathbf{w}')$

#### 2.2.1 v 向量 — 凭证向量

将一张凭证的若干行分录压缩为一个科目向量：

$$amt_i = |debit_i| + |credit_i|$$

$$v_i = \frac{amt_i}{\sum amt} \times C_i$$

清晰度系数 $C_i$（科目自带业务属性的强弱）：

| 层级 | 值 | 科目举例 | 含义 |
|------|-----|---------|------|
| T0 | 1.5 | 固定资产、主营业务收入、生产成本、研发支出、递延收益等 | 业务指向极强，放大信号 |
| T1 | 1.0 | 原材料、应付账款等（默认） | 正常区分力 |
| T2 | 0.3 | 其他应收款、其他应付款、营业外收支 | 业务模糊，压低信号 |
| T3 | 0.0 | 银行存款、库存现金、其他货币资金 | 纯资金管道，彻底屏蔽 |

> **例**：凭证 `记-0397` "承兑汇票到期"，分录：
> - 应付票据 153,887（借方）+ 其他货币资金 46,166（贷方）+ 银行存款 107,721（贷方）
> - 总额 = 307,774
> - v(应付票据) = 153,887/307,774 × 1.0 = 0.5
> - v(银行存款) = 0（T3 屏蔽），v(其他货币资金) = 0（T3 屏蔽）
> - 最终 v = [应付票据: 0.5, 其余科目: 0] —— 只有一个有效分量。

#### 2.2.2 w 向量 — 桶偏好向量

每个业务桶有一个人工配置的稀疏偏好向量，标注哪些科目是该桶的"锚定科目"。权重分级的意图：1.0 = 决定性科目（出现即锁定）；0.7~0.9 = 强相关；0.4~0.6 = 中等相关；0.1~0.3 = 弱相关。

存货采购桶：

$$w_{存货采购} = \begin{cases}1.0 & \text{原材料, 在途物资, 材料采购, 材料采购过渡, 委托加工物资}\\0.8 & \text{应付票据}\\0.5 & \text{库存商品}\\0.4 & \text{周转材料, 包装物及低值易耗品, 材料成本差异}\\0.3 & \text{消耗性生物资产}\\0 & \text{其他科目}\end{cases}$$

押金保证金桶（弱锚定桶的典型）：

$$w_{押金保证金} = \begin{cases}0.4 & \text{其他应收款}\\0.3 & \text{其他应付款}\\0 & \text{其他}\end{cases}$$

#### 2.2.3 R 矩阵 — PMI 相关性矩阵

N×N 对称矩阵，$R_{ij}$ = 科目 i 和 j 在凭证中"结伴出现"的互信息。

**构建与融合**：
1. 公司专属 $R_{company}$：从当前序时账统计科目共现
2. 通用 $R_{universal}$：从 `global_counters.json` 加载历史累积共现（"水池"持续扩大）
3. 融合：$R_{final} = 0.8 \cdot R_{universal} + 0.2 \cdot R_{company}$

**PMI 公式**：

$$PMI(A, B) = \ln\frac{N \cdot count\_AB}{count\_A \cdot count\_B}$$

约束：对角线 = 1.0（自相关），负 PMI 截断为 0，上限钳制 7.0（防稀疏共现极端值），排除"本年利润"和"以前年度损益调整"。

> **例**：某公司 N=11,328，原材料出现 205 次，委托加工物资出现 133 次，共现 98 次：
> $$PMI(原材料, 委托加工物资) = \ln(11328 \times 98 / (205 \times 133)) = \ln(40.7) \approx 3.71$$
> 管理费用出现 2620 次，银行存款出现 5023 次，共现 890 次：
> $$PMI(管理费用, 银行存款) = \ln(11328 \times 890 / (2620 \times 5023)) = \ln(0.77) \approx -0.27 \to \text{截断为 0}$$

#### 2.2.4 w' 向量 — 传播后的桶偏好

$$w' = \frac{w \times R}{\|w \times R\|_2}$$

$w \times R$ 借助 PMI 把锚定科目的偏好扩散到相关科目；L2 归一化防爆炸。

**稀释效应（深度分析）**：以存货采购为例。w 有 10 个锚定科目，传播后的 raw 值：

| 科目 | w | 传播后的 raw | 来源 |
|------|-----|-----------|------|
| 半成品 | 0 | **≈ 7.0** | 纯传播：PMI(原材料,半成品)=3.8 + PMI(委托加工物资,半成品)=3.2 |
| 产成品 | 0 | **≈ 4.9** | 纯传播：PMI(原材料,产成品)=3.2 + PMI(委托加工物资,产成品)=1.7 |
| 原材料 | 1.0 | **≈ 3.9** | 自身 1.0 + 传播自委托加工物资(PMI=2.9) |
| 委托加工物资 | 1.0 | **≈ 3.9** | 自身 1.0 + 传播自原材料(PMI=2.9) |
| **应付票据** | **0.8** | **≈ 0.8** | **仅自身贡献**（本公司应付票据不与任何存货科目共现） |
| 其他 ~140 科目 | 0 | 0.01~2.0 | 间接 PMI 传播 |

L2 范数 ≈ 12，归一化后：

| 科目 | raw | w' |
|------|-----|-----|
| 半成品 | 7.0 | 0.58 |
| 产成品 | 4.9 | 0.41 |
| 原材料 | 3.9 | 0.33 |
| **应付票据** | **0.8** | **0.067** |

应付票据从 0.8 被稀释了 **~12 倍**——不是因为它不重要，而是因为**同桶的其他锚定科目通过 PMI 产生了比它大得多的信号**，这些大信号撑大范数，归一化时伤及无辜。当凭证只有应付票据一个有效分量（v=0.5）：

$$\text{结构分} = 1.67 \times 0.5 \times 0.067 \approx 0.056$$

0.056 在 0.7 级的关键词偏置面前毫无招架之力——这就是"保证金"三个字能夺桶的数学本质。

**为什么不直接去掉 L2 归一化？** 去掉后 raw(半成品)=7.0 直接参与点积，所有含半成品的凭证结构分都会极大 → 全部判为生产制造。但半成品也可能出现在销售出库场景中。PMI 传播不区分"直接业务关系"和"间接统计关联"，L2 压制高 PMI 链路的统治力，代价是低 PMI 链路被连带削弱。

**当前补偿策略**：$\lambda_{struct}=1.67$ 暴力放大结构分（非根本解法——同时放大信号和噪声）。可选的改进方向：稀疏化 w'（top-K 截断）、软阈值归一化（softmax 温度缩放）、分桶归一化、非对称传播——均需实验验证，暂未实施。**注意**：NN 融合上线后程序权重仅 20%，稀释效应的实际影响已大幅降低。

### 2.3 关键词偏置：$\max(b, c)$

#### 2.3.1 b — 手工关键词

AC 自动机（Aho-Corasick，纯 Python 实现）扫描凭证的**摘要 + 二级科目名称**（不扫一级科目——一级科目已通过结构分参与，再扫会双重计分，如"应交税费"里的"税费"）。

分数两级来源：

- **显式配置**：`KEYWORD_EXPLICIT_SCORES` 优先，支持**负分抑制**。例如 `"报销": {"日常费用": 0.6, "生产制造": -0.3}`——报销凭证不该被生产制造抢桶；`"员工借款": {"员工借款": 0.9, "借款筹资": -0.5}`——员工借款词显式压制借款筹资（防"暂借款"子串命中裸"借款"）。
- **自动生成兜底**：基础分 0.6/N（N = 该关键词出现的桶数，稀释共享词）+ 长词加成 0.2（≥4 中文字符）+ 科目名加成 0.5。

> **例**：凭证含二级科目"进项税"，不在显式配置中，且只出现在"税费"桶的 JSON 关键词列表里（N=1）：
> - 基础分 = 0.6/1 = 0.6，中文 3 字无长词加成，不是科目名
> - → $b_{税费} = 0.6$

**二级科目衰减**（×0.6）：二级科目的信号弱于摘要文本——"生产成本-工资"里的"工资"不该像摘要写"支付工资"那样强烈：

$$b = b_{summary} + b_{detail} \times 0.6$$

> **例**：凭证 `记-0062` "支付厂房水费"，科目明细含"原材料"：
> - 摘要词：水费 → $b_{summary} \approx 0$
> - 明细词：原材料（命中存货采购）→ $b_{detail} = 0.6 \times 0.6 = 0.36$（改前 0.6）
> - 存货采购的优势被削弱，日常费用有机会胜出。

**T3 科目明细过滤**：银行存款等 T3 科目的二级明细（如"招商银行保证金账户"）不再参与关键词匹配，防止银行账户名里的"保证金"污染关键词匹配。

> **例**：凭证 `记-0397` "承兑汇票到期"：

| | 改前 | 改后 |
|------|------|------|
| sub_details | ["银行承兑汇票", "保证金账户…", "招商银行龙岗支行…"] | ["银行承兑汇票"] |
| 命中关键词 | "保证金" → 押金保证金 +0.7 | 无命中 |
| 效果 | 误判为押金保证金 | 不再有保证金偏置干扰 |

**累加上限**：同一桶多个关键词命中可累加，但 `MAX_KEYWORD_BIAS = 2.0` 封顶（防"差旅+机票+酒店+滴滴"堆砌成绝对统治）。

#### 2.3.2 c — 自动词（完整生命周期）

目标：从历史分类数据中**自动发现**"野生"强特征词，无需人工配置。系统自己学会"顺丰→日常费用""承兑→存货采购"。

**Phase A: 数据采集** — jieba 分词 → 7 条规则过滤 → 桶内去重累积：

| # | 规则 | 示例（被过滤） | 原因 |
|---|------|--------------|------|
| 1 | 单字词 | "付"、"收" | 信息量太低 |
| 2 | 纯数字/日期 | "202501"、"3.14" | 无业务语义 |
| 3 | 纯英文字母 | "RMB"、"USD" | 罕见且无区分力 |
| 4 | 字母数字混合，数字占比 > 50% | "A12345678" | 发票号/单号噪音 |
| 5 | ≥ 6 字的纯数字串 | "20250115001" | 长票据号 |
| 6 | 停用词（~48 个） | "支付"、"深圳"、"有限" | 全桶高频，无区分力 |
| 7 | 同一凭证内去重 | 摘要写了两次"顺丰" | 防单凭证堆砌同一词 |

停用词分类：通用会计动词（支付/收到/转入/转出/冲销/调整/结转/计提/摊销/核销/报销/付款/收款/入账）、银行名称（招行/工行/建行/招商银行……）、通用词汇（本月/本期/合计/金额/凭证/发票/人民币/美元）、城市与公司后缀（深圳/北京/上海/广州/有限/公司/技术/科技）。

**Session 追踪**：每份序时账 = 一个 Session。每个（词, 桶）记录其出现在哪些 Session 中——用于 Tier 3 垃圾桶判断（≥5 个 Session 仍低频 → 确认无区分力）。

**Phase B: 存储架构** — 按哈希分离存储，同哈希重跑自动清除旧数据（纠错反馈能传导到自动词表）：

```
_storage/
├── auto_words/{hash}.json        ← 每份序时账的原始词频 + session 信息
├── auto_words_tier1.json         ← 全局聚合 Tier 1（高频确认词）
├── auto_words_tier2.json         ← 全局聚合 Tier 2（低频累积词）
├── auto_words_tier3.json         ← 垃圾桶日志（按 (词,桶) 去重，防重复累积）
└── word_data.json                ← 总览 + 手动删除记录
```

**Phase C: PMI 计算** — 条件 PMI（对桶大小不敏感，小众桶的强特征词不被埋没）：

$$PMI_{cond}(w, bucket) = \ln\frac{P(w \mid bucket)}{P(w) \cdot P(bucket)} = \ln\frac{cnt\_in\_bucket \times total\_vouchers^2}{n\_bucket^2 \times global\_cnt}$$

前置过滤：桶凭证数 < 10 不参与；词出现 < 3 次检查是否进垃圾桶；手工删除黑名单跳过。

**Phase D: PMI → auto_score 映射** — 分段线性：

$$auto\_score(pmi) = \begin{cases} 0 & pmi \leq 0.5 \\ (pmi - 0.5) \times 0.3 & 0.5 < pmi \leq 1.5 \\ 0.3 + (pmi - 1.5) \times \dfrac{0.4}{1.5} & 1.5 < pmi \leq 3.0 \\ 0.7 + (pmi - 3.0) \times 0.1 & 3.0 < pmi \leq 5.0 \\ 1.0 & pmi > 5.0 \end{cases}$$

```
auto_score
  1.0 ┤                                      ╱──────
      │                                   ╱
  0.9 ┤                                ╱
  0.7 ┤                          ╱
  0.3 ┤                    ╱
    0 ┼─────────────╱────────────────────────────── PMI
      0       0.5  1.5          3.0          5.0
```

| PMI 区间 | 语义 | 设计意图 |
|----------|------|---------|
| ≤ 0.5 | 词与桶几乎独立 | 直接丢弃 |
| (0.5, 1.5] | 弱关联 | 微量分数，需多词累积 |
| (1.5, 3.0] | **中等关联（大部分有效特征词）** | 斜率最大，充分区分 |
| (3.0, 5.0] | 强关联 | 斜率极低，防"完美词"权重失当 |
| > 5.0 | 饱和 | 封顶 1.0 |

**Phase E: 跨桶排他过滤** — 系统最严格的质量控制：真正的强特征词必须**唯一归属**一个桶。"顺丰"只能是日常费用，"承兑"只能是存货采购。一词多桶（如"折旧"同时在长期资产和生产制造达标）→ **全部丢弃**，这类模糊信号留给结构分和手工关键词。

**Phase F: 三层分级**：

| 层级 | 条件 | 含义 | 参与打分？ |
|------|------|------|:---:|
| Tier 1 | count ≥ 5 | 高频确认词，强特征 | ✅ |
| Tier 2 | count < 5 且 sessions < 5 | 低频词，跨 Session 累积中 | ✅ |
| Tier 3（垃圾桶） | count < 3 且 sessions ≥ 5 | 多轮始终低频 → 确认无价值 | ❌ |
| 黑名单 | 人工删除 | 用户标记"这个词分错了" | ❌ |

**Phase G: 分类时匹配** — 分词 → 过滤手工词集合（同词不重复加分）→ 查 Tier1+2 → 累加（$\lambda_{auto}=1.0$）→ 上限 2.0。

**完整算例：追踪"顺丰"的全生命周期**

数据背景：某公司 3 份序时账（3 个 Session），全局 8,000 张凭证；日常费用桶凭证数 400/450/420，"顺丰"出现 12/15/11 次。

1. **采集**：通过全部 7 条过滤 → `word_counts["日常费用"]["顺丰"] = 12/15/11`（按 Session 分离落盘）
2. **聚合**：合并 3 个哈希文件 → count=38，sessions={1,2,3}，n_bucket=1,270，total=8,000
3. **PMI**：$$P(顺丰 \mid 日常费用) = \frac{38}{1270} = 0.0299,\quad P(顺丰) = \frac{38}{8000} = 0.00475$$
   $$PMI_{cond} = \ln\frac{0.0299}{0.00475 \times 0.15875} \approx 3.68$$
   解读："顺丰"在日常费用桶中的浓度是全量凭证的约 40 倍——极强的统计信号。
4. **映射**：PMI=3.68 ∈ (3.0, 5.0] → auto_score = 0.7 + 0.681 × 0.1 ≈ **0.768**
5. **排他**："顺丰"只出现在一个桶 → ✅ 通过
6. **分级**：count=38 ≥ 5 → **Tier 1**，持久化到 `auto_words_tier1.json`
7. **使用**：新凭证"支付顺丰快递费"→ 分词过滤后剩["顺丰"] → $c_{日常费用} = 0.768$。配合手工关键词"快递"（b=0.6），max(b,c)=0.768，日常费用毫无悬念胜出。

**对比算例：被跨桶排他杀死的词——"折旧"**

| 桶 | count | P(w\|bucket) | PMI | auto_score |
|----|:-----:|:-----------:|:---:|:----------:|
| 长期资产 | 80 | 0.133 | 2.12 | 0.47 |
| 生产制造 | 120 | 0.150 | 1.87 | 0.40 |
| 管理费用 | 65 | 0.036 | 1.34 | 0.24 |

三个桶都过 PMI > 0.5 门槛 → 跨桶排他：**全部丢弃**。虽然"折旧"在长期资产和生产制造都是真实信号，但无法唯一归属时系统选择不信任——交给结构分（"累计折旧"科目偏好）处理。

**$\max(b, c)$ 的语义**：同一词同时是手工关键词和自动词 → 取较大值，不重复加分；**不同词**仍可累加（手工"差旅"0.6 + 自动"顺丰"0.77 → 1.37，上限 2.0）。

### 2.4 金额特征：$\text{clamp}(s, \pm 0.05)$

**无监督（AmountProfiler）**：每桶凭证金额近似对数正态分布：

$$z = \frac{\ln(amt) - \mu}{\sigma}, \quad s_{unsup} = 0.3 \cdot \tanh(-\frac{z^2}{2})$$

返回范围 $(-0.3, 0]$。金额越接近桶的历史均值（z→0），惩罚越小。低于 10 个样本的桶不参与（防冷启动误导）。

**有监督（纠错 EMA）**：用户纠错后，EMA 动态调整正确桶的 μ/σ：

$$\mu_{new} = 0.9 \cdot \mu_{old} + 0.1 \cdot \ln(amt)$$

$$\sigma^2_{new} = 0.9 \cdot \sigma^2_{old} + 0.1 \cdot (\ln(amt)-\mu_{old}) \cdot (\ln(amt)-\mu_{new})$$

EMA 覆盖无监督：EMA 可用时直接采用 `s = s_ema`（n < 3 的桶 EMA 不参与）。改判覆盖时按 (vid, 金额) 历史精确回滚旧桶的 EMA 贡献。

**上限钳制**：$\text{clamp}(s, \pm 0.05)$。金额在实务中模糊性高，只排雷、不主导。

> **例**：长期资产桶 μ=12.5, σ=1.8（约 27 万）。凭证金额 15 万：
> - z = (11.92 - 12.5)/1.8 = -0.32 → s = 0.3 × tanh(-0.051) ≈ -0.015（正常范围，惩罚很轻）
>
> 凭证金额 5,000 元（极小）：
> - z = (8.52 - 12.5)/1.8 = -2.21 → s = 0.3 × tanh(-2.44) ≈ -0.296 → clamp 为 **-0.05**（最大惩罚）

### 2.5 纠错增强：$d$

**信号格式**（四维联合）：

$$ctx:\{\text{科目指纹}\} + \{keyword\} + \{native\_bucket\}$$

- 科目指纹：凭证全部 T3 过滤后科目排序拼接（如 `"应交税费"`）
- keyword：jieba 从摘要 + 科目明细切出的一个词
- native_bucket：该凭证**首次纠正时的原始分类，永不改变**

**记录时**（`record_corrections_batch`）：批次内 (vid, bucket) 去重；同 vid 改判不同桶 → 撤销旧信号（含所有再确认轮次）；同 vid 同桶再确认 → 批次计数 +1；同时更新金额 EMA。

**查询时**（`compute_rank_bonus`）：取凭证科目指纹 + 关键词 + 第一轮分类桶（原生桶）→ 遍历 rank_table 匹配：原生桶精确相等 + 关键词命中 + 科目指纹 Jaccard ≥ 0.6 → $d = P(correct\_bucket) \times 1.0 \times multiplier$。

**Boost 表**：

| 纠错批数 | 乘数 |
|---------|------|
| 1 | 2.0 |
| 2 | 2.25 |
| 3+ | 2.5 |

> **例**：用户纠正凭证 `记-0001`（科目={应交税费}, 摘要含"证券", 原生桶=日常费用 → 税费）：
> - 记录信号：`ctx:应交税费+证券+日常费用 → 税费: 1`
>
> 下次遇到凭证 `记-0009`（科目={管理费用, 应交税费, 银行存款}, 摘要含"证券"）：
> - Jaccard vs `"应交税费"` = 1/2 = 50% < 60% → ❌ 不命中（±1 科目容差外的泛化被拦截）
>
> 记-0001 自身重跑：Jaccard = 1/1 = 100% + 关键词命中 + 原生桶一致 → $d_{税费} = 1.0 \times 2.0 = 2.0$

| 规则 | 判定条件 | 目标桶 |

## 三、模型部分（NN V3.0）

### 3.1 动机与架构

**动机**：从 0 训练 NN 会严重过拟合——模型不懂中文，"付杭州分公司货款"→存货采购是背答案，"付北京分公司货款"就懵。V3.0 改为**微调中文预训练模型 BGE-Large-zh-v1.5**（326M 参数，语义零成本继承），输入为「整句摘要 + 科目开关向量」，输出桶概率（CrossEntropy 分类，非聚类）。

$$\text{logits} = \text{Head}\Big( \text{CLS}\big(\text{BGE}(summary)\big) \;\oplus\; \text{Linear}_{64}(switch) \Big)$$

$$\hat{y} = \arg\max_b \; \text{softmax}(\text{logits})_b, \qquad \mathcal{L} = -\log \frac{e^{z_y}}{\sum_b e^{z_b}}$$

| 分量 | 维度 | 含义 |
|------|------|------|
| $\text{BGE}(summary)$ | 1024 | BGE-Large-zh-v1.5 对摘要整句编码，取 last_hidden_state 第 0 位（[CLS]） |
| $switch$ | 158 | 科目开关 one-hot：一级科目[方向]（`应付账款[借]`） |
| $\text{Linear}_{64}$ | 158→64 | 科目开关压缩投影（可训练，head 组） |
| $\text{Head}$ | 1088→256→17 | Linear → ReLU → Dropout(0.1) → Linear（分类头 293,329 参数） |
| $B$ | 17 | 业务桶数（金标准动态构建） |

**关键选择**：
- **科目是"开关"不是"文本"**——one-hot 而非序列输入，组合出现即业务模式；
- **摘要整句保留（弃用 jieba）**——预训练模型自带语义切分，词边界由 BERT 式 tokenizer 处理；
- **微调而非从 0 训练**——"付杭州/付北京"天然同桶。

### 3.2 训练数据管线

#### 3.2.1 buckets_v2 格式（按桶聚合，AI 按桶审核友好）

```json
{ "fingerprint": "abc123", "reviewed": false,
  "buckets": { "存货采购": [
      { "subjects": ["应付账款[借]", "银行存款[贷]"],
        "records": [{"summary": "付杭州分公司货款", "count": 3}] } ] } }
```

#### 3.2.2 提取（V2.1 Step 9 自动导出）

- 按凭证号分组，桶取组内首个「业务分类」
- 摘要 = 组内全部非空摘要**去重后空格拼接**，字符级上限 200
- 科目方向判定（按绝对值——红字凭证负金额不能被跳过）：

$$|debit| > |credit| \to \text{借};\quad \text{否则 } |credit| > 0 \to \text{贷};\quad \text{两者皆 0} \to \text{跳过该行}$$

- **硬规则桶绝不进入训练**：`HARD_RULE_BUCKETS = {其他业务, 资金内部往来, 汇兑损益}`——由程序 if 语句写死分配，无学习价值，还污染分布。（员工借款桶**参与训练**，0d 只是它的兜底路径。）

> **踩坑（NaN 的 truthy 陷阱）**：`x or 0` 无法转换 NaN（`bool(nan) == True`），导致 85% 记录只剩贷方。修复：`pd.to_numeric(errors="coerce")` + `pd.isna` 显式判断。
> **踩坑（红字凭证）**：`debit > credit` 判断方向会跳过负金额行（冲减分录），科目组合只剩一半。修复：按**绝对值**比较。

#### 3.2.3 相似摘要去重

同一业务按月重复（"付XX公司货款"），数字不同语义相同。处理流程：

1. **数字归一化**：摘要中所有数字 → `#`（日期/凭证号/金额对分类无意义）
2. **difflib SequenceMatcher** 相似度 ≥ 75% → 合并，count 累加（保留 count 最大的为幸存者）

> **算例**：`付杭州分公司货款 2025年1月` → `付#分公司货款 ####年#月`；`付杭州分公司货款 2025年2月` → 归一化后相同 → 合并为 1 条，count=2。而"付北京分公司货款"归一化后 ≠ 杭州版 → 保留两条——模型学到的是"付X分公司货款"的桶归属，这正是泛化目标。
> 实测（当前金标准）：13,404 原始 → 12,918 条（相似去重 486 条）。

#### 3.2.4 置信度主动学习

AI 审核成本高，程序先筛掉已确认的：

| 判定 | 条件（与金标准比对） | 去向 |
|------|------|------|
| **high** | subjects 完全相同 + bucket 相同 + 摘要相似度 ≥ 75%（**数字归一化后**比对） | 直接并入金标准，**AI 不读** |
| **low** | 其余 | 留在主文件 `{hash}.json` → AI 审核 |

> 数字归一化是硬要求：只差期间/年份的同类摘要（"暂估计提2024年12月厂房电费" vs "2025年1月"，原始相似度可低至 0.67）归一化后才过 75% 阈值，否则会被误判 low 白审一遍。

**AI 审核规则**（`AI_REVIEW_GUIDE.md`）：一个桶一个桶看；不属于该桶的科目组合/摘要直接删除；**只删不改、拿不准就删**（存疑样本会教坏模型，宁缺毋滥）；审完标 `reviewed: true`。

#### 3.2.5 merge 幂等与 count 语义

- `source_hashes` 字段跟踪已消费文件 → 重复运行不重复并入
- 同键（摘要+科目组合）同桶跨文件 count 累加；同键不同桶 → **分桶计数加权众数胜出**（文件内与跨文件口径一致，胜出桶的 count 只含胜方次数）
- 同指纹重导出的文件（可能带了融合/纠错升级后的新分类）**不再重复并入**（count 会翻倍），移入 `training/consumed/` 保留最新副本供人工比对
- **count 语义** = 出现频次。训练时展开为样本重复度，上限 `MAX_COUNT_EXPAND = 20`（count>20 与 =20 等价），防止单条记录膨胀失控
- 关键顺序：先读现有金标准 → 再构建合并结果（曾因顺序错误导致金标准被空数据覆盖）

### 3.4 训练方法

**三策略**：

| 策略 | 机制 | 适用 |
|------|------|------|
| full（默认） | 编码器 + 分类头全部可训练 | 8GB 显存 + batch≤4 |
| lora | peft `LoraConfig(r=16, lora_alpha=32, target=["query","value"])` + `enable_input_require_grads()` | 显存紧张，质量接近 |
| frozen | 编码器 `requires_grad=False` | 最快最省，冒烟验证 |

**参数分组**：按参数名分组——含 `encoder` → 编码器组（LR 1e-5），其余 → head 组（LR 1e-3）。LoRA 适配器参数名天然含 encoder，无需特判。

**参数定稿（踩坑后）**：

| 参数 | 值 | 踩坑记录 |
|------|-----|---------|
| `NN_ENCODER_LR` | **1e-5**（初版 2e-5） | 2e-5 时 Epoch 2 验证准确率 95.4%→87.1% 崩盘——预训练权重被大步长推离最优区域 |
| `NN_HEAD_LR` | 1e-3 | 分类头随机初始化，需快收敛 |
| LR 调度 | warmup 10% 步数 + 线性衰减 | `get_linear_schedule_with_warmup`，微调标准做法 |
| `NN_DEFAULT_EPOCHS_V3` | **8**（初版 20） | 预训练模型 1-3 轮即收敛，20 轮 17 轮白跑 |
| batch | 4 | 8GB 显存实占 ~6.5GB；3 线程并发 19GB → OOM（已加防重入锁） |
| `max_length` | 64 tokens | 压显存；摘要字符级 200 截断 |
| 早停 patience | 5 | 连续 5 轮无提升停止，best 已落盘 |
| 数据划分 | **记录级** 80/20 按桶分层 | 先切记录、再展开 count——旧版先展开再切，同一记录的展开样本同时进训练/验证集（val_acc 虚高泄漏） |

**显存三件套**：fp16 AMP（`autocast` + `GradScaler`）+ gradient checkpointing（`use_cache=False`）+ 短序列截断。8GB 笔记本 GPU（RTX 4060 Laptop）实占 ~6.5GB。

**早停为什么有效**：预训练模型已懂中文，第一轮微调即"校准到位"（分类头拟合 + 编码器轻调），之后每轮编码器继续偏离预训练最优区域 → **背训练数据**（train_loss 降、val_acc 崩）。数据量（万级）远小于模型容量（326M）时这是必然现象，早停就是保护。

**best 落盘**：仅 val_acc 提升时保存——`encoder.half().save_pretrained(fine_tuned/)`（deepcopy 副本保存，不污染训练中的原模型；LoRA 先 `merge_and_unload`）+ `.pt` 分类头（含 hidden_dim/num_subjects/num_buckets/桶映射等完整元数据）+ 两个索引 json。上一版 fine_tuned 自动备份到 `backups/fine_tuned_prev/`。

### 3.5 训练情况与结果

| 版本 | 数据 | 配置 | best val_acc | 行为 |
|------|------|------|:---:|------|
| v1 | 2005 条 / 15 桶 | LR 2e-5，无 warmup | 97.87%（Epoch 2） | 数据少，过拟合慢 |
| v2 | 13599 条 / 15 桶 | LR 2e-5，无 warmup | 95.4%（Epoch 1） | Epoch 2 崩至 87.1% |
| v3 | 13818 条 / 17 桶 | LR 1e-5 + warmup | 95.8%（Epoch 2 上升中） | 曲线健康 |
| **v4（当前）** | **12918 条 / 17 桶** | **LR 1e-5 + warmup + 早停** | **95.93%（Epoch 2）** | **2026-08-12 训练** |

当前模型元数据（`finance_classifier.pt`）：BGE-Large-zh-v1.5，best_epoch=2，num_subjects=158，num_buckets=17，分类头 293,329 参数。

**关键结论**：
- LR 1e-5 + warmup 的收益可量化：v2 的 Epoch 2 崩盘（-8.3 点）→ v3/v4 的 Epoch 2 上升
- 95.93% < 97.87% 不是退步：验证集几百条 → 数千条（题目变难），17 桶 > 15 桶（类别更多）
- **泛化验收通过**（V3.0 成败判据）：同科目组合下"付杭州分公司货款"与"付北京分公司货款"预测同一桶
- 融合端到端实测：程序误判长期资产的"付杭州分公司货款" → 融合后修正为存货采购

**分桶质量报告**：报告中的分桶准确率/混淆矩阵取自 **best 落盘那一轮**的指标快照（而非末轮模型——早停时两者不是同一个模型）。

### 3.6 训练工程（生产可靠性）

| 机制 | 作用 |
|------|------|
| 后台线程 + `training_progress.json` | 训练不阻塞页面，每轮写进度（loss/acc/时间），前端 `st.fragment(run_every=2.0)` 实时刷新 |
| 防重入锁 `_TRAIN_LOCK` | 任何时刻仅一个训练线程（3 线程并发 OOM 事故后新增） |
| 显存自检 | 按模型+策略查表（Large+full 需 5.5GB / Base+lora 2.5GB…），可用不足直接报错而非跑几秒后 OOM |
| 秒级停止 | 每 batch 检查 stop 信号，点停止秒级生效，best 已保存 |
| 残留清理 | 进程重启后清理 running 状态的残留进度文件（防无限整页刷新） |
| 结束释放 | 训练结束 `empty_cache()`，把显存还给推理融合 |

## 四、融合打分（左脚踩右脚）

### 4.1 程序概率化：softmax + 温度 + clamp

程序输出的是无界得分 $S_{prog}(b)$，直接与模型概率加权不可控，先压平再转概率：

$$P_{prog}(b) = \frac{\exp\big(\text{clamp}(S_{prog}(b),\, -5,\, 5) \,/\, T\big)}{\sum_{b' \in \text{shared}} \exp\big(\text{clamp}(S_{prog}(b'),\, -5,\, 5) \,/\, T\big)}$$

| 常数 | 值 | 作用 |
|------|-----|------|
| `clamp` | $[-5, 5]$ | 程序真实得分上限约 5~6（关键词 2.0 + 自动词 2.0 + 纠错 2.5 + 制单人 0.5），只压极端异常分，正常区间完全不受影响 |
| `T` | **2.5** | 温度：T 越大程序概率越平缓，防"死倔" |

> **踩坑（死倔案例）**：某凭证程序得分 15 分（极端叠加），$e^{15/2.5}=403$，softmax 后程序概率≈1——0.2 的权重仍可翻转模型判断。加 clamp 后 $e^{5/2.5}=7.4$，与正常分差（约 $e^2=7.4$）同量级，程序意见被正确压回合理范围。

### 4.2 融合公式

$$P_{final}(b) = \underbrace{0.2 \cdot P_{prog}(b)}_{\text{程序 20\%}} + \underbrace{0.8 \cdot P_{nn}(b)}_{\text{模型 80\%}}, \qquad bucket^* = \arg\max_b P_{final}(b)$$

**约束**：
- 只在**两侧共有的桶**上融合：程序打分桶 18 个（20 桶 − 资金内部往来 − 汇兑损益，含其他业务兜底桶），NN 桶 17 个（不含其他业务/资金内部往来/汇兑损益），共享集通常即 NN 的全部 17 桶；
- 共享桶为空 → 退避程序 100%；
- 硬规则预分配凭证**不参与融合**（已在 Step 0 判定，置信度=高）；
- 空摘要凭证不参与融合（BGE 需要文本输入）。

> **设计细节**：程序对「其他业务」的判断（营业外/捐赠/罚款等关键词 +0.6）在融合中被忽略——该桶不在 NN 桶集中，程序 softmax 只在共享集上计算。仅当 NN 退避时程序对「其他业务」的判断才生效。这是"硬规则桶不进训练"决策的连带效应，见 §九 局限 8。

### 4.3 置信度分档

$$\text{confidence} = \begin{cases} \text{高} & P_{nn}(bucket^*) \geq 0.80 \\ \text{中} & 0.50 \leq P_{nn}(bucket^*) < 0.80 \\ \text{低} & P_{nn}(bucket^*) < 0.50 \end{cases}$$

| 情形 | 置信度 |
|------|:---:|
| 硬规则预分配（程序写死，无歧义） | 高 |
| 未知科目退避（开关失真，程序 100%） | 低 |
| 融合成功 | 按 $P_{nn}(bucket^*)$ 分档 |

### 4.4 融合算例

「付杭州分公司货款」（应付账款[借] + 银行存款[贷]）：

| 步骤 | 值 |
|------|-----|
| 程序判断 | 长期资产（应付账款无锚定词、关键词偏弱）→ $S_{prog}$ 分散 |
| 模型判断 | 存货采购 $P_{nn}=99.9\%$（金标准同类样本最多） |
| 融合 | $P_{final} = 0.2 \cdot P_{prog} + 0.8 \cdot P_{nn}$ → **存货采购** |
| 置信度 | 高（≥80%） |

这正是"左脚踩右脚"：**程序用规则纠模型的冷启动错误，模型用语义纠程序的规则盲区**。

### 4.5 融合模式总结

| 模式 | 触发 | 输出 |
|------|------|------|
| 硬规则预分配 | Step 0 命中 | 程序桶，置信度=高 |
| 纯程序（模型未训练/加载失败） | 交付物缺失、OOM、NameError 等 | 程序桶，置信度=低 |
| 未知科目退避 | 科目开关含未知科目 | 程序桶，置信度=低 |
| 融合（20% + 80%） | 其余 | 融合桶，置信度按 NN 概率 |

## 五、推理与部署

### 5.1 4 件交付物

| # | 文件 | 说明 |
|---|------|------|
| ① | `fine_tuned/` | 微调后 BGE（fp16，~650MB，save_pretrained） |
| ② | `finance_classifier.pt` | 分类头权重 + 元数据（best_val_acc/epoch/num_subjects/num_buckets/hidden_dim/桶映射/科目索引） |
| ③ | `subject_to_index.json` | 科目开关索引（158 个） |
| ④ | `index_to_bucket.json` | 桶索引（17 个） |

**加载校验**（全部显式报错，不静默）：
- 交付物缺失 → FileNotFoundError（提示先去训练）
- `num_subjects` 与 .pt 不一致 → ValueError
- 分类头权重键缺失/多余 → ValueError（防 hidden_dim/num_subjects 不一致时带着随机权重上线）
- json 桶映射与 .pt 内嵌映射逐项比对（防"同数量不同名字"的静默映射错误）

### 5.2 未知科目处理

$$\text{switch}_i = \begin{cases} 1 & \text{科目} i \in \text{subject\_to\_index} \\ 0 & \text{未知} \end{cases}$$

未知科目开关保持 0 + 收集 `unknown_subjects`——**不扩容**（扩容破坏已训练权重）。融合侧策略：存在未知科目 → 退避程序 100%（开关失真，模型不可信），置信度=低，提示补充训练数据后重训。

> **踩坑**：输入 `[借方]`/`[贷方]` 与索引 `[借]`/`[贷]` 不匹配 → 误报 unknown。修复：`_normalize_subject()` 归一化。
> **踩坑**：融合候选科目用裸科目名（"应付账款"）→ 100% 退避、融合永不生效。修复：统一走 `extract_subjects_from_group`（带方向）。

### 5.3 推理工程

| 机制 | 说明 |
|------|------|
| 设备自动选择 | `auto`：显存空闲 ≥2.5GB 用 GPU（fp16 模型 ~1.3GB + 批量激活余量），否则 CPU；训练与分类同开时可强制 `cpu` |
| chunk 批量 | `predict_batch_full(chunk_size=64)`：万级凭证不能一次 forward（实测单次全量 5.5GB 分配失败 OOM），64 条 × 64 tokens 激活 ~200MB |
| 懒加载 | V2.1 classify 首次调用才加载模型；加载失败静默降级纯程序模式（只警告一次） |
| 摘要口径 | 融合输入的摘要 = 组内全部非空摘要去重拼接（≤200 字符），与训练口径一致（首行摘要会与训练分布不一致） |

## 六、纠错回路全流程

```
用户下载纠错表（Excel）→ 修改"纠错分类"列 → 上传
  │
  ├─ 解析纠错表
  │     ├─ 读取"凭证号""当前分类""程序原生桶""纠错分类"列
  │     │   （程序原生桶 = 第一轮无纠错 d 的程序桶，与查询侧 original_bucket 口径一致）
  │     ├─ 跳过纠错分类 == 当前分类的行
  │     ├─ 从 original_df 反查: summary, subjects, subject_details, amount
  │     └─ T3 过滤 subject_details
  │
  ├─ CorrectionManager.record_corrections_batch()
  │     ├─ 批次内去重: (vid, correct_bucket) 每批只计一次（页面按文件内容哈希防重，同一文件只学一次）
  │     ├─ 覆盖检测: 同 vid 改判不同桶 → 撤销旧信号（含所有再确认轮次，含本批次待写入增量）
  │     ├─ 再确认: 同 vid 同桶 → 批次计数 +1（金额 EMA 幂等，不重复累积）
  │     ├─ 金额 EMA 更新（有监督 μ/σ，按 (vid, 金额) 历史记录，改判时可精确回滚）
  │     └─ 信号写入 rank_table: "ctx:{科目指纹}+{关键词}+{原生桶}" → {correct_bucket: count}
  │
  └─ 下次分类时
        ├─ 第一轮评分（d=0）→ top_no_d（原生桶，随分类结果输出"程序原生桶"列）
        ├─ compute_rank_bonus(..., original_bucket=top_no_d)
        │     └─ 遍历 rank_table → Jaccard ≥ 0.6 → d = P × multiplier
        └─ 第二轮评分（带 d）→ 程序桶 → 融合 → 最终桶
```

## 八、关键设计决策

| 决策 | 理由 |
|------|------|
| 双轨 + 融合而非单一模型 | 程序可解释、可纠错、冷启动可用；模型懂语义、泛化强；融合取长补短 |
| 融合权重 20/80 | 模型 95.9% 验证准确率后让模型主导；程序保留否决权（硬规则）与兜底权（退避） |
| softmax + T=2.5 + clamp | 程序得分无界，直接加权不可控；概率化后两轨同量纲 |
| 微调预训练模型而非从 0 训练 | 中文语义零成本继承 |
| 科目开关 one-hot | 科目是"开关"不是"文本" |
| 硬规则桶不进训练 | 机械性凭证无学习价值，还污染分布 |
| 置信度主动学习 | AI 只审最难部分，审核成本与数据量解耦 |
| 记录级 train/val 切分 | 防 count 展开样本跨侧泄漏（val_acc 虚高） |
| 相似去重 75% + 数字归一化 | 同类业务按月重复合并；保留"付杭州/付北京"的语义泛化样本 |
| 早停 + LR 1e-5 | 预训练模型微调的核心保护：不偏离最优区域 |
| 未知科目退避 + 不扩容 | 开关失真时模型不可信；扩容破坏已训练权重 |
| 两轮评分（d=0 → d 补全） | 纠错需要原始分类才知道"纠正了什么" |
| 科目指纹全量（非逐个 acc1） | 防止单科目信号污染多科目凭证 |
| 二级科目衰减 ×0.6 | 明细信号弱于摘要，防"生产成本-工资"被职工薪酬夺桶 |
| T3 科目明细过滤 | 防银行账户名里的"保证金"污染关键词匹配 |
| L2 归一化 w' | 防高 PMI 爆炸（已知稀释信号，融合后影响变小） |
| 跨桶排他过滤自动词 | 强特征词必须唯一归属 |
| 金额上限 ±0.05 | 金额在实务中模糊性高，严格限制 |
| 指纹去重（PMI/自动词） | 同份数据重复上传不重复学习 |

## 九、已知局限

1. **类别不均衡**：头部三桶占摘要 76%，尾部 7 桶（<100 条）模型近乎随机——专项补数据是最大杠杆
2. **置信度只反映模型单方概率**：最终桶由 0.2×程序+0.8×模型共同决定，但置信度只看 $P_{nn}(bucket^*)$——模型 30% 但程序力挺时记"低"，口径与"最终答案的把握"不完全一致
3. **金标准按指纹一次性**：同哈希文件的分类改进（融合升级/纠错回路生效后）不能自动更新金标准——同指纹重导出文件移入 consumed/ 保留副本，靠人工比对（指纹可考虑纳入程序版本号）
4. **L2 归一化稀释**（程序侧）：w' 值通常只有初始 w 的 1/5~1/10，结构分偏弱（融合后程序权重仅 20%，影响变小）
5. **PMI 静态性**：通用 R 只增不减，不会"遗忘"过时共现关系
6. **NN 科目开关丢失行数权重**：set 去重后一张凭证 3 行银行存款与 1 行应付账款同为两个开关——金额权重只存在于程序侧 v 向量
7. **长摘要截断**：max_length=64 丢弃尾部信息（多为供应商/日期细节，影响有限）
8. **程序"其他业务"判断在融合中被忽略**：其他业务桶不在 NN 桶集，程序 softmax 只在共享集上计算——非结转类的营业外凭证若 NN 退避才按程序判其他业务，否则被融合进 17 桶之一（"硬规则桶不进训练"决策的连带效应）
9. **auto 数据噪声**：置信度 high 直接并入金标准的记录可能残留程序错误标签（定期抽样复审）
10. **jieba 分词**：财务术语依赖词库，"材料采购过渡"等需人工补充

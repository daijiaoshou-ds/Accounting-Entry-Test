# 理论设计

## 1. 构建相关性矩阵R

我们对用户传入的序时账，先获取所有的一级科目，将这些一级科目作为矩阵的行和列，构成一个方阵R。

比如这样：

|  | 生产成本 | 制造费用 | 管理费用 | 
|---|---|---|---|
| **生产成本** | 1.0 | 0.8 | 0.1 | 0.9 | 
| **制造费用** | 0.8 | 1.0 | 0.3 | 0.7 | 
| **管理费用** | 0.1 | 0.3 | 1.0 | 0.0 | 


### 1.1 相关性矩阵R的计算

这里面的数值应该怎么算？我们用PMI公式：

对于两个科目（或实体）A 和 B：

$$
\text{PMI}(A,B) = \log \frac{P(A,B)}{P(A) \cdot P(B)}
$$

其中：
- `P(A,B)` = A 和 B **在同一张凭证里共同出现**的概率（或频率）。  
- `P(A)` = A 出现的概率。  
- `P(B)` = B 出现的概率。

用频率来估计（假设总凭证数 N）：

```
P(A) = (包含A的凭证数) / N
P(B) = (包含B的凭证数) / N
P(A,B) = (同时包含A和B的凭证数) / N
```

代入：

$$
\text{PMI}(A,B) = \log \frac{N \times (同时包含A和B的凭证数)}{(包含A的凭证数) \times (包含B的凭证数)}
$$

- **PMI > 0**：正相关，两者同时出现的次数高于随机期望，会计上存在绑定关系。  
- **PMI ≈ 0**：独立，出现与否互不影响。  
- **PMI < 0**：负相关，互相排斥（比如某些互斥的费用科目）。

实际使用时，通常会 **截断负值至 0**，因为负相关在相关性传播里没有意义，只保留非负值。

举个实际数字的例子

假设有 10000 张凭证：
- 生产成本出现了 500 张 → P(生产成本)=0.05
- 制造费用出现了 400 张 → P(制造费用)=0.04
- 两者同时出现的有 300 张 → P(共生)=0.03

那么：

$$
\text{PMI} = \log \frac{0.03}{0.05 \times 0.04} = \log \frac{0.03}{0.002} = \log 15 \approx 2.71
$$

很高，说明它们强绑定。

再看制造费用和管理费用：
- 管理费用出现 2000 张 → P=0.2
- 制造费用和管理费用同时出现 100 张 → P=0.01

$$
\text{PMI} = \log \frac{0.01}{0.04 \times 0.2} = \log \frac{0.01}{0.008} = \log 1.25 \approx 0.22
$$

虽然同时出现了 100 次，但 PMI 接近 0，因为管理费用本来出现就极其频繁，这个共现基本是碰运气，并非绑定。  
这样 PMI 就成功抑制了常见科目的干扰。

还有：
PMI 计算的工程平滑处理（Laplace Smoothing）：
为了防止代码中出现分母为 0 或 Log(0) 的错误：
如果 (同时包含A和B的凭证数) == 0，则直接判定 PMI(A,B) = 0，不进行 Log 计算。

### 1.2 相关性矩阵R的继承与使用

我们的矩阵R设为两套。

#### 1.2.1 通用 $R$（底层基座：不可篡改的真理）
*   **怎么来？** 是我们经过训练计算后的，跑出上面说的“条件概率矩阵”。
*   **它的长相：** 它极其稳定。在通用 $R$ 里，`应付职工薪酬` 和 `社保/公积金` 的相关性极高；`固定资产` 和 `在建工程` 的相关性极高。
*   **作用：** 这是一个**“保底防线”**。就算是一家刚成立的新公司，序时账里一条数据都没有，只要套上这个通用 $R$，它马上就拥有了“一个拥有10年经验的初级会计”的分类能力。

#### 1.2.2. 专属 $R$（地方方言：千人千面）
*   **怎么来？** 每次实施到一家具体的分公司时，抽取这家公司最近半年或一年的历史凭证，单独跑出一个矩阵。
*   **它的长相：** 充满了个性化偏差。比如这家公司的研发部门很喜欢买设备，所以在专属 $R$ 里，`研发费用` 和 `固定资产` 的相关度会异常高。

#### 1.2.3. 融合算法：动态权重参数 $\alpha$ (Alpha)
有了两份矩阵，我们不能直接相加，我们需要一个融合公式：
$$ Final\_R = (1 - \alpha) \times 通用\_R + \alpha \times 专属\_R $$

这里，我们把 $\alpha$ 设置为20%

#### 1.2.4. 通用R怎么获得？基于大数定律！

因为我们这个项目现在是刚开始，训练数据全部都是0。

我们分为下面三步走：

>第一步：建立三个“全局计数器”**

在项目里，我们只维护三个永远在累加的数字账本（Hash Table）：

1.  **全局凭证总数 ($N_{global}$)**：天下所有流进来的凭证总行数。
2.  **全局单科目频次 ($Count_A$)**：比如 `制造费用` 在全宇宙出现了多少次，`应付职工薪酬` 出现了多少次。
3.  **全局共现频次 ($Count_{AB}$)**：比如 `制造费用` 和 `生产成本` 同时出现在同一张凭证里的总次数。

>第二步：数据的“倒水”过程（如何累积）

我们的项目刚上线，计数器全是 0。

*   **第 1 天，导入了公司 A 的序时账（10,000张凭证）：**
    程序不去算PMI，只做统计。
    *   凭证总数 + 10,000
    *   `制造费用` 出现次数 + 1,000
    *   `生产成本` 出现次数 + 800
    *   两者共现次数 + 600
*   **第 2 天，导入了公司 B 的序时账（50,000张凭证）：**
    *   凭证总数再 + 50,000（全局变 60,000）
    *   `制造费用` 次数再 + 4,000（全局变 5,000）
    *   两者共现次数再 + 3,000（全局变 3,600）
*   **以此类推，不断倒水...**

>第三步：随时“酿酒”（生成通用 $R$）**

只要你拥有了这三个全局计数器，你**随时随地**都能生成最新的“通用 $R$”。
怎么生成？就是把你这三大全局计数器里的数字，代入刚才那个 PMI 条件概率公式：

$$通用 R(制造费用, 生产成本) = \frac{全局共现次数 / 全局凭证总数}{(全局制造费用次数 / 全局总数) \times (全局生产成本次数 / 全局总数)}$$

**为什么这就是“通用的”？**
因为根据**“大数定律（Law of Large Numbers）”**，当你的水池里累计了 1,000 家公司、一亿条凭证之后：
1. 某家小公司财务把“买辣条”记入“研发费用”这种奇葩操作，在几千万次的正规研发核算面前，会被彻底稀释成 0.0001 的微小噪音。
2. 留下的那些高分值，全是全中国百万会计共同用手敲出来的、符合《企业会计准则》的**钢铁共识**。

这就是“通用”的本质：**它是海量财务行为统计学上的最大公约数。**


## 2. 构建偏好矩阵w

我们再给每个业务桶，去构建它们的对相关性矩阵R里的每个元素的偏好，比如生产制造桶，它对生产成本、制造费用、管理费用的编号值可能是[1.0,0.6,0.1]

业务桶的明细你可以详见`assets\业务桶与keyword.json`

这个偏好度，我们先硬编码。

## 3. 相关性传播w'

我们用向量w乘以矩阵R，得到 $w'$ ，这就是到经过相关性传播后的桶偏好，比如，因为制造费用和生产成本的相关性比较强，所以生产制造桶对制造费用的偏好度会上升。

我们可以以此算好每个向量w乘以矩阵R的结果，并暂存起来。

## 4. 凭证向量v

每一张凭证，我们都变成一个向量，同时，我们再来考虑**金额大小**和**清晰度**来作为权重。

核心原则：
>某个科目在这张凭证里涉及的资金越大，它在向量里的值就越大，对最终得分的拉扯就越强。
>某个会计科目本身的语义越明确，它得到的加分更多。比如，应付职工薪酬、在建工程就是语义明确的会计科目，管理费用就是语义模糊的会计科目。

### 4.1 金额权重

#### 4.1.1 确定每个科目在凭证里的“参与金额”

一张凭证，同一个科目可能有借方金额，也可能有贷方金额（比如应付职工薪酬一借一贷）。  
我们关心的不是方向，而是**这个科目总共卷入了多少资金流**。  
所以，对于科目 `i`，我们定义它的凭证内总发生额：

\[
\text{amt}_i = \text{abs}(\text{借方金额}_i) + \text{abs}(\text{贷方金额}_i)
\]

比如一张凭证里：
- 在建工程：只有借方 1,000,000 → amt = 1,000,000
- 管理费用：只有借方 10 → amt = 10

### 4.1.2 转换成向量值：避免绝对值过大，做归一化或缩放

直接放 1,000,000 和 10 进去，数值差距太大，会让矩阵运算不稳定，而且不同凭证总金额不同，无法比较。  
常见做法是**凭证内归一化**：用该科目的 amt 除以整张凭证所有科目的 amt 总和（即凭证总发生额的一半？注意复式记账总发生额是借方总额+贷方总额，我们关心的是比例）。

定义凭证的**总参与金额基数**：

\[
\text{total\_amt} = \sum_{\text{所有分录行}} \text{amt}_k
\]

（注意：这等于 借方总额 + 贷方总额，因为每行都取绝对值，合起来就等于凭证的总资金流动规模×2？不对。借方总额=贷方总额=凭证合计金额，设为 T。那么每行 amt 相加，因为借方的 amt 就是借方发生额，贷方 amt 就是贷方发生额，总和 = 借方总额 + 贷方总额 = 2T。所以 total_amt = 2T。）

然后该科目的向量值：

\[
x_i = \frac{\text{amt}_i}{\text{total\_amt}}
\]

在建工程：1,000,000 / (1,000,000 + 10) × 2? 等等，我们要精确算。

凭证合计金额 T = 1,000,010（假设借方合计=1,000,010，贷方合计=1,000,010）。  
那么：
- 在建工程 amt = 1,000,000
- 管理费用 amt = 10
- 贷方科目（假设是银行存款）amt = 1,000,010

total_amt = 1,000,000 + 10 + 1,000,010 = 2,000,020

x_在建 = 1,000,000 / 2,000,020 ≈ 0.49999  
x_管理费用 = 10 / 2,000,020 ≈ 0.000005  
x_银行存款 = 1,000,010 / 2,000,020 ≈ 0.500005

这样，在建工程和银行存款主导，管理费用几乎可以忽略。

### 4.2 清晰度权重

我们构建一个清晰度的表格，可以是这样的：

| 科目类型 | 包含的一级科目（举例） | 清晰度系数 $C_i$ | 逻辑释义 |
| :--- | :--- | :--- | :--- |
| **T0：绝对灵魂（极其清晰）** | `应付职工薪酬`, `固定资产`, `在建工程`, `无形资产` | **1.2 ~ 1.5** | 自带强业务属性，只要出现，就是主角。 |
| **T1：标准业务（比较清晰）** | `管理费用`, `销售费用`, `主营业务收入/成本`, `研发费用` | **1.0** | 正常的业务承载科目，不放大也不缩小。 |
| **T2：垃圾桶/过渡（模糊）** | `其他应收款`, `其他应付款`, `营业外收支` | **0.2 ~ 0.3** | 表达极不清晰，哪怕金额很大，也要压制它的权重。 |
| **T3：资金/管道（无业务含义）** | `银行存款`, `库存现金`, `应交税费` | **0.0** | 纯粹的结算手段或副产物，彻底屏蔽。 |

在算金额时，我们再来乘以一个$C_i$即可。

每一个一级科目最好都建立一个清晰度，我给你准备了一级科目明细表，可详见`assets\一级科目明细.md`


## 5. keyword的设计

到这里，我们还没有用到keyword，我们把keyword当做感知机里的“+b”，这个b可以直接硬编码，就是keyword对桶加多少分，同时对某些桶扣多少分。比如可以维护一张关键词偏置表，这里的得分我们直接硬编码，比如：

| 关键词 | 生产制造桶 | 费用报销桶 | 职工薪酬桶 |
|--------|----------------|----------------|----------------|
| 领料   | +0.5           | 0              | 0              |
| 退料   | +0.5           | 0              | 0              |
| 报销   | -0.3           | +0.6           | 0              |
| 顺风车 | 0              | +0.3           | 0              |
| 社保   | 0              | 0              | +1.0           |
| 支付货款 | 0            | 0              | 0 (归采购桶)   |

我也给你准备了keyword明细，可以详见`assets\业务桶与keyword.json`

在工程实现上，我们对这些keyword做成AC字典，首先去扫描序时账每一行的科目明细（二级科目），再去扫描序时账的摘要，看看是否包含我们要的keyword。

科目明细和摘要是什么形式的？

| 制单日期 | 凭证编号 | 凭证号 | 摘要 | 业务分类 | 科目编码 | 一级科目 | 科目名称 | 币种 | 原币金额 | 借方金额 | 贷方金额 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 46051 | 记-0024 | 永拓2026年1月-记-0024号 | 2601月销售WE-S（West Coast Lighting WCL AB)货物(SZEF).WE20251231 | 销售收入 | 112201 | 应收账款 | 美元 |  |  | 473.6 |  |

就是这里的“科目名称”列和“摘要”列。

同时，keyword可以是累加的：

比如，摘要里可能写了“刘总报销滴滴顺风车及招待餐费”。这里面命中了 `报销`、`顺风车`、`餐费` 多个词。

> 1. 采用 AC 自动机（Aho-Corasick Automaton）对整张凭证的【摘要拼接 + 所有明细科目名称拼接】进行全文扫描。
> 2. 如果命中了多个 keyword，则各个业务桶的偏置 $+b$ 采取**累加机制**。
>    例如：命中“报销”和“顺风车”，那么【费用报销桶】的 $+b = 0.6 + 0.3 = 0.9$。
> 3. **去重机制：** 同一个 keyword 在同一张凭证里无论出现多少次，只加一次分（防止因为分录有 10 行，导致摘要里的同一个词被重复加 10 次分）。


## 6. 最终计算

计算公式如下：

$$ Score = (v \cdot w') + b $$

然后取得分最高的业务桶。

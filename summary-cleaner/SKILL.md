# 序时账清洗 3.0 — AI 操作手册

> **你是 AI 助手，这份手册是给你的。用户通常是会计/审计人员，不懂代码。**
> 你要替 TA 把每一步做到位并验证通过；TA 只需要回答几个问题、看一眼结果。

## 这个 skill 在做什么

把一份序时账**先切成单元、再判到 20 个标准业务桶**，并在此基础上一键编出**现金流量表**。

- 输入：序时账 Excel/CSV，至少要有 **凭证号、一级科目、借方金额、贷方金额** 四列
- 中间产物：**单元清单**（切割 + 打分的结果，交给 AI 复核）
- 输出：**一个** Excel（3 张 sheet），由程序落盘

## ⚠️ 分工铁律（先读这条，再看流程）

| 谁做 | 做什么 | 为什么 |
|---|---|---|
| **程序** | 读文件、认列名、**切成单元**、跑模型、写回凭证、编现金流、**导出 Excel**、校验 | 确定、量大、要可复现；落盘是"确定的活"，**你不写产出文件** |
| **你（AI）** | **复核单元**、把结论交回程序、把结果**讲成人话** | 要读懂自然语言、处理模糊情况，程序写不完 |

**你只做最后一公里。** 不要自己算数、不要自己拼 Excel、**不要自己写 JSON/脚本改东西**——
需要复核面就用 `units` 命令，有结论就用 `run --unit` / `run --cashflow` 交回程序。

## ⚠️ 三个层次与顺序（先读这条，别记反）

```
序时账（几千~几万张凭证）
   │
   ① 切割 ── 按「科目组合 + 摘要」去重 ──→ 单元
   │         └─ 同科目组合内，摘要**归一化（忽略数字）后相似**的并成一族，
   │            只留一个「代表」给模型（--sim 调阈值，默认 0.95）
   │                                      ★ 这一层**没有凭证号**
   ② 打分 ── 模型给**每个单元（=每族代表）**一个桶（一次推理 = 一个单元）
   ③ 复核 ── **你**看的就是这些单元
   │                                      ★ 你改的是单元，不是凭证
   ④ 写回 ── 单元 → 桶，铺到**整族**凭证   ★ 凭证号在这一步才出现
   ⑤ 现金流 ─ 程序拿具体凭证（货币资金行）→ 现金流量项目
```

**为什么是这个顺序**：你的复核结论是**写回的输入**，不是事后修正。
先改单元，再写回凭证，再算现金流 —— 所以交付物天然自洽
（业务分类与现金流量项目永远对得上）。

**为什么你复核的是单元而不是凭证**：凭证可能上万个，AI 必然复核不过来。

⚠️ **别拿凭证数估复核面**：真账摘要里塞满了单号/金额/日期/公司名，
原样文本去重几乎不起作用（实测 **11456 张凭证 → 11227 个单元**，只省 2%）。
所以切割必须算上「摘要归族」那一层，同一科目组合内：

| 口径 | 单元数（实测真账） |
|---|---|
| 原样文本（旧实现） | 11227 |
| 去数字 | 5759 |
| 去数字 + 标点空白 | 5422 |
| **再按相似度 ≥0.95 归族（默认）** | **5142** |

`units` 出参里的 `dedup` 字段会告诉你这次切掉多少，`units[].同族摘要`
告诉你这一族还包含哪些写法。**族越大，改判的影响面越大**——但也越值得改：
一族 600 张判错，改 1 个单元就全修好了。

> **归族的风险（知道就行）**：同族抄代表的作业，所以代表判错会**放大到整族**。
> 阈值默认取保守的 0.95；`--sim 1` 只并"去掉数字后完全相同"的，
> `--sim off` 退回原样文本（旧行为）。
> 硬规则单元单独成组，不会和模型单元混族。

**所以你不能这样干**：

| ❌ 错误做法 | 后果 |
|---|---|
| 手改导出 Excel 的业务分类列 | 现金流列不会重算，交付物自相矛盾；且违反"产出文件由程序落盘" |
| 自己写 PowerShell / Python 脚本去改补丁文件 | shell 转义、BOM、编码、路径处处是坑，而且改错了没人拦 |
| 用 `run --cashflow` 去"修"单元判错导致的错误项目 | 程序判定的行**拒收**，改不动；而且根子在单元，不在现金流 |
| 什么都不做，只在汇报里写"建议改判" | 交付出去的现金流量表仍然是错的 |

**正确做法**：把结论用**可重复的命令行参数**交给程序（见第 4、5 步），
别写文件、别碰 Excel。

## 第 3 步：切成单元并打分 【程序】

```cmd
%PY% -X utf8 cli.py units "序时账.xlsx"
```

**这一步只做 ①②：切割 + 打分，不写回凭证、不算现金流、不产出任何文件。**
它的出参就是你的**复核面**。

程序会做 3 件事：

| 阶段 | 做什么 |
|---|---|
| 1. ETL | 读文件、认列名 |
| 2. 硬规则 | 预分配「资金内部往来」「汇兑损益」（这几类程序直接定） |
| 3. 切割 + 打分 | 按「科目组合 + 摘要」去重成单元，每个单元问模型一次 |

**出参关键字段**：

| 字段 | 含义 |
|---|---|
| `vouchers` / `unit_count` | 多少张凭证 / 切成多少个单元（复核面大小） |
| `units[].单元号` | 如 `U137`——交给程序时的简短把手 |
| `units[].单元键` | `科目组合 :: 归一化摘要` 的规范文本，**可跨月复用** |
| `units[].科目组合` | ⚠️ 是**数组**（`["应付账款[借]", "银行存款[贷]"]`），不是字符串；当主键要先转 tuple |
| `units[].模型桶` | 模型判的桶（要复核的就是它） |
| `units[].概率` | 模型对这个桶的概率（越低越可疑——但请看下面的警告） |
| `units[].次选` | 模型拿不准时的第二/第三选择，**往往就是正确答案** |
| `units[].来源` | `模型` / `硬规则` / `兜底` |
| `units[].覆盖凭证数` | 这个单元铺到几张凭证（改它就会改这么多张） |
| `units[].同族变体数` | 这一族里有多少种不同写法（>1 说明归过族） |
| `units[].同族摘要` | 抄这个代表作业的其它写法样本（最多 5 条） |
| `dedup` | 本次切割的成绩：原样单元数 → 归族后单元数、族数、多少张凭证抄了作业 |
| `confidence_dist` | 概率分布（`=1.0` 占比 —— 判断"按概率排序还有没有用"） |
| `bucket_counts` | 桶 → 单元数（`bucket_vouchers` 是桶 → 凭证数） |
| `reuse` | 有没有用 `--reuse-units` 复用打分 |

`--limit` / `--offset` 翻页，`--bucket <桶>` 只看某个桶。

### 3.1 ⚠️ 先别读清单：4931 个单元，按概率排根本看不到错

这个模型对熟悉口径会饱和到 1.0（真账 **93.7% 是 p=1.000**，中位数 1.0000，
`次选` 全退化成 0.00）；更麻烦的是**最终确认的错判里绝大多数也是 p=1.000**。
所以"按概率从头往下看"这条路**看不到它们** —— 上一轮执行者看了概率最低的 60 条，
只改了 2~3 个。

**正确的复核姿势是三步收敛**（真账实测：约 500 个单元 = 10% 的复核面，
命中 **47 个改判 / 132 张凭证**）：

| 步 | 命令 | 看什么 | 真账规模 |
|---|---|---|---|
| ① 全局画像 | `units "序时账.xlsx" --summary` | 桶分布、概率分布、族数、最可疑 20 个 | 1 屏 |
| ② **同族离群** | `units "序时账.xlsx" --families` | 同一科目组合里**桶分布不一致**的少数派 | 约 40 族 / 200+ 条 |
| ③ 尾部小桶全量看 | `units "序时账.xlsx" --bucket 借款筹资`（逐个换桶） | 单元数少的桶整桶看完 | 约 75 个单元 |

②是**最有用的**：同一个科目组合里的凭证往往属于同一业务模式，多数派通常对、
少数派才可疑。`--families` 已经把"哪些族有少数派、少数派是哪些单元"算好了
（省得自己写脚本——上一轮的执行者就是自己写的，第一版还踩了「科目组合是数组」的坑）。

> **少数派 ≠ 判错**。真账最大的族 `应付账款[借] + 银行存款[贷]` 有 693 个单元，
> 分布是 `存货采购 579 / 长期资产 109 / 日常费用 5`，那 109 个长期资产
> **全是判对的**。先读摘要，遇到这些**正常支线**就别改：
>
> | 族里出现的桶 | 摘要特征 | 结论 |
> |---|---|---|
> | 长期资产 | 设备款 / 工程款 / 软件款 / 专利费 / 装修 | **正常**，银行付款族的支线 |
> | 押金保证金 | 押金 / 保证金 / 投标保证金 | **正常** |
> | 职工薪酬 | 公积金 / 社保 / 代扣个税 | **正常** |
> | 单位往来 | 关联方、分公司往来、代付代收 | **正常** |
> | 其它 | 语义确实对不上这一族的多数派 | 可疑 → 用 `--unit` 改判 |

### 3.2 出参太大？用 `--out-json` 落盘

```cmd
%PY% -X utf8 cli.py units "序时账.xlsx" --out-json "单元.json"
```

- 程序**自己**用 UTF-8 写一份**纯 JSON**（不带 `RESULT ` 前缀）；
  stdout 只留摘要（超过 10 条的明细数组/大映射折叠成 `{条数, 内容}`）；
- 为什么需要它：**Windows PowerShell 的 `1>` 重定向拿到的文件是 UTF-16LE**
  （0xFF 0xFE BOM），按 UTF-8 读必崩；而且 `units` 出参有 5MB 单行 JSON，不好取；
- 那份文件还能喂给 `run --reuse-units` **复用打分**（见第 5 步），迭代省一次全量推理
  —— 所以**第一条命令就加 `--out-json`**，别等改判完了才想起来。

## 第 4 步：复核单元 【你】 ← 本 skill 的核心价值

**先按第 3.1 节的三步收敛拿到要看的清单，再逐个看单元、判断「模型桶」对不对。**
依据优先级：

1. **`assets/AI_JUDGMENT_NOTES.md` 里已有的案例与规则**——最优先，那是积累下来的口径
2. **`reference/AI_REVIEW_GUIDE.md` 的 A 表**——模式 → 桶的硬规则
3. **`assets/bucket_definitions.md` 的桶定义与边界**——兜底依据

**只能选 20 个桶之一**，拿不准就标「待人工确认」，不要自己造桶名。

> ⚠️ **别把"少数派"直接判成错**：`--families` 给的少数派里，
> 长期资产（设备款/工程款/软件款/装修）、押金保证金、职工薪酬（公积金/社保）、
> 单位往来（关联方代付代收）都是**正常支线**，出现在付款/收款族里不算离群错误。
> 详见第 3.1 节的表。

### 4.1 怎么读一个单元

```
U186  模型桶=存货采购  p=0.5777  覆盖 1 张
单元键：短期借款[贷] + 银行存款[借] :: 2025/8/15-入福费廷贷款2000万
次选：  [["借款筹资", 0.4218], ["销售收入", 0.0003]]
```

- 看**科目组合 + 摘要**（这就是模型看到的全部输入，也是单元的身份）；
- 概率低 + `次选` 就看着像正确答案 → **大概率判错了**；
- 上例 `短期借款[贷] + 银行存款[借]` 是收借款，应为 `借款筹资`，
  不是 `存货采购`（模型被"费"字带偏了）。

### 4.2 把结论交回程序（**不要写文件**）

一条命令交完所有改判，`--unit` 可以重复：

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录" ^
  --unit "U186=借款筹资" ^
  --unit "U052=单位往来"
```

- 键可以是 **单元号**（`U186`，短、不易抄错），也可以是**单元键原文**：
  `--unit "短期借款[贷] + 银行存款[借] :: 2025/8/15-入福费廷贷款2000万=借款筹资"`
- `--unit` 可以写**很多次**——一次把结论交完，**别发现一个跑一次**
- 桶名必须是 **20 个业务桶之一**，非法桶名会被驳回；
  单元没找到会列进 `unknown_units`
- 程序会把生效的口径修正写成 `<输出目录>/口径修正.json` 留档。
  **它是程序写的，不是你写的**；键用的是**单元键**，所以下个月出现同样的
  「科目组合 + 摘要」时会直接命中——这就是可复用的口径修正表。
- 交完结论要重跑 `run` 才生效；**记得带 `--reuse-units`**（第 5 步），
  否则每改一次都要再等一次全量推理。

### 4.3 拿不准 / 成批出错怎么办

| 情况 | 怎么处理 |
|---|---|
| 零星几个单元判错 | 用 `--unit` 改判，汇报里说明改了什么、依据是什么 |
| **成批同类单元判错** | **不要逐个改**。说明模型不适配这家公司，汇报并建议**补训练数据后重训** |
| 某几个单元确实定不了 | 不要硬猜，标「待人工确认」并在汇报里列出来 |
| 复核面太大看不完 | 回第 3.1 节：先 `--summary`，再 `--families`，再尾部小桶；**别从概率头部硬读** |

📖 **判断优先级、高频误判对照表、出错怎么分流 → `reference/REVIEW_GUIDE.md`**
📖 **跨桶决策表 → `reference/AI_REVIEW_GUIDE.md` 的 A 表**
　（⚠️ 同文件的 B/C 表是**训练数据筛选**口径——写着"不属于任何桶 → 删除"，
　那是 1.0 时代挑训练样本的标准，**3.0 复核时不要执行**：3.0 有 `单位往来`／
　`员工借款` 这些桶，往来款、员工借款都有地方放）

## 第 5 步：写回 + 编现金流 + 导出 【程序】

复核结论作为**输入**传给 `run`：

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录" --unit "U186=借款筹资"
```

程序会做（顺序不可调换）：

| 阶段 | 做什么 |
|---|---|
| 1. 切割 + 打分 | 同第 3 步（`units` 与 `run` 用的是同一段逻辑，单元号也一致） |
| **2. 套用复核结论** | 按你交的单元改桶 —— 这是**写回的输入** |
| 3. 写回 | 单元 → 桶，铺到每一张具体凭证（`分类判定` 标 `复核改判`） |
| 4. 编现金流 | 业务桶 → 现金流量项目，方向看货币资金借贷 |
| 5. 导出 | **一个** Excel，3 张 sheet |

> ⚠️ **迭代时务必带 `--reuse-units`**：`run` 每次都会**重新跑一遍全量推理**
> （真账 CPU int8：`units` 213s + `run` 256s，改一个桶就要再花 256s）。
> 把第 3 步那份清单带上就跳过了：
>
> ```cmd
> %PY% -X utf8 cli.py units "序时账.xlsx" --out-json "单元.json"
> %PY% -X utf8 cli.py run "序时账.xlsx" --out "输出" --reuse-units "单元.json" --unit "U186=借款筹资"
> ```
>
> 键是**单元键**，所以跨月、换文件也能命中；没命中的（新出现的摘要）才问模型，
> 出参里看 `reuse.命中单元数` / `未命中凭证数`。
> `--summary` / `--families` 的 `--out-json` 文件**同样能复用**（它们是同一份打分），
> 所以最省的顺序是：第一条命令就 `units ... --summary --out-json "单元.json"`。
> ⚠️ `--sim` 要和 `units` 那次一致（不一致会在出参里给警告）。
> 实测 800 张样例：7.5s → **1.3s**（且不加载模型）。


**输出的那一个 Excel，3 张 sheet**：

| sheet | 内容 |
|---|---|
| `原始序时账` | 用户给什么就是什么，一个字不改 |
| `业务分类结果` | 原始序时账 + 业务分类 + **分类判定** + 置信度 + 现金流量项目 |
| `货币资金凭证` | 含货币资金科目的**整张**凭证 + 现金流量项目 |

`分类判定` 这列告诉你**这个桶是谁定的**，用户也靠它审计：
`模型` / `硬规则` / `复核改判`（你改的）/ `兜底`。

> **不要**给用户多个 Excel。**不要**自己生成任何产出文件。

**跑完检查这几个字段**（`run` 出参 JSON，**完整字段表，含类型**）：

| 字段 | 类型 | 期望 | 不正常说明什么 |
|---|---|---|---|
| `ok` | bool | `true` | false → 看 `error` / `stage`（`env` = 缺依赖） |
| `rows` / `vouchers` | int | 与文件相符 | 差太多 → 列认错了，回第 2 步 |
| `classified` / `unclassified` | int | `unclassified=0` | 不为 0 → 有凭证丢了标签，**别交付** |

| `unique_inputs` / `model_calls_saved` | int | — | 折叠省掉多少次推理 |

| `amount_by_bucket` | obj | — | 桶 → 金额（汇报 Top5 用） |

| `cashflow.wash_rows` | int | — | 行内一借一贷冲销（无净流量）的条数 |
| `cashflow.rows_without_item` | int | ≤ `needs_review_rows` | 大于它 → 有行既没项目也没标待复核 |
| `cashflow.amount_by_section` | obj | — | **经营/投资/筹资净额（第 6 步要汇报的大数）** |
| `cashflow.amount_by_item` / `net_cash` | obj / float | — | 按项目金额 / 净增加额 |

### 5.1 现金流"待复核"（如果有）

改完单元、算完现金流后，可能出现程序判不下来的条目，
在 `run` 出参的 **`cashflow_review.items`** 里。**先看 `原因` 分流**：

| 原因里出现 | 说明 | 你该怎么办 |
|---|---|---|
| **方向与桶不符** | 桶判错了（如"日常费用"却收到钱） | ★ **回去改单元**（`--unit`），别在现金流层补。`候选项目` 是**空的**，因为它这个方向本来就没有候选 |
| 不在裁判表里 / 同时命中多个 | 桶没错，是一级科目定不了 | 看摘要+对方科目，从 `候选项目` 里挑一个，用 `--cashflow` 交回去 |
| 不在映射表里（未分类） | 桶名不认识 | 先复核业务分类（`--unit`） |

### ★ 现金流层补丁决策表（"方向与桶不符"到底补不补）

`候选项目` 是空的，所以这一步**只能靠摘要判断**。判据就这两条
（上一轮已经踩过、也留在了积累库里，这里上移到手册，免得新会话的 AI 去翻）：

> | 摘要长什么样 | 说明 | 动作 |
> |---|---|---|
> | 含**收 / 收到 / 退回 / 退款 / 提现 / 销户转入** | 桶没错，是这笔业务方向特殊 | 直接补 **收到其他与经营活动有关的现金**（用 `--cashflow`） |
> | 写**"支付"但金额在借方**（疑似**红字冲销**） | 定不了是冲销还是真收 | 标 **待人工确认**，**不硬配项目**，在汇报里列出来 |
>
> 拿不准就选后者：**宁可留着让人看，不要硬配一个看着合理的项目。**

```json
// 第 2 类（用 --cashflow 补）
{
  "行号": 1, "凭证号": "记-001", "科目": "银行存款",
  "对方科目": ["其他权益工具"], "对方科目笔数": {"其他权益工具": 2},
  "摘要": "收到某公司投资款",
  "业务分类": "投资本金", "现金流方向": "收",
  "候选项目": ["收回投资收到的现金", "吸收投资收到的现金"],
  "原因": "业务桶「投资本金」在收现方向下有 2 个候选，…"
}
```

**你的任务**：看**摘要 + 对方科目**，从 `候选项目` 里选一个，用 `--cashflow` 交回去
（同样可以重复，同样不用写文件）：

```cmd
%PY% -X utf8 cli.py run "序时账.xlsx" --out "输出目录" ^
  --unit "U186=借款筹资" ^
  --cashflow "502=吸收投资收到的现金"
```

- 键是 `items` 里的 `行号`——**该行在序时账表体里是第几行数据**（1 开始）。
  ⚠️ 它**不等于 Excel 的工作表行号**：第 1 行是表头，所以工作表行号 = `行号` + 1。
  **原样抄 `items` 里的 `行号` 就行**，别自己去数行。
- `item` 必须是合法现金流量项目，且**方向要与该笔收/付一致**
  （例外：「汇率变动对现金的影响」是中性项目，往哪一行上补都合法）
- 只作用于「待复核」的条目；程序已判定的**不会被覆盖**
- 被采纳的条目在结果里标为 **「补丁补充」**

**「方向与桶不符」为什么会出现在正常数据里**：模型难免把个别凭证判进单向桶
（销售收入 / 存货采购 / 日常费用…）的反方向。程序**故意不**给它配一个
反方向的现金流项目——那会把"桶判错了"洗成一个看着合理的项目。
所以它来问你。**根子在业务分类**：用 `units` 找到那个单元、改桶、重跑，
现金流会自己重算对。只有当你确认"这个桶其实没错、只是这笔业务特殊"
（例如确属退款），才用 `--cashflow` 直接指定项目。

> ⚠️ **带上 `--unit` 一起跑**：`run` 每次都是从零重算的，
> 漏带 `--unit` 你的改判就白做了。

## 出错了先想清楚是哪一类

不要一上来就改数据。**按性质分流**：

| 症状 | 性质 | 动作 |
|---|---|---|
| 出参 `stage: "env"` / `missing: [...]` | **环境没装好**（不是代码 bug） | 按第 0 步装依赖；`No module named modelscope.__main__` 就换 SETUP 第二节 ① 的下载法 |
| `python -m modelscope` 报错 | modelscope 改了 CLI 入口 | 用 python API 一行命令（SETUP 第二节） |
| 出参读进来是乱码/`UnicodeDecodeError` | PowerShell `1>` 写的是 UTF-16LE | 别用重定向，加 `--out-json` |
| 字段映射错、文件格式不对 | 程序能确定的错 | 修配置重跑 |
| **同类单元成批判错** | **模型/桶定义问题** | **不要逐个改**，汇报并建议补充训练数据后重训 |
| 现金流待复核条数很多 | 桶定义粒度不够 | 见 `CASHFLOW_GUIDE.md` 第三节：该拆桶了 |
| 零星几个单元判错 | 正常误差 | 用 `--unit` 改判 + 记进积累库 |
| `--unit` 报 `unknown_units` | 单元号/单元键抄错 | 重新跑 `units` 核对；单元号只对同一份文件有效 |
| `--unit` 被驳回 | 桶名不是 20 个之一 | 看 `rejected` 里的原因 |
| `reuse.未命中凭证数` 很大 | 复用清单不完整（带过 `--limit`）或 `--sim` 不一致 | 用完整清单、两次 `--sim` 一致 |

## 边界（别越界）

- 本 skill 只做**业务分类**与**现金流映射**，不做实质性审计测试、不评价合规性。
- **不生成产出文件**——Excel 永远由程序落盘。
- **不自己写脚本/JSON 去改数据**——结论只用命令行参数交回程序。
  手写 shell 脚本改文件容易踩转义、编码、路径的坑，而且改错了没人拦。
- **不手改产出文件**——改业务分类要走 `--unit`，否则现金流列不会重算，
  交付物会自相矛盾。
- **不逐个纠错**——成规模的错误说明该重训模型，不是该逐个改单元。
- **不造桶名**——只能选 20 个桶之一，拿不准标「待人工确认」。
- **不改 `assets/cf/*.json` 来"修"个别案例**——那是业务配置，
  改它会影响所有同桶凭证。个别问题走 `--unit` / `--cashflow`。

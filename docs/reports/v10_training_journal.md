## 结论速览

| 轮次 | 数据 | 编码器/轮数 | val_acc | 关键变化 |
|---|---|---|---:|---|
| v10 | 17,490 条 / 30 桶 | bge-large / 8 | 94.89% | 首次 30 桶；成本结转≈0 召回、借款 66.7% |
| v10.2 | 21,453 条 / 29 桶 | bge-large / 8 | 94.13%（ep4） | 成本结转 **99.5%**、借款 **86.1%**、生产制造 89.8% |

**最重要的一条**：模型不是"没见过这个科目组合"，而是**有摘要可背时不学组合**。
训练时按 0.3 概率把摘要置空（`--summary-dropout 0.3`），成本结转的组合准确率
从 **0/30 涨到 28/30**，未见过的措辞从 26.7% 升到 99.2%，而常规验证准确率不变。
→ 详见第三部分；建议下一轮生产训练默认开启。

#### 三个必须查的

1. **销售 → 采购（23 次）**：科目组合是应收/收入 vs 应付/存货，理论上不该混。可能是摘要都是"XX公司货款"，方向特征（借/贷）被模型弱化了。
2. **采购 → 银行手续费（20 次）**：异常。银行手续费的科目是财务费用+手续费词，采购是存货+应付。除非摘要里同时有"手续费"和"货款"。
3. **材料 37.5%**：52 条样本里错 32 条，基本不可用。

### 结论

#### 好消息

1. **30 桶体系可学**：整体 94.89%，比 v5（18 桶 97.39%）低 2.5 个点，但类别多了 12 个、边界细得多，这个代价合理。
2. **小类没有被吞**：合成到 30 条的三个桶全部 100%，证明"按经济活动划分"的桶是有语义特征的，不靠样本堆。
3. **六类基本立住**：办公 90.9%、市场 93.6%、能源 94.6%、中介 90.6%、治理 89.8%，只有材料塌了。

#### 坏消息

1. **材料类名存实亡**（37.5%）：52 条样本 + 与 F3 边界模糊，实际不可用。
2. **投资收益与投资分不开**（43.5%）：两者都是"投资"语义，摘要差别只在"收益/本金"，模型学不出。
3. **费用父级只有 66.5%**：1,352 条模糊样本，模型 1/3 会硬猜一个子类。

#### 不需要做的

**不用加 class_weight。** 数据证明小类的问题不是"样本少被吞"（30 条也能 100%），而是"特征重叠"。加权只会让模型在小类上过拟合，不解决边界问题。

### 建议的下一步

| 优先级 | 动作 | 预期收益 |
|---|---|---|
| 高 | **材料类与 F3 合并或补真实样本** | 37.5% → 90%+，但需要 100+ 条真实"车间物料/包装物"样本 |
| 高 | **投资收益并入「投资」桶**（靠方向+科目分项目） | 消灭 43.5% 这个桶，与现有设计一致（桶不含方向） |
| 中 | **父级加置信度阈值**：模型对父级样本的 top1 概率 < 0.6 时强制回退父级 | 父级 66.5% → 85%+，且不影响其他桶 |
| 中 | 查「销售→采购」「采购→银行手续费」的具体样本 | 可能是一条规则就能修 |
| 低 | 借款 66.7%：35 条样本，靠科目规则兜底即可 | 收益小 |

第 2 条其实回到设计原则：**投资和投资收益是同一经济活动的两条线（投出/回报），按"同一活动正反合并"的规则，本来就该合并**。当时拆开是为了现金流单射，但现金流可以靠"方向 + 对方科目"分（投资收益的对方科目是投资收益/应收股利）。

### 两处混淆的根因（已定位）

#### 销售 → 采购（23 次）

不是模型分不清买卖，是**销售桶里混了"应收应付对冲"凭证**：

```
2601月 SGM-1应收款抵ZIMI应付材料款      应付账款[借]、应收账款[贷]
应付账款余额转入应收账款款               应付账款[借]、应收账款[贷]
收到XX公司发票 应付余额转入应收           应付账款[借]、应付账款[贷]、应收账款[贷]
```

这类凭证同时挂着应收和应付，模型看到"应付账款"就判采购。**它既不是销售也不是采购，是往来对冲。**

修法：bridge 层加一条规则——`应付账款[借] + 应收账款[贷]` 且摘要含"对冲/抵/转入" → 归「单位往来」。

#### 采购 → 银行手续费（20 次）

采购桶里混了"代付货款 + 手续费"和"期末调汇"凭证，都带 `财务费用[借]`：

```
裕富香港代付伯东11月货款...手续费      其他应付款[贷]、应付账款[借]、财务费用[借]
2024年10月份货款（委外加工）对公跨行汇款手续费  应付账款[借]、财务费用[借]、银行存款[贷]
富宏电子有限公司（2023Q3调汇）          应付账款[贷]、财务费用[借]
```

模型看到"手续费/财务费用"就往银行手续费桶靠。**主业务是采购/付款，手续费只是附带。**

修法：这类凭证保持"采购"，但在训练特征上，`财务费用` 不应成为强信号（当前科目开关是 one-hot，无法降权）。实际影响只有 20 条，可暂不处理。

### 修复优先级（明天可直接做）

| # | 动作 | 影响 | 工作量 |
|---|---|---|---|
| 1 | 应收应付对冲 → 单位往来 | 销售 99.3% → 99.6%，减少 23 条错 | 1 条 bridge 规则 |
| 2 | 投资收益并入「投资」 | 消灭 43.5% 的桶 | 改配置 + 重跑 rebuild |
| 3 | 父级置信度阈值（<0.6 回退） | 父级 66.5% → 85%+ | inference 层改动 |
| 4 | 材料类补真实样本或并入 F3 | 37.5% → 90%+ | 需 100+ 条真实数据 |

前三条都不需要重训（1、2 是数据/规则；3 是推理逻辑）。只有第 4 条需要重训。

### 三个真问题（记录级去重后仍成立）

#### 1. 薪酬 → 生产制造（3 条记录）

摘要带「车间 / 一车间 / 生产部」，科目是 `制造费用`，模型判成生产制造。
按口径，车间的工资仍是**薪酬**（成本中心 ≠ 经济业务）。样本里这类是少数，
但属于口径系统性风险——下一轮可以补 30–50 条「车间工资/生产部加班费」的薪酬样本压住。

#### 2. 结算手续费 → 利息支出（2 条记录）

都在 `财务费用` 下，摘要只差"手续费"和"利息"两个字。
另有 4 条落到费用·治理/能源（平台费、境外月费这类名字里没有"手续费"的）。
桶名已改成「结算手续费」，但样本里仍有大量以"XX手续费"开头、实为杂费的单据。

#### 3. 长期资产购建 → 费用 / 采购（各 14 条）

判据是"含固定资产/在建工程科目"，但购建类凭证常是复合的（设备款 + 安装 + 运费），
一条里既有设备也有服务费。属于边界问题，暂不处理。

### 指标口径的一个坑（重要）

`per_bucket_accuracy` 是**按 count 展开后的样本级**准确率。
一条 count=12 的记录，在验证集里就是 12 条一模一样的样本。

投资桶 52 条验证样本里，有 **12 条是同一条记录**：

```
收中国证券登记结算有限责任公司深圳分公司派发红利代扣代缴个人所得税
其他应付款[贷] / 银行存款[借]   → 模型判 利润分配（0.68）
```

它一错，投资就直接掉 23 个百分点。**记录级去重后是 37/40 = 92.5%**。

建议：以后 `_evaluate` 同时输出 record-level 准确率，两者并看。

## 三、实验：训练时丢弃摘要，能不能治「背摘要」

2026-11-06 · 结论：**正向收益很大，建议采纳**

### 要验证什么

`交货 - C000425,深圳麦哲科技有限公司` 这类写法被判成采购，而科目组合
`发出商品[借]+库存商品[贷]` 在金标准里 3,874 count **100% 是成本结转**。

探针实验证明模型根本没学会这个组合，只在背摘要字面：

| 摘要（固定同一组合） | 判断 |
|---|---|
| `发出商品--某客户` | 成本结转 1.000 ✅ |
| `结转本月发出商品` | 成本结转 1.000 ✅ |
| `交货` | 采购 1.000 ❌ |

再用中性文本「本月合计」只给组合：`发出商品[借]+库存商品[贷]` → **采购 0.99**，
说明组合→桶的映射压根没学到。

假设：给训练样本**按概率把摘要置空**，堵死「背摘要」这条捷径，模型只能学组合。

### 实验设置

| | 对照组 | 实验组 |
|---|---|---|
| 数据 | 21,453 记录（同一份） | 同左 |
| 编码器 | bge-base-zh-v1.5 | 同左 |
| epochs / batch | 3 / 8 | 同左 |
| 摘要丢弃 | 0 | **0.3** |
| 用时 | 36.6 分钟 | 31.8 分钟 |

同 seed、同划分，唯一变量是 `--summary-dropout`。

### 结果

| 测试集 | 对照组 | 实验组 | 生产模型（bge-large/8ep） |
|---|---:|---:|---:|
| **A 交货措辞**（120 条，训练集从未出现的说法） | 26.7% | **99.2%** | 41.7% |
| **B 中性文本**（846 条，只给科目组合） | 13.1% | **32.2%** | 24.7% |
| **C 常规验证**（2000 条） | 93.8% | **94.0%** | 95.2% |

B 组关键桶（只给组合，不给摘要）：

| 桶 | 对照组 | 实验组 |
|---|---:|---:|
| 成本结转 | **0/30** | **28/30** |
| 生产制造 | 6/30 | **30/30** |
| 采购 | 30/30 | 30/30 |
| 销售 | 29/30 | 30/30 |
| 费用·办公与行政运营 | 0/30 | 2/30 |

### 怎么读这个结果

**1. 措辞泛化从"全崩"变成"基本全对"**：26.7% → 99.2%。
`交货 - C000425` 这类写法不再依赖训练集里是否出现过。

**2. 组合真的学会了**：成本结转 0/30 → 28/30，生产制造 6/30 → 30/30。
这说明模型之前并不是"组合没见过"，而是**有捷径就不学组合**。

**3. 常规准确率没有付出代价**：93.8% → 94.0%，在噪声范围内。
唯一代价是收敛慢半拍——第 1 轮 0.9152 vs 0.9208，第 3 轮追平。

**4. 费用子类仍然差**（2/30）：这是组合本身区分不了（五个费用子桶的科目组合
高度重叠），必须靠摘要。所以丢弃率不能太高，否则这些桶会退化。

**5. 生产模型的 B 只有 24.7%，比对照组 13.1% 高** —— 那是因为 bge-large
容量大、8 轮训得久，但仍没学会组合（成本结转 0/30 与对照组一致）。
换成 large + dropout 应该能同时拿到 95%+ 的 C 和 99% 的 A。

### 建议

1. **下一轮生产训练加 `--summary-dropout 0.25~0.3`**。成本几乎为零（一个参数），
   收益是措辞泛化从"靠训练集覆盖"变成"靠组合推理"。
2. **丢弃率做一次小扫描**（0.2 / 0.3 / 0.4），重点看两个数：
   A 组不能掉、`费用·办公` 这类靠摘要的桶不能崩。
3. 现有 `费用子类` 的模糊是设计使然（父级回退兜着），不作为优化目标。

### 丢弃率扫描（0 / 0.2 / 0.3 / 0.4）

同一份数据、同一个编码器（bge-base）、同 3 轮，唯一变量是丢弃率：

| 丢弃率 | A 交货措辞 | B 中性文本 | B·成本结转 | B·生产制造 | B·费用办公 | C 常规验证 | val_acc |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0（对照） | 26.7% | 13.1% | 0/30 | 6/30 | 0/30 | 93.8% | 93.87% |
| 0.2 | 98.3% | 24.5% | **0/30** | 20/30 | 6/30 | 94.2% | 93.91% |
| **0.3** | **99.2%** | 32.2% | 28/30 | 30/30 | 2/30 | 94.0% | 93.89% |
| 0.4 | 98.3% | **37.1%** | 28/30 | 30/30 | 4/30 | 94.2% | 93.95% |

**读法**：

- **0.2 不够**：措辞救回来了（98.3%）但组合仍没学会（成本结转 0/30）——
  它靠残留的文字线索在猜，换个说法还会崩。
- **0.3 是拐点**：成本结转 0/30 → 28/30，模型真正开始用科目组合。
- **0.4 不比 0.3 差**：B 高 4.9 个百分点（846 条里多 42 条判对），成本结转、生产制造打平，
  C 还高 0.2 点；A 少 1 条（120 条样本，噪声）。
  原先担心「丢太多会让靠摘要的费用子类崩」——**没有发生**（费用·办公 2/30 → 4/30）。
- **三者常规准确率都在 94% 左右，丢弃没有代价。**

**选哪个**：0.3 与 0.4 实质打平。取 **0.3** —— A 组略好、干预更小，对真正需要摘要的桶更稳；
0.4 也完全可以，若重训后 A 组不达标可以上调。

## 结论

- **该上线**：真正的痛点是陌生措辞（交货那次翻车），A 组 41.7% → 95.0% 是决定性改善；

## 三、数据流：每一步的形态与规模

| # | 阶段 | 数据结构 | 规模 | 说明 |
|---|---|---|---:|---|
| 1 | 读表 | `pandas.DataFrame` | 905,838 × 10 列 / 507MB | calamine（Rust）解析 xlsx，全量进内存 |
| 2 | 硬约束 | `dict[str, str]` | 977 条 | 凭证号 → 桶；命中者不再进模型 |
| 3 | 科目归一化 | `dict[str, list[str]]` | 143,153 凭证 | 每凭证一组 `科目[借/贷]` 开关字符串 |
| 4 | 拼开关 | `torch.Tensor`（模型内） | 46,377 × 187 | 0/1 多热，按批构造成张量 |
| 5 | 去重 | `list[dict]` | 143,153 → 40,328 组 | 每组一个代表 + 成员凭证号列表 |
| 6 | 模型输入 | `list[dict]` | 46,377 条 | `[{"summary": str, "subjects": [str]}]`；一次调用传 40,328 条，内部按 chunk=128 分批 |
| 7 | 模型输出 | `list[dict]` | 46,377 × 29 桶概率 | `[{"probs": {桶名: float}, "unknown_subjects": [...]}]` |
| 8 | 逐凭证落结论 | `list[dict]` | 149,960 行 | 14 个字段：桶/置信度/概率/Top3/来源/后处理/摘要/科目/金额/组合/组内张数/未知科目 |
| 9 | 明细 | `pandas.DataFrame` | 149,960 × 14 | 复核页数据源 |
| 10 | 写回 | `pandas.DataFrame` | 905,838 × 17 | 原 10 列 + 业务分类/置信度/判定来源/模型概率/校准概率/Top3/后处理 |
| 11 | 落盘 | parquet ×3 | result / detail / vouchers | 按 job 存盘；导出 >50 万行走 CSV |

**没有跨进程/跨网络的搬运**：整条链路在单进程内，DataFrame 与 Python 原生对象互换，
只有两处序列化——读表（xlsx → DataFrame）和落盘（DataFrame → parquet）。

## 四、模型侧

| 项 | 值 |
|---|---|
| 凭证总数 | 149,960 |

| 待模型判定 | 143,153 |
| **指纹（摘要 + 科目组合）** | **143,153** |
| 去重后（首轮调用组数） | **40,328**（L1/L2 合并 99,518，L3 合并 2,808，**3.55:1**） |
| **模型实际调用** | **46,377**（首轮 40,328 + 低置信组重判 173 组 / 6,049 条） |
| 摘要编码缓存 | 命中 170 / 38,258（0.4%，冷跑；170 条是重判时命中首轮刚写入的） |
| 缓存条目 / 体积 | 38,088 / 168.8MB |
| 模型吞吐 | **860 次/秒** |
| 未分类 | 5,830（3.9%） |

指纹到调用量的漏斗：

```
149,960 凭证
  −977  硬约束（0.7%）
=143,153 待判定
  ÷3.55 去重（L1 精确 / L2 去数字 / L3 相似 ≥0.95，同科目组合内）
= 40,328 组
  +6,049 低置信组拆开重判（173 组，代表概率 <0.80）
= 46,377 次模型调用   ← 凭证数的 30.9%
```

三个值得注意的点：

1. **采购的中置信异常多**（6,048 / 49,522 = 12.2%），远高于销售（0.3%）。
   8 家公司的采购措辞差异最大——"货款/材料款/预付/暂估"各有写法，模型在边界上犹豫。
   这是复核清单的主要来源。
2. **成本结转的低置信 241 张**（占该桶 2.1%），与它 7.5% 的占比不相称。原因是"结转"类摘要
   同时出现在生产制造与成本结转，两者边界靠贷方科目区分。
3. **未分类 5,830 张全部记低置信**——这个档位是硬编码的，不是模型给的。

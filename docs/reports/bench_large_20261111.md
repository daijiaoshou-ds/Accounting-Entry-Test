## 三、数据流：每一步的形态与规模

| # | 阶段 | 数据结构 | 规模 | 说明 |
|---|---|---|---:|---|
| 1 | 读表 | `pandas.DataFrame` | 846,991 × 10 列 / 481MB | calamine（Rust）解析 xlsx，全量进内存 |
| 2 | 硬约束 | `dict[str, str]` | 976 条 | 凭证号 → 桶；命中者不再进模型 |
| 3 | 科目归一化 | `dict[str, list[str]]` | 143,136 凭证 | 每凭证一组 `科目[借/贷]` 开关字符串 |
| 4 | 拼开关 | `torch.Tensor`（模型内） | 46,365 × 187 | 0/1 多热，按批构造成张量 |
| 5 | 去重 | `list[dict]` | 143,136 → 40,318 组 | 每组一个代表 + 成员凭证号列表 |
| 6 | 模型输入 | `list[dict]` | 46,365 条 | `[{"summary": str, "subjects": [str]}]`；一次调用传 40,318 条，内部按 chunk=128 分批 |
| 7 | 模型输出 | `list[dict]` | 46,365 × 29 桶概率 | `[{"probs": {桶名: float}, "unknown_subjects": [...]}]` |
| 8 | 逐凭证落结论 | `list[dict]` | 144,119 行 | 14 个字段：桶/置信度/概率/Top3/来源/后处理/摘要/科目/金额/组合/组内张数/未知科目 |
| 9 | 明细 | `pandas.DataFrame` | 144,119 × 14 | 复核页数据源 |
| 10 | 写回 | `pandas.DataFrame` | 846,991 × 17 | 原 10 列 + 业务分类/置信度/判定来源/模型概率/校准概率/Top3/后处理 |
| 11 | 落盘 | parquet ×3 | result / detail / vouchers | 按 job 存盘；导出 >50 万行走 CSV |

**没有跨进程/跨网络的搬运**：整条链路在单进程内，DataFrame 与 Python 原生对象互换，
只有两处序列化——读表（xlsx → DataFrame）和落盘（DataFrame → parquet）。

| **模型实际调用** | **46,365**（首轮 40,318 + 低置信组重判 172 组 / 6,047 条） |
| 摘要编码缓存 | 命中 169 / 38,249（0.4%，冷跑；169 条是重判时命中首轮刚写入的） |

| 未分类 | **7**（0.005%） |
| 未知科目 | 14 个 / 370 张 |

指纹到调用量的漏斗：

```
144,119 凭证
  −976   硬约束（0.7%）
=143,136 待判定
  ÷3.55  去重（L1 精确 / L2 去数字 / L3 相似 ≥0.95，同科目组合内）
= 40,318 组
  +6,047 低置信组拆开重判（172 组，代表概率 <0.80）
= 46,365 次模型调用   ← 凭证数的 32.2%
```

## 六、清理空摘要前后的对比

上一版文件有 58,757 行空摘要（其中 5,221 张凭证整张空白，全来自 `序时账5.xlsx`）。清理后：

| | 清理前 | 清理后 | 变化 |
|---|---:|---:|---:|
| 行 | 905,838 | **846,991** | −58,847 |
| 凭证 | 149,960 | **144,119** | −5,841 |
| 待判定指纹 | 143,153 | **143,136** | **−17** |
| 模型调用 | 46,377 | **46,365** | **−12** |
| 端到端 | 99.0s | **95.6s** | −3.4% |
| 未分类 | 5,830 | **7** | −5,823 |
| 低置信 | 6,569 | **746** | −5,823 |

**关键点：行数少了 6.5%，模型调用只少 12 次**——因为删掉的全是"无摘要、根本不进模型"的凭证。
清理带来的是**时间外收益**：未分类从 3.9% 降到 0.005%，低置信从 4.4% 降到 0.5%，
复核清单从 9,000+ 张缩到 8,489 张且全部是真实需要人看的。

时间只省 3.4%，也印证：**行数不等于模型调用量，删数据不等于加速。**

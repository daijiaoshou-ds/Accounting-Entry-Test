# 一、流程

## 1.1 在管线里的位置

四个功能有先后依赖，不是并列的四个按钮：

```
对方科目分析(contra) → 序时账清洗(cleaning) → 现金流量编写(cashflow)
                                            └→ 会计分录测试(entry_test)
```

**为什么会计分录测试排在清洗后面**：第 1 步画像的业务活动就是清洗判出来的业务桶，
第 2 步「活动里的科目」用业务活动当先验，科目对那一层用的对方科目行表也是清洗那一棒
带过来的。同一份账不应该有两个业务分类，也不该有两个"对方科目"。

**接不上上游就直接报错，不静默降级**：缺业务分类时，画像只剩"按一级科目统计"，
那是科目余额表不是画像；产物看起来跟正常的一样，只是内容空了，没人会发现。所以
报错并给出两条路——先在同一个任务上跑清洗，或者 `--option upstream=<清洗任务 id>`。

## 1.2 六个阶段

接上游时 `read` 跳过，实际执行 5 个：

| 阶段 | 做什么 | 本次耗时 | 失败时 |
|---|---|---:|---|
| link | 从上游搬 `raw.parquet / detail.parquet / contra_rows.parquet / review_bucket.json` | 0.12s | 上游未完成则报错 |
| read | 读表 + 认列名（复用清洗那一段），接上游时跳过 | — | 缺必需列直接报错 |
| integrity | 第 0 步，写 `integrity.json` | 0.34s | 不阻断，问题进表 |
| profile | 第 1 步，写 `profile.json` | 0.89s | 缺业务分类报错 |
| detect | 第 2 步，白名单 → 四块检验（含本福特的背景 stats）→ `leads.json` | 9.9s | 单块出错不拖垮其余 |
| export | HTML 报告 + Excel 标记表 | 5.0s | 直接报错 |

两处刻意的设计：

**完整性不过也继续跑。** 不平衡、缺号本身就是发现，不是"不能跑"。把它当闸门关掉，
等于把发现藏起来。

**一块挂了不拖垮全部。** 四块的输入依赖不一样（指纹要摘要、活动科目要业务分类、
科目对要上游行表、孤儿冲销要红字行），某一层在残缺的账上跑不动，不该让另外几块的
发现也消失。没跑成的那一块会在报告里写明原因，不留空白。

## 1.3 风险白名单

开跑前先整张剔掉三类凭证：

| 原因 | 张数 | 为什么不携带判断信息 |
|---|---:|---|
| 汇兑损益 | 12 | 金额由期末汇率与外币余额算出，不是人选的数；天然整数化、天然随汇率跳 |
| 结转期末损益 | 12 | 把损益科目清零，金额是当期汇总数，必然巨大、必然"跳变" |
| 资金内部往来 | 83 | 集团内调拨，科目与金额由资金安排决定，账面两边都是自己人 |

合计 **107 张 / 1,538 行**被整张放过（一张凭证里过半的行命中同一原因才放过，按单行
放过会把正常凭证整张误伤）。

判定**优先用业务活动**、退回摘要关键词。这不是锦上添花：本案「资金内部往来」83 张，
大部分摘要里并不含"内部往来"四个字，靠关键词抓不全。

放过必须是显式的——报告脚注写"按白名单放过 107 张（汇兑 12 / 结转 12 / 内部往来 83）"，
Excel 里有一列逐张标着原因。静默过滤才是问题：那种"看起来没有异常"的报告，
没人知道是被过滤了还是真的没有。

# 二、第 0 步：总体完整性

## 2.1 三项检查

**凭证号连续性。** 各家公司的凭证号写法不同（`2025年1月-记-001号`、`收001`、
`40001001`），所以先按前缀拆成"凭证序列"，序列内按自然数序（`re.findall(r"\d+")`）
判断缺号。这份账拆出 12 条序列，每条一个月份、一种字号。

**按月借贷平衡。** 不检查单张凭证——ERP 里单张不平衡根本录不进去。按月份核对
借方发生额与贷方发生额是否相等。

**数据质量。** 空科目、缺摘要、零金额行、缺日期，各计一行数。

## 2.2 本次数据

| 检查项 | 结果 |
|---|---|
| 账本概况 | 7,883 张凭证 / 42,683 行 / 2025-01–2025-12 / 54 个一级科目 |
| 凭证号连续 | 12 条序列全部通过（1 月 499 张 1–499 … 12 月 861 张 1–861，无缺号） |
| 按月借贷平衡 | 12 个月全部通过，差额 0.00（月发生额 1.22 亿 – 3.79 亿） |
| 空科目 / 缺摘要 | 0 / 0 |

## 2.3 它证什么、不证什么

**证的是总量守恒，不是明细正确。** 借贷同错的串户不破坏平衡；一张 5,000 万的虚构
收入混进十万行，平衡照样成立。它是地基——必要非充分。

反过来，"不平衡"这件事本身就有信息：差额多少、差在哪个月、差额是否等于某几张凭证
的金额之和，这些比"通过"有价值得多。所以它进表、进 facts，不阻断后续。

## 2.4 金额首位分布：本福特（背景）

**它不作判决，也不出线索。** 只回答一个问题：这份账的金额，像不像自然长出来的。
放在这一节的理由很直接——本福特在统计上很有说服力（大样本、分布明确、MAD 有公认
档位），在审计上却指不出具体哪一笔。它说得出"费用这类业务的金额偏整数"，说不出
"这张凭证有问题"。所以它只当背景：不进异常清单、不标任何凭证行、Excel 里不会因为
它多出一个"是"。

两个口径：**借、贷分开跑**（收款与付款是两种业务，混在一起两个分布互相污染）；
**只取 ≥10 元的绝对值**（首位数字要成立，数本身至少两位；红字取绝对值，因为关心的是
"金额长什么样"不是方向）。样本不足 1,000 条不跑。

**只做首位，不做次位。** 次位的本意是查"凑整、整数化"，但它在本账套里没有信息量：
整数报销、整万转账、按天计息让次位 0 天然偏高，样本门槛又高（5,000），几乎每份账
都会落到"边缘"，报出来全是噪声。

| 侧 | 样本 | 首位 MAD | 判读 |
|---|---:|---:|---|
| 借方 | 22,590 | 0.00487 | 接近 |
| 贷方 | 17,629 | 0.00370 | 接近 |

两侧都在正常区间，这一项到此为止。

只有落到"边缘 / 不可接受"（首位 MAD > 0.012）才往下走三步：找偏离最大的数字、
按业务活动分解贡献、留一确认（剔掉它 MAD 应当回落）。**回不落就不算定位成立**——
只看"这个活动的贡献为正"是不够的：一个笔数多、但完全符合本福特的大活动，它对每个
数字的贡献都可能为正，剔掉它却什么也不会变。

这道闸门挡的是两种"伪定位"，两种都在真实账上出现过：

| 归因形态 | 剔除后 | 为什么不能写 |
|---|---|---|
| 「采购」首位 2 多 83 笔 | 可接受 → 可接受 | 剔了等于没剔，偏离是散的 |
| 「采购」次位 0 多 190 笔 | 边缘 → 不可接受 | 剔了更差，这个活动其实在"压着"偏离 |

门槛同理：首位 MAD 落在"可接受"区间（≤0.012）就说明整账正常，不该再往下找来源。

次位唯一站得住的信号长这样：序时账2 借方次位 MAD 0.01074（边缘），定位到「费用」有
1,564 笔次位为 0（占该活动 20%，全账基线 12%），剔掉后回落到"接近"。方向是对的，
但它指向"这个活动的填数习惯"——估算、凑整、按额度报账，不是某一张凭证。这正是
"统计上成立、审计上用不上"：能写进背景，写不进凭证清单。

# 三、第 1 步：画像

## 3.1 只回答三个问题

- 这份账都做了哪些**经济活动**（what）——业务活动清单
- 这些活动的**金额**怎么分布（how）——笔数、金额、占比
- 记录是**谁做的**（who）——每个活动的主要制单人及其占比

维度刻意压到最少。维度一多，人就不看了。

## 3.2 集中度：两个 HHI

HHI = Σ(份额²)，0–1，越大越集中。两个维度各算一次：

- **金额 HHI**：份额按凭证算，回答"这个活动是不是少数几张凭证撑起来的"；
- **对手方 HHI**：份额按科目算（凭证内去重），回答"这个活动的钱主要往来于几个科目"。

判读档 0.25 / 0.15（高度集中 / 中等集中 / 分散），只作参考，不下结论。

**不做抽凭建议。** 真抽凭要先定重要性水平、样本量、覆盖哪些认定，靠"金额前 80%"
拼出来的清单不是抽样、只是排序，交出去反而误导。抽样留给细节测试。

## 3.3 本次画像（前 8 个活动）

| 业务活动 | 域 | 凭证 | 笔数占比 | 金额（元） | 金额占比 | 主要制单人 | 金额HHI | 对手方HHI |
|---|---|---:|---:|---:|---:|---|---:|---:|
| 采购 | 经营 | 3,858 | 48.9% | 938,671,181 | 26.5% | 储金菊 85.3% | 0.013 | 0.190 |
| 销售 | 经营 | 636 | 8.1% | 802,934,763 | 22.7% | 陈金香 70.9% | 0.010 | 0.264 |

# 四、第 2 步：检验总览

## 4.1 五块、两层

| 块 | 层 | 输入 | 判据一句话 | 条数 |
|---|---|---|---|---:|
| 金额孤立 | 个体层 | 指纹（摘要 + 科目组合） | 同一指纹内某张金额的稳健 z ≥ 3.5 | 19 |
| 活动里的科目 | 个体层 | 群 × 科目（点乘矩阵） | 科目有家（有效桶数 ≤2）；纵向 群内占比 ≤1% 且金额 ≥100 万，横向 跨对抗群 | 14 |
| 科目对孤立 | 个体层 | 借 × 贷 边表 | 对借方是罕见通道（σ_row ≤ 2%），对贷方却是主要来源（σ_col ≥ 30%） | 6 |
| 现金收付 | 行为层 | 库存现金借贷 | 金额 ≥ min(该类均值×50%, 5,000) | 6 |
| 孤儿冲销 | 行为层 | 红字行 + 冲销关键词 | 本年有冲销，本年找不到等额母体 | 61 |

层不是难度分级，是**证据的粒度**：个体层说的是"这一笔在这一类里不合群"，行为层说的是
"这笔账的动作本身不完整"。原本还有一层"总体层"，只剩本福特——它现在只当整账可信度的
背景（见 2.4），不产出线索，所以线索清单里只有个体层与行为层。

## 4.2 一条线索长什么样

线索 = **统计证据** + **涉及凭证**。两样缺一不可：只有统计量等于没交付（审计员要的是
凭证号），只有凭证号等于没解释（不知道为什么看它）。

```
层     类型        主体                  笔数   金额          证据（可复核）                        凭证
个体层  科目对孤立  财务费用 → 资本公积      4    2,617,344.87  对「财务费用」332 笔占 1.20%；      2025年9月-记-0575号…
                                                            对「资本公积」4 笔占 100%
```

三条约定：

1. **不给建议程序。** 写死的"建议"会变成两种坏东西——套话（每张都建议"查合同"），
   或者越界（替审计员下结论）。
2. **优先级只有三档，且不跨层可比。** 一条金额孤立和一条孤儿冲销不是同一种东西，
   硬排成一个序会给出"第 3 名比第 7 名更该查"的错觉。层内排序：优先级 → 金额。
3. **报告只放汇总，不放明细。** 报告里每块只回答"哪一类问题最多、最大的一处是哪个"，
   一条线索的证据要占三四行，95 条就把报告变成没人读完的表。具体是哪几张凭证，
   去 Excel 筛。

## 4.3 本次结果

95 条线索（个体层 34 / 行为层 61），落在 **159 张凭证**上。
Excel 里筛「是否异常=是」，得到的就是这些行；其中 61 张是孤儿冲销（一张凭证
一条线索，不重复计数）。

# 五、科目组合孤立

这一章是全文重点。它对应最初设计里的两句话：

> 2.1 业务活动里的科目组合：每个业务活动统计会计科目出现的情况，极少出现的科目去翻凭证。
> 2.2 对方科目里的科目组合：原材料的借方对方科目里，应付账款高频、预计负债低频；
> 应付账款的贷方对方科目里，原材料只是其一，预计负债的对方科目却很少。

两句话问的**不是同一件事**，所以实现成两块而不是一块。

## 5.1 两个视角，两套先验

| | 活动里的科目（§5.9） | 科目对孤立（§5.3 起） |
|---|---|---|
| 问的问题 | 这个**活动**该不该用这个科目 | 这两个科目之间的**通道**正不正常 |
| 先验来自 | 上游清洗判出的业务活动 | 全账的边频次，不含业务语义 |
| 统计单位 | 群 × 科目（格） | 借 × 贷（边） |
| 分母 | 列：本桶各科目凭证数之和；行：该科目全账凭证数 | 借方科目的全部往来 / 贷方科目的全部来源 |
| 典型发现 | 销售里出现其他应收款 | 财务费用贷记资本公积 |
| 天然看不见 | 同一活动内部两个科目之间的异常组合 | 借贷同一科目的重分类（自环） |

"两套先验"是关键：活动层用业务语义当先验，所以它知道"股东出资在权益筹资里是常客"；
科目对层没有业务语义，只认频次，所以它一定会把股东出资挑出来。

### 用同一份账证明两者不可替代

**① 科目对报、活动层不报：股东出资（4 笔，1,000 万）**

```
2025年7月-记-0513号  借 银行存款 1,540,000  贷 实收资本 1,540,000   摘要：深圳品誉转入投资款
2025年12月-记-0643号 借 银行存款 3,000,000  贷 实收资本 3,000,000   摘要：收到深圳品誉转入投资款
（另两笔同形态：7 月 246 万、12 月 300 万）
```

银行存款全年 340 笔，走实收资本的只有 4 笔（1.18%）；实收资本全年就登台 4 次，
100% 来自银行存款。科目对层报出，是对的——它只认"这条通道稀有且专用"。
活动层放过它，也是对的——这 4 张在上游被分到「权益筹资」，在那个活动里用实收资本
天经地义。**同一批凭证，两层给两个答案，因为问的不是同一个问题。**

**② 活动层报、科目对不报：其他应收款重分类（1 笔，955 万）**

```
2025年1月-记-0479号  借 其他应收款 9,555,272.50
                    贷 其他应收款 9,555,272.50   摘要：其他应收款-陕西誉品实业有限公司科目重新分类
```

这张凭证借贷都在「其他应收款」内部，落到矩阵里是**自环**，被剔掉，一条边也不产生
（矩阵里剔了 27 条结构边，自环是其中一类）。活动层抓到了它：它被分在「销售」，
而销售活动一年 636 张凭证里只有这一张用其他应收款。

两个例子摆完，两层的分工就清楚了：**科目对管"通道稀不稀有"，活动层管"语境合不合理"。**

## 5.2 科目对：把凭证变成边

### 5.2.1 输入是什么

上游「对方科目分析」交出来的是一张**行表**：45,012 行，每行带
`一级科目 / 借方金额 / 贷方金额 / 对方科目-一级`。

它比序时账的 42,683 行多 2,329 行——不是一一对应的搬运：多行凭证里，一条分录会按
对方科目拆成多行（本次有 2,651 张凭证存在这种展开）。

注意它的视角：**一行只描述一个端点的看法**。

```
借 原材料 100   对方科目-一级 = 应付账款
贷 应付账款 100  对方科目-一级 = 原材料
```

同一次配对写了两遍。直接按行建边，一张凭证会长出 A→B 和 B→A 各一条，其中一条账上
根本不存在。

### 5.2.2 四步

```
① 每行出一条边
   借方行：subj → 对方
   贷方行：对方 → subj
   红字（负数）把方向翻过来：借方的红字是贷方，贷方的红字是借方

② 去掉"同一笔被写两遍"的重复
   键 = 凭证号 + 借 + 贷 + |金额|

③ 同一凭证同一对求和
   蓝字入库 512 万 + 红字冲回 512 万 → 净额才是这张凭证真正发生的数

④ 方向相反的成对边：金额接近（差 < 20%）合并成净额，差得远的分开留
   收退款 1,015 / 付款 49,530 是两笔独立业务，不能抵
```

第 ④ 步是唯一带点判断的地方：同一张凭证里 A→B 与 B→A 同时存在时，"正负相抵"和
"两笔独立业务"在数据上长得一样，差别只在金额差多少。

### 5.2.3 为什么不用净额法

更省事的做法是"先按科目算净借额，再配对"。它会在过路科目上失效：一张凭证里应付账款
先收 6,690 又付 6,690，净额为 0，整张凭证的边全部消失——**实测那样会漏掉 12% 的
借方发生额**。所以按"每对一条边"建，接受多算，不接受少算：少算的边永远不会被任何人
看到，多算的边至少还在那里。

### 5.2.4 已知近似

多借多贷（借 A / 贷 B、C）时两端各生成一次，边金额会比实际偏高：**全账边金额合计比
借方发生额多约 9%**。笔数与两端份额不受影响，而检测只用这两样，所以不修。
但要知道：报告里那条边的"金额"是上限，不是净值。

本次数据：**12,373 条边记录 / 7,613 张凭证 / 293 个科目对 / 48 个借方科目**。
（7,776 张凭证里剩下的 163 张，是单边凭证或只有自环的凭证。）

## 5.3 两个条件份额

### 5.3.1 定义

矩阵每一格是「借 X → 贷 Y」的凭证数，于是有两种份额：

```
σ_row(X→Y) = count(X→Y) / 借 X 出现的凭证数     —— 这笔钱在 X 的往来里占多少
σ_col(X→Y) = count(X→Y) / 贷 Y 出现的凭证数     —— Y 的来源里有多少来自 X
```

两个都是**条件概率**，不是统计显著性：分母本身就是条件，所以不依赖任何独立性假设。
固定 X，σ_row 沿行求和 = 1；固定 Y，σ_col 沿列求和 = 1。

### 5.3.2 用真实数据看一眼

财务费用作借方，全年 332 笔：

| 借 ＼ 贷 | 银行存款 | 租赁负债 | 应收票据 | 应收账款 | 资本公积 | 应付账款 | 应付利息 | 行合计 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 笔数 | 261 | 36 | 21 | 7 | **4** | 2 | **1** | 332 |
| σ_row | 78.6% | 10.8% | 6.3% | 2.1% | **1.2%** | 0.6% | **0.3%** | 100% |
| 贷方全年笔数 | — | — | — | — | **4** | — | **1** | |
| σ_col | — | — | — | — | **100%** | — | **100%** | |

一眼看出两件事：财务费用的常规去路是银行存款（78.6%）；资本公积和应付利息这两格，
σ_row 低到 1.2% / 0.3%，σ_col 却是 100%。

**这就是判据要的形状**：在借方那儿几乎不走，在贷方那儿几乎是唯一入口。

### 5.3.3 四象限

| | σ_col 低（贷方来源之一） | σ_col 高（贷方主要来源） |
|---|---|---|
| **σ_row 低**（借方罕见通道） | 两端都稀有：样本量的巧合，样本为 1 时"专享"是废话 | **报出**：罕见通道 + 专用终点 |
| **σ_row 高**（借方常用通道） | 常规流：借方的一级马路汇入贷方的众多支流 | 枢纽对枢纽：双方的主干道（如应交税费→应付账款，80.1% / 33.3%） |

只有右上一格进线索。另外三格都不是"异常"，是被会计科目体系本身决定的常态。

### 5.3.4 为什么必须同时看两个

**只看 σ_row 低**：所有一次性往来都算。借方科目一年动两千次，任何出现 2 次的边
σ_row 都是 0.1%，这是"稀有"的定义，不是"异常"的证据。

**只看 σ_col 高**：选出的是"某个科目的唯一用途"。实收资本 4 笔全来自银行存款，
σ_col = 100%，但那只是实收资本本来的用途。

**同时成立**才是那个结构：一个几乎不登台的科目，登台时几乎只从同一个通道进来，
而那个通道的主人对它毫无感觉。这个不对称，要么是"一次性的合法安排"（股东出资），
要么是"钱走了不该走的门"（利息挂进资本公积）——**判据只负责把这两种情况挑出来，
判断哪一种要靠读凭证。**

## 5.4 为什么不用 E 和 lift

设计文档「二、特征孤立 · B 科目组合」里出现过期望频次 E 与提升度 lift。它们不进判据，
也不进报告。

### 5.4.1 它们不是独立信息

```
E    = row_all × col_all / N        （N = 全账边数）
lift = count / E
```

而已有 `count = σ_row × row_all = σ_col × col_all`，代入：

```
lift = count × N / (row_all × col_all) = N × σ_row × σ_col
```

**lift 就是两个条件份额的乘积乘上常数 N**，而 E 不过是 `count / lift`。给定 σ_row、
σ_col、N，E 和 lift 一个比特的新信息都没有——它们只是把同一组数换了个刻度。

### 5.4.2 换刻度换坏了

`lift = N × σ_row × σ_col` 这条恒等式说明：lift 的大小同时被"边稀不稀"和"全账多大"
决定。两边都稀时它会被 N 放大到荒谬，一边满概率时它的上限又掉回 1。

原话的例子正是这样：若「原材料」出现在所有凭证里，σ_row 的分母就是 N，E 退化成
col_all，lift 的上限变成 σ_col ≤ 1——**无论这对科目多离谱，lift 都超不过 1**。
反过来，两端都稀有（count = 2，row_all = col_all = 6,000）时 lift 会到几百，
可这条边除了"少"什么也没说。

实测口径也一致：E < 0.5 的边，lift 中位数 24、最大 2,619。

### 5.4.3 结论

要判断的是"这条通道是不是专门为对方开的"，这件事由 σ_row 低 + σ_col 高直接表达。
E 与 lift 是同一件事的另一种写法，且这种写法在两端规模悬殊时失效。于是删掉：
不参与判定，不在报告与 Excel 里出现。

## 5.5 判据与阈值

### 5.5.1 判据

```
count ≤ 5              稀有：一年出现这么多次以内才谈得上"一条通道"
σ_row ≤ 2%             对借方是罕见通道
σ_col ≥ 30%            对贷方是主要来源
row_all ≥ 100          借方端要够活跃，它的"份额极低"才有信息量
col_all ≤ 50           贷方端要够冷门，它的"被专享"才说明问题
边合计 ≥ 10 万 且 最大单笔 ≥ 5 万    金额门槛
```

### 5.5.2 参数之间有一个可推导的关系

后两条在现在的常数下**恒被前三条蕴含**：

- `count ≤ 5` 且 `σ_row ≤ 2%` ⇒ `row_all ≥ 5 / 0.02 = 250 > 100`；
- `count ≤ 5` 且 `σ_col ≥ 30%` ⇒ `col_all ≤ 5 / 0.3 ≈ 16.7 < 50`。

所以本次 23 条边过了 σ_row 那一关后，`row_all ≥ 100` 与 `col_all ≤ 50` 一条也没再
拦下（漏斗里两步都是 23 → 23 → 6）。它们留在代码里的作用是**当 RARE_MAX 放宽时兜底**：
一旦允许 count 到 20，`row_all`、`col_all` 就开始真正起作用。写出来是为了让"为什么
要这个门槛"这件事留在原地，而不是靠读者自己推。

### 5.5.3 漏斗（本次真实数据）

| 步骤 | 剩余 | 说明 |
|---|---:|---|
| 边记录 | 12,373 | 7,613 张凭证 |
| 去重成科目对 | 293 | 48 个借方科目 |
| 剔结构边 | 266 | 27 条（自环 / 结转 / 成本↔存货） |
| 金额门槛 | 146 | 边合计 ≥ 10 万且最大单笔 ≥ 5 万 |
| 笔数 ≤ 5 | 36 | |
| σ_row ≤ 2% | 23 | 借方端的"罕见通道" |
| row_all ≥ 100 | 23 | 恒满足（见 5.5.2） |
| σ_col ≥ 30% | 6 | 贷方端的"主要来源"——**真正的分水岭** |
| col_all ≤ 50 | 6 | 恒满足 |

**为什么只剩 6 条**：293 条边里，一年出现 5 次以内的只有 36 条（其余都是常规通道）；
这 36 条里有 13 条在借方端不够罕见（σ_row > 2%）；剩下 23 条里又有 17 条在贷方端
不够"专享"（σ_col < 30%）。两层条件都是"必须"，交集自然小。

最接近但被否掉的两条，可以看出来阈值在哪里起作用：

| 边 | 笔数 | 金额 | σ_row | σ_col | 被哪一条否掉 |
|---|---:|---:|---:|---:|---|
| 原材料 → 待处理财产损溢 | 5 | 518,823.36 | 1.16% | 29.4% | σ_col < 30% |
| 管理费用 → 待处理财产损溢 | 4 | 3,501,820.18 | 0.54% | 23.5% | σ_col < 30% |

「管理费用 → 待处理财产损溢」4 笔 350 万，其中一张单笔 350 万——从审计角度看值得翻，
但它只占「待处理财产损溢」全年 17 笔的 23.5%，够不上"专用通道"。**这是这一层的
取舍：宁可漏掉"稀有但不专用"的，也不把每个冷门科目的每次出现都报出来。**

## 5.6 结构白名单

有些边天然稀有，稀有是记账规则造成的，不是疑点。判定前先剔，本次 27 条：

| 类型 | 例子 | 为什么不算 |
|---|---|---|
| 自环 | 银行存款 → 银行存款 | 招行转建行，不是"两个科目的关系"；进矩阵还会把银行存款的行合计撑大、压小别的边 |
| 结转 | 主营业务收入 → 本年利润、本年利润 → 利润分配 | 期末结转必然只走这一条路 |
| 成本 ↔ 存货 | 主营业务成本 ↔ 库存商品 / 发出商品 / 生产成本 … | 结转销售成本，每个月都一样 |

自环还在另一个地方起作用：借贷同一科目的重分类凭证（§5.1 案例②）因此在这一层
完全不可见。这是科目对层的盲区，不是 bug——它问的是"两个科目之间"，同一科目内部
的搬运不在它的问题域里。

### 案例一：财务费用 → 资本公积（真问题的那一类）

```
2025年3月-记-0431号  计提席龙龙借款利息 40,236,069.5 × 3% / 360 × 89 天（第一季度）
  借 财务费用 298,417.52 / 12,666.67 / 57,730.83
  贷 资本公积 298,417.52 / 70,397.50
2025年6月-记-0373号  同形态（第二季度）
2025年9月-记-0575号  计提席龙龙借款利息 40,236,069.5 × 3% / 360 × 92 天（第三季度）
  借 财务费用 308,476.53 / 28,166.67 / 8,333.33（三笔明细）
  贷 资本公积 344,976.53
  借 财务费用  72,756.67   贷 资本公积 72,756.67   （深圳誉品投资有限公司借款）
2025年12月-记-0695号 同形态（第四季度）
```

四笔正好是一年的四个季度：**每个季度都把股东借款利息计提到资本公积，不是偶发一笔**。
两个借款人（席龙龙、深圳誉品投资有限公司），每笔利息按「本金 × 3% / 360 × 天数」算，
形态完全一致。

这笔分录说明的事实很干净：利息费用的对价没有落在负债上，也没有付现，而是落在了权益上。
两种读法都成立——股东把利息转增了资本，或者把费用挂进了权益。差别不在账里：
账上只有"借财务费用、贷资本公积"，看不到股东会决议、债转股协议，也看不到期后有没有
真的办增资。**这一层能做的就是把这张凭证推到人面前；它是不是问题，账里没有答案。**

对比一下同一年里正常的利息计提：

```
2025年12月-记-0706号  计提中国银行/工商银行/农业银行贷款利息
  借 财务费用 22,687.50 / 12,166.67 / 103,193.33
  贷 应付利息 22,687.50 / 12,166.67 / 103,193.33
```

同样叫"计提利息"，银行借款走应付利息，股东借款走资本公积——同一本账里的两种做法，
本身就是值得问一句的地方。

### 案例二：银行存款 → 实收资本（合法但稀有）

```
2025年7月-记-0513号   借 银行存款 1,540,000  贷 实收资本 1,540,000  深圳品誉转入投资款
2025年7月-记-0514号   借 银行存款 2,460,000  贷 实收资本 2,460,000
2025年12月-记-0643号  借 银行存款 3,000,000  贷 实收资本 3,000,000  收到深圳品誉转入投资款
2025年12月-记-0645号  借 银行存款 3,000,000  贷 实收资本 3,000,000
```

四笔合计 1,000 万，摘要明确、金额整齐、借贷清楚。这是**这一层的标准假阳性**：
股东出资一年就那么几次，矩阵一定会把它挑出来。

它的价值不在"抓到了问题"，而在"证明判据没有在乱报"——如果连这种边都不报，说明阈值
已经松到什么都抓不到了。线索是线索，不是结论。

### 案例三：财务费用 → 应付利息（弱信号）

```
2025年12月-记-0706号  借 财务费用 138,047.50  贷 应付利息 138,047.50（三家银行合计）
```

这是完全正常的计提分录。它被报出来，只因为「应付利息」全年只用了这 1 次——
σ_col 自然是 100%。

它揭示的是判据的边界：**"不常用"和"不正常"是两件事**，统计量只能看见前者的形状。
所以这类线索的优先级是"高"，但它排在清单里是让人"看一眼就放过"，不是让人去查。

## 5.8 这一层的边界

| 边界 | 具体表现 | 影响 |
|---|---|---|
| 依赖上游行表 | 没有 `contra_rows.parquet` 时整层不跑 | 报告写明原因，不留空白；画像与其余四块照跑 |
| 白名单凭证不进矩阵 | 107 张被整张剔掉 | 这些凭证之间的边不参与频次统计，份额会略偏 |
| 多借多贷金额偏高 | 全账合计比借方发生额多约 9% | 笔数与份额不受影响；报告的"金额"是上限 |
| 自环不可见 | 借贷同科目的重分类一条边也不产生 | 由活动层兜（§5.1 案例②） |
| 金额门槛 | 边合计 < 10 万不进线索 | 小额通道一律不看，避免长尾淹没清单 |
| 两端规模截断 | col_all ≤ 50 | 冷门科目优先；50 次以上的科目不会被判"被专享" |
| 阈值边缘 | σ_col 23.5% 的边被否 | 见 §5.5.3：接受"稀有但不专用"的漏报 |

## 5.9 活动里的科目：群 × 科目与点乘矩阵

### 5.9.1 先分群

单个业务桶太细。采购 3,858 张、生产制造 85 张，一张产成品入库单里有生产成本、半成品、
库存商品，被上游判成"采购"，单看桶会把这笔成本流转报成账务问题。所以先把业务桶并成
四个群：

| 群 | 成员 | 凭证 | 对抗谁 |
|---|---|---:|---|
| 供应链 | 采购、生产制造、长期资产购建 | 4,398 | 销售、筹资 |
| 销售 | 销售、长期资产处置 | 647 | 供应链、筹资 |
| 费用 | 费用、薪酬、单位往来、押金保证金、折旧摊销 | 2,195 | 筹资 |
| 筹资 | 借款、权益筹资、利息支出、筹资费用、利润分配 | 220 | 供应链、销售、费用 |

群与对抗关系写在桶表 `groups` 里，运行时不聚类、不随账变化。其余桶不进群——税费、
结算手续费、期末结转这些是"别的业务"，它们的作用是给科目提供另一个家（见 5.9.2），
而不是被检测。

费用群与供应链、销售不对抗：费用部门领料、低值易耗品摊销是正常形状，不该报。

### 5.9.2 点乘矩阵：一个科目的家在哪个桶

两个剖面，一个乘法。

```
列剖面 P(桶, 科目) = 该科目在本桶的凭证数 ÷ 本桶所有科目的凭证数之和
行剖面 P(科目, 桶) = 该科目在本桶的凭证数 ÷ 该科目的全账凭证数
点乘              = 列 × 行
```

列的分母不是桶的凭证数——一张凭证有 2.5 个科目，用桶的凭证数会让列合计大于 1。
按"各科目凭证数之和"做分母，列合计才正好是 1；行同理。

点乘后按科目归一化，得到"这个科目在各桶的份额"。

**为什么必须两个剖面。** 应交税费在采购 1,111 笔（量最大）、在税费桶 113 笔（纯度最高，
该桶 193 次科目出现里 113 次是它）：

| 桶 | 列剖面 | 行剖面 | 点乘 | 份额 |
|---|---:|---:|---:|---:|
| 采购 | 11.54% | 53.52% | 6.17% | 42.2% |
| 销售 | 21.20% | 16.62% | 3.52% | 24.1% |
| 税费 | 58.55% | 5.44% | 3.19% | 21.8% |

只看量会判给采购，只看纯度会判给税费桶。两家各占一半、谁也不过半——它就没有家。
这正是"应交税费是万金油"的量化表达。

### 5.9.3 有效桶数：公共程度的刻度

份额本身是一个分布，用赫芬达尔指数的倒数衡量它有多散：

```
有效桶数 = 1 / Σ(份额²)
```

含义直白：**这个科目的点乘值相当于摊在几个桶里**。1 = 全在一个桶，3 = 摊在三个桶，
8 = 到处都有。

判据只有一条：**有效桶数 ≤ 2**。它自带份额下限——`HHI = Σp² ≤ max(p)·Σp = max(p)`，
所以有效桶数 ≤2 时最大份额必然 ≥50%，不用再单独设份额阈值。

| 原材料 | 85.5% | 1.33 |

### 5.9.4 两条检测

- **纵向（稀疏大额）**：这个科目在群里各桶**等权平均**的占比 ≤1%、金额 ≥100 万。
  等权是为了不让大桶压过小桶：直接按凭证数相加，3,858 张的采购会把 85 张的生产制造
  稀释掉，生产成本在供应链只剩 0.57%，被当成稀疏；等权后是 9.2%。

- **横向（跨对抗群）**：它的家在别的群，而那个群与本群性质对抗。

# 六、其余两块

## 6.1 金额孤立（个体层）

**指纹 = 归一化摘要 + 带方向的科目组合**（`计提工资｜费用[借]、应付职工薪酬[贷]`）。
数字归一成 `#`，所以"计提2025年5月工资"和"计提2025年6月工资"是同一个指纹。

判据：同一指纹内，最大的一张用**稳健 z**（中位数 + MAD，阈值 3.5）判断是否离群。
不用均值/标准差：一条 96.8 万就能把均值和方差一起拉走，把一个离群点变成"正常波动"。

闸门（缺一个都会变成误报）：该指纹 ≥ 6 张、覆盖头尾月份的 60%、跨度 ≥ 4 个月；
金额 ≥ 5,000 元且与中位数之差 ≥ 5 万。

本次：5,439 个指纹，其中 4,554 个只出现一次（不判），123 组够样本，跳出 **19 条**。
最大的一条：

```
2024年8月份货款   同类 12 张、中位数 271,238.70
                 2025-02 这张 6,756,662.82，是中位数的 24.9 倍
```

这一层只报"跳变"。另外两个指纹信号刻意不做：**新增指纹**在科目对那一层已经报了
（新组合必然是一对低频的边，各报一遍会让人以为抓到两个问题）；**断档**要判"该有"
就得先知道哪些事是月度必发的，只能靠摘要关键词猜，猜错会把"这个月真的没发生"报成
"漏记了"。

## 6.2 孤儿冲销（行为层）

只看一件事：**本年有冲销，本年找不到被冲的那一笔。**

- **闭环**：本年先有暂估、本年又冲掉。不管后面有没有实际支付——"暂估 + 冲销都在本年"
  已足以说明对本年净影响为零，放过。
- **孤儿冲销**：本年只有冲销，找遍全账没有等额母体。这才是要问的。

匹配方式：把凭证拆成「负数行合计 / 正数行合计」，键是（一级科目, 借/贷）——按科目+方向
合计而不是逐行比，因为暂估可能写 3 行、冲销写 1 行，逐行比会把同一笔判成对不上。
用冲销里最大的一笔去候选索引里按金额取窗口（容差 max(0.02, 0.1%)），再要求母体覆盖
冲销的全部科目方向。

**不按摘要判"是否明示冲销往年"**：摘要怎么写取决于制单人的习惯，同一件事三个人三种
说法；而且跨期冲销本来就该看。摘要只用来识别"这是不是冲销"，以及在证据里如实记录
它提到了哪张往年凭证。

本次：**75 张冲销凭证，14 张本年闭合，61 张孤儿，合计 3,883 万**。最大的一张：

```
2025年1月-记-0156号  未开票收入红冲（12 行）
  应收账款 红字 9,335,806.60（10 个客户）
  主营业务收入 红字 8,261,775.75
  应交税费 红字 1,074,030.85
   → 本年找不到等额母体；摘要也没有指向往年凭证
```

这是把上年末的未开票收入整批红冲，母体在 2024 年——本年的账里当然找不到。

**金额口径要注意**：证据里的"冲销金额"是全部红字行按（科目, 方向）合计，一笔完整
冲销的借贷两侧都会被计入，所以这个数约等于经济金额的两倍（上例 1,867 万 vs 实际
影响 934 万）。它用于排序与优先级，不要当作影响金额读。

两个已知边界写在证据里：母体可能在**上一年**或别的系统（存货核算、固定资产），
"本年未找到"不等于"不存在"；部分冲销（只冲一半）金额对不上，会落进孤儿。
另外还有 **925 张有红字但没有冲销关键词**的凭证，这一层看不见它们——数字在统计里，
不在线索里。
